# 自适应自转功率与缓冲控制

更新：2026-10-24。对应 [设计方案](superpowers/specs/2026-10-24-chassis-follow-power-priority-design.md)。控制策略已实施，实车指标尚未验收。

## 生效范围

`CHASSIS_FOLLOW_MODE` 默认恢复为 `0`，车身按原公式跟转对齐云台。显式设为 `1` 仍可使用云台朝向平移、车身不主动跟转。

以下分阶段功率策略在 `CHASSIS_SPIN_MODE=1`、直供、缓冲控制开启时生效。显式 `CHASSIS_SPIN_MODE` 优先于旧 `CHASSIS_SPIN_ADAPTIVE_ENABLE`。固定/正弦模式和超级电容保持原有预算入口，低能量保护仍有效。

## 自转功率阶段

| CSV `spin_power_phase` | 含义 | 行为 |
| --- | --- | --- |
| 0 | 不使用分阶段策略 | 普通模式或固定/正弦/电容路径 |
| 1 | 基础功率跟踪 | 目标为有效限功率的 98%，缓冲正增补为零 |
| 2 | 缓冲增补 | 发布可用额外功率，自转按斜率建立真实需求 |
| 3 | 低能量恢复 | 撤销增补，按缺口减让基础功率 |
| 4 | 数据降级 | 撤销增补与新升速；恢复后重新确认基础功率 |

基础阶段要求有效新功率样本连续 100 ms 落在基础目标的 `±max(2 W, 3%)` 范围，瞬时功率不超过基础上限，电机和保护状态健康，保守能量下限至少 30 J，才开放增补。重复读取同一功率帧不增加确认时间。限功率改变、制动、反馈失效和周期异常都会撤销资格。

正常增补为 `min((E-20)/0.25, (E-5)/0.3-5, 最大增补)` 的非负部分，E 是保守估算下限。首轮最大增补为 60 W，上升率 1200 W/s；下调预算立即生效。模型预算只转换一次安全系数，功率反馈目标和自转目标使用同一物理功率口径；慢环修正不能扩张批准的物理上限。

下限不超过 10 J 时回充；达到 20 J 并持续 100 ms 后退出回充，重新进入基础确认。预测触及 5 J 硬底座时立即恢复。增补阶段低于 15 J 或持续 100 ms 达到执行能力边界时撤销增补。普通模型限流不会直接反复切换阶段。

入场从零按限斜率建立目标。跟踪误差在 500 rpm 内可正常增长；超过时，仅新反馈证明四轮同向加速且误差未持续扩大，才允许 25% 上升率。连续 100 ms 误差未改善则停止趋势放行。模型限流、硬电流上限、快保护和制动分别报告。

## 当前默认值与旧参数

| 参数 | 自适应默认值 | 位置 |
| --- | --- | --- |
| 功率误差增益 | 80 Wz/(W·s) | `chassis_spin_config.h` |
| 目标上升/下降斜率 | 1200 / 2400 Wz/s | 同上 |
| 功率低通 / 升速确认 | 50 / 50 ms | 同上 |
| 能量目标 / 增补进入 / 增补退出 | 20 / 30 / 15 J | `chassis_energy_config.h` |
| 回充进入/退出 / 硬底座 | 10 / 20 / 5 J | 同上 |
| 释放时间 / 上升率 | 0.25 s / 1200 W/s | 同上 |

结算延迟 0.1 s、能量余量 3 J、功率余量 5 W、预测窗口 0.3 s 继续保留。上述能量值都针对保守下限，不能直接按裁判原始能量判断阶段。

原 Flash 分组、字段数量和控制模式编号保持兼容。有效旧 Flash 参数仍会覆盖源码默认，未自动擦除。通过在线调参 GET 查询实际值；需要新响应参数时应用上表增益、斜率和时间值并等待保存完成。新增能量阶段门槛为编译配置，不占用旧参数组字段。

CSV 的 `power_tuning_source`、`spin_tuning_source`：0 编译默认，1 参数文件，2 启动时从 Flash 恢复，3 运行时成功调参。这里报告值的应用来源，保存状态仍由 GET 回复的 saved/pending 等字段表示。用户已有的电机 Kp 和自转边界设置在实施中保留。

## USB 观测

功控字段自 CSV v3 引入（101 列，前 85 列与 v2 相同）。当前固件输出 v4（111 列），追加目标/实际整车速度，网页接受 v1/v2/v3/v4，详见 [底盘速度说明](chassis-velocity.md)。功率图可勾选“自转基础目标、缓冲增补请求、获准缓冲增补、自转物理上限”；缓冲状态显示当前阶段，悬停显示受限原因及参数来源。CSV 导出保留新增字段。

新增功率字段 `_cw` 为 0.01 W，增益/斜率 `_milli` 为千分之一，确认时间和低通时间为 ms。`spin_slow_correction_cw` 可为负。

| `spin_block_reasons` 位 | 含义 |
| --- | --- |
| 0 | 控制停用 |
| 1 | 电机/快照反馈失效 |
| 2 | 模型基础限流 |
| 3 | 电流硬上限 |
| 4 | 快保护或瞬态增长未获准 |
| 5 | 制动 |
| 6 | 轮速未跟上，趋势不足 |
| 7 | 转速上限 |
| 8 | 低能量恢复 |
| 9 | 功率计过期 |

阶段 1 配合能量值能区分“尚未达到基础功率”和“能量不足以开放增补”。预算上升并不证明实际功率已跟上，应同时观察实测功率、目标/实际轮速、模型修正及保护状态。

## 构建与实车验收

```powershell
make -j8 PROFILE=atype-vehicle BUILD_DIR=build/power-priority-vehicle CHASSIS_SPIN_MODE=1
```

不同宏配置使用独立目录。未执行烧录或实物操控。先验证随动方向，再记录同电压、同地面下的原地与平移自转波形；确认“基础到达 → 缓冲增补”顺序、低能量恢复、限功率突降和失联撤销。有限缓冲只能支持短时超限；硬件可达性及真实功率的响应时间需要实车确认。
