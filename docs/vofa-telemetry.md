# 用 VOFA+ 查看 A 板无线遥测

## 编译固件

版本库中的 A 板配置默认 `VOFA_TELEMETRY_MODE=0`，在速度控制模式且 UART7 空闲时输出 JustFloat。本地若已把 [Inc/board_config.h](../Inc/board_config.h) 改为 `1`，正常构建会使用 FireWater；下方命令显式指定采集配置，避免依赖本地默认值。`VOFA_TELEMETRY_ENABLE=0` 可关闭输出。

| `VOFA_TELEMETRY_MODE` | 用途 | VOFA+ 协议 |
| --- | --- | --- |
| `0`（默认） | 原有 19 路遥测，默认 50 Hz | JustFloat |
| `1`，主板开启 CAN IMU 接收 | schema 3，72 路观测数据，每组一行，发送间隔至少 80 ms | FireWater |
| `1`，未开启 CAN IMU 接收 | schema 2，64 路本板观测数据，发送间隔至少 80 ms | FireWater |

在 [Inc/board_config.h](../Inc/board_config.h) 中修改 `VOFA_TELEMETRY_MODE` 后，正常编译烧录即可切换协议。构建命令也可显式覆盖该宏。力控模式、裁判使用 UART7 或 UART7 接有辅助设备时，默认关闭 VOFA+ 输出。USB 遥测可同时开启，也可用 `USB_TELEMETRY_ENABLE=0` 单独运行无线遥测。[A 板串口接线](atype-integration.md#接线)

当前推荐两块 A 板通过 **CAN1** 传送底盘 IMU，主板将四轮、命令、功率和远端 IMU 汇总到 **一个 VOFA+ 窗口、一份 CSV**。第二块板刚性固定在底盘、尽量靠近几何中心。同一工程分别构建两份固件，主底盘/云台板使用：

```powershell
make -j8 PROFILE=atype-vehicle BUILD_DIR=build/kalman-can1-main CHASSIS_IMU_CAN_RX_ENABLE=1 CHASSIS_VELOCITY_FUSION_ENABLE=1 CHASSIS_VELOCITY_FUSION_CALIBRATED=0 VOFA_TELEMETRY_ENABLE=1 VOFA_TELEMETRY_MODE=1
```

主板输出 schema 3 的 72 列，`I0=3`、`I63=0`、`I64=2`，`I5` bit 15 表示已选择远端 CAN IMU。`I33`–`I45` 只取第二块板的 IMU；缺片组不更新样本，最后一份完整样本超龄或源无效时标无效，不退回本地云台 IMU。四轮有效时状态为 `UNCALIBRATED`，速度估计仍来自轮速。

第二块底盘 IMU 板只采样、控温并经 CAN1 发送，关闭本板 VOFA 和 USB 遥测：

```powershell
make -j8 PROFILE=atype-vehicle BUILD_DIR=build/imu-can1-sender IMU_CAPTURE_ONLY=1 IMU_CAPTURE_CAN_TX_ENABLE=1 VOFA_TELEMETRY_ENABLE=0 USB_TELEMETRY_ENABLE=0 CHASSIS_VELOCITY_FUSION_ENABLE=0
```

该模式不初始化电机、底盘、云台或遥控，不运行整车速度融合。将两份固件分别烧入对应板，第二块板无需连接 VOFA+。远端 IMU 当前用于统一记录，**尚未输入主板的速度融合器或控制回路**；不能把底盘 IMU 数据套入原有云台杆臂补偿算法。

本路线不要求云台杆臂实测，也不提供两板硬件同步。若另行验证主板原有的云台 IMU 融合路径，应关闭远端接收，提供目标车实测的 `chassis_velocity_fusion_calibration.h`，再设置 `CHASSIS_VELOCITY_FUSION_CALIBRATED=1`；不能使用 `tests/.../stubs` 的合成参数进行实车标定。[现有观测器的标定字段与读取方式](chassis-velocity-fusion.md)

FireWater schema 2/3 均替换原有 38 列功率测量格式，不能沿用旧列名；JustFloat 的 19 路格式保持兼容。不接 CAN 时仍可使用文末的[可选：独立双 CSV 采集](#可选独立双-csv-采集)。

当前整车默认直供。已接入匹配的 F334 超电且整车使用超电供电时，构建时设置 `CHASSIS_POWER_SOURCE_MODE=1`。JustFloat 的第 11–13 路是超电数据，其中第 12 路需要 F334 的 CAN `0x052` 输入功率反馈；FireWater 的 `I5` bit 13 标明供电配置。[超电协议](supercap-can-protocol.md)

## 两板 CAN1 接线与传输

将第二块板接入主板现有 **CAN1 总线**：`CAN_H` 对 `CAN_H`、`CAN_L` 对 `CAN_L`，并连接参考地。按板卡丝印和实际接线图确认接插件引脚，本页不指定物理针序。终端电阻按总线两端配置；已有两端终端时，不因新增节点再加第三只。

当前 CAN1 为 **1 Mbps**。IMU 使用标准 ID **`0x520`**，与当前工程已有 ID 无冲突。每个样本分为 9 个 8 字节帧，每 20 ms 尝试发送一组（50 Hz），包含四元数 4 轴、导航系去重力加速度 3 轴、传感器系角速度 3 轴，以及源样本序号、源板毫秒时间、发送时样本年龄和有效标志。

接收端检查严格分片顺序、同组 tag、CRC16/CCITT-FALSE，以及从首片开始的 10 ms 组装期限。发送任一分片失败即中止本组；缺片、错序、校验失败或过期组不更新已发布样本。拒绝组累计值随主板 CSV 输出，最后一份完整样本仍须通过年龄和有效标志检查才能使用。

## 连接调试器

1. 将塔克调试器的无线主机插到电脑 USB 口，接收端设为无线从机。普通款主机的 STA 灯为蓝色，从机为绿色。若尚未配对，按手册第 2.2 节完成配对并给两端重新上电。
2. 只连接**主板 UART7**：在 A 板位号 `16` 的串口组找到最右侧、丝印 `7` 的接口。接线前按 A 板和调试器的丝印核对引脚。[UART7 接口位置](referee-uart7-fix.md)

   | A 板 UART7 | 无线从机 |
   | --- | --- |
   | `TX`（PE8） | `RX` |
   | `GND` | `GND` |
   | `5V`（从 A 板取电时） | `5V` |

   单向遥测只需要上表中的连线。调试器引脚和供电方式见《塔克无线高速 DAP 调试下载器手册 V3.0.1》第 1.4、2.4.1 节，手册推荐从机使用 5 V 供电。

3. 上电后在 Windows 设备管理器的「端口（COM 和 LPT）」里确认主机新增的虚拟 COM 号。对应示意见手册第 2.5 节。

## 在 VOFA+ 中连接

1. 连接方式选 **SerialPort**，选择主板调试器的虚拟 COM 号，设为 **115200、8 数据位、无校验、1 停止位、无流控**。CAN1 路线只使用这一个接收通道。
2. 按固件档位选择 **JustFloat** 或 **FireWater**，再打开串口。右侧数据栏以 `I0`、`I1` 等显示通道，点击通道名可重命名。FireWater 模式下，在字节接收区用字符串显示（关闭 `Hex`），并在 `Rx` 设置里显示采样数据包，即可看到每组完整的逗号分隔数据。 [VOFA+ FireWater 协议](https://www.vofa.plus/docs/learning/dataengines/firewater/)
3. 两板上电后先保持静止，等待 INS 完成启动标定。在 CAN1 路线确认 **`I0=3`、`I63=0`、`I64=2`、`I5` bit 15 为 1**，随后确认 bit 4 持续有效、`I65` 接近一组 CAN 发送周期且没有持续增长。`I65=-1` 表示尚无可报告的接收年龄。仅有 schema 和来源标记不能证明已收到有效 IMU。
4. 从控件栏拖入「波形图」，右键在 Y 轴菜单勾选要看的通道。JustFloat 可对照 `I0` 和 `I4` 的左前轮实测/目标转速；FireWater 可先对照 `I21` 和 `I24` 的轮速反算/目标前向速度，并查看 `I40`–`I45` 的底盘 IMU 响应。CAN1 推荐构建尚无融合结果。标称 Δt 为 JustFloat `20 ms`、FireWater `80 ms`；实际间隔和缺帧由板端时间与发送序号判断。[VOFA+ 波形图操作](https://www.vofa.plus/docs/learning/widgets/wave/)
5. 采完后用左上角 **文件 → 保存数据** 将完整 **`I0`–`I71`** 另存为一份 `.csv`。切换固件档位或开启下一次测量前，先保存上一批，再清空采样缓冲区，分别命名文件。

接收区可能按窗口宽度折行。即使 72 列在窗口里折行，每组在串口上仍只有一个行末换行，保存的 CSV 按组分行。

## JustFloat 通道表

| 通道 | 数据 | 单位 |
| --- | --- | --- |
| `ch0`–`ch3` | LF、RF、LB、RB 电机转子实测转速 | rpm |
| `ch4`–`ch7` | LF、RF、LB、RB 电机转子目标转速 | rpm |
| `ch8` | 功率计实测功率 | W |
| `ch9` | 限制后模型估算功率 | W |
| `ch10` | 有效功率上限 | W |
| `ch11` | 超级电容输出侧底盘功率 | W |
| `ch12` | 超级电容输入功率 | W |
| `ch13` | 超级电容剩余百分比 | % |
| `ch14`–`ch16` | IMU 的 yaw、pitch、roll | ° |
| `ch17` | 电机在线位掩码，bit 0–3 对应 LF、RF、LB、RB | — |
| `ch18` | 数据有效位掩码，见下文 | — |

LF、RF、LB、RB 依次为左前、右前、左后、右后。将转子 rpm 除以 `REDUCTION_RATIO_WHEEL`（默认 19.0）即可换算为轮端 rpm。电机在线位清零时，该电机的实测和目标转速均发送 0。

`ch18` 的 bit 0 对应功控模型（`ch9`、`ch10`），bit 1 对应功率计（`ch8`），bit 2 对应电容输出与剩余百分比（`ch11`、`ch13`），bit 3 对应电容输入（`ch12`），bit 4 对应 IMU（`ch14`–`ch16`）。数据不可用时发送 0，可结合有效位区分真实零值。

每帧由 19 个小端 32 位浮点数和 `00 00 80 7F` 帧尾组成，共 80 字节。数据字节若恰好拼成帧尾，固件会调整冲突浮点数的最低尾数位，避免接收端提前切帧。发送周期跟随 `USB_TELEMETRY_PERIOD_MS`，默认 20 ms（50 Hz）。UART7 忙时跳过当期整帧。[JustFloat 解码器](https://github.com/je00/Vodka/blob/master/dataengines/justfloat/justfloat.cpp#L39-L50)

## FireWater 卡尔曼观测通道表

CAN1 主板使用 **schema 3，每行固定 72 个十进制整数**；未开启远端接收时为 schema 2，每行固定 64 列。均以逗号分隔，仅在最后一列后加一个换行（LF）。整行组好后一次提交给 UART7，串口为 **115200、8N1**。发送间隔至少 80 ms，标称 12.5 Hz；UART7 忙时跳过整行，后续发送序号会出现间隔。CAN1 的 50 Hz 传输在这里降采样为标称 12.5 Hz CSV。

schema 3 保留前 64 列的布局：`I0` 改为 `3`，`I33`–`I45` 改取远端底盘 IMU，并追加 `I64`–`I71` 的来源与接收诊断。`I63` 仍表示输出 CSV 的主板角色，不能据此把 schema 3 的 IMU 判断成本地云台 IMU。

| VOFA+ 列 | 数据 | 单位或编码 |
| --- | --- | --- |
| `I0` | 格式版本 | CAN1 主板为 `3`；本板采集为 `2` |
| `I1`、`I2` | 输出本行的板端时间高、低 16 位 | ms；schema 3 为主板时间 |
| `I3`、`I4` | 发送尝试序号的高、低 16 位 | 从 0 开始，包含未发出的尝试 |
| `I5` | 数据有效位与配置位掩码 | 见下表 |
| `I6` | 速度观测状态 | 见状态表，关闭观测 `-1`，独立 IMU 采集 `-2` |
| `I7` | 底盘模式 | `0` 零力、`1` 自旋、`2` 不跟随、`3` 跟随档；无效 `-1` |
| `I8`、`I9` | 四轮在线位、最终使能位 | bit 0–3 对应 LF、RF、LB、RB |
| `I10`–`I12` | 原始诊断快照、速度估计、最新轮速反算的年龄 | ms；未知或不可用 `-1` |
| `I13`–`I16` | 四轮原始转子转速 | rpm，LF、RF、LB、RB |
| `I17`–`I20` | 四轮接收反馈的年龄 | ms，LF、RF、LB、RB |
| `I21`、`I22` | 最新轮速反算 vx、vy | mm/s，底盘前、右为正 |
| `I23` | 最新轮速反算的车体旋转速度 wz | mrev/s，即 `1000 × 转/秒`；除以 1000 得转/秒 |
| `I24`、`I25` | 四轮目标反算的 vx、vy | mm/s，底盘前、右为正 |
| `I26` | 四轮目标反算的车体旋转速度 wz | mrev/s，同 `I23` |
| `I27`、`I28` | 速度估计 vx、vy | mm/s；只有有效位 bit 3 为 1 才表示融合 |
| `I29`、`I30` | 与融合对应的配对轮速 vx、vy | mm/s，底盘前、右为正 |
| `I31`、`I32` | 融合所用的中心平移加速度 X、Y | mm/s²，固定导航系 |
| `I33` | IMU 样本年龄 | ms；schema 3 为已知年龄下界，计算与限制见下文 |
| `I34`、`I35` | 源 INS 样本序号的高、低 16 位 | 同序号表示同一 INS 观测 |
| `I36`–`I39` | 源 INS 四元数 w、x、y、z | 数值除以 1000000；原生传感器系到源板导航系 |
| `I40`–`I42` | 源 IMU 去重力加速度 X、Y、Z | mm/s²，源板导航系，尚未进行杆臂校正 |
| `I43`–`I45` | 源 IMU 角速度 X、Y、Z | mrad/s，原生传感器系 |
| `I46`、`I47` | yaw、pitch 原始编码器 | `0…8191`，保留零位前的原值 |
| `I48`、`I49` | yaw、pitch 转子转速 | rpm |
| `I50`、`I51` | yaw、pitch 编码器反馈年龄 | ms |
| `I52`–`I55` | 四轮最终尝试提交的 CAN 电流命令 | DJI 原始单位，LF、RF、LB、RB |
| `I56`–`I58` | 限制前模型功率、限制后模型功率、有效功率上限 | cW，除以 100 得 W |
| `I59` | 控制周期引用的功率计实测值 | cW |
| `I60` | 最终控制快照年龄 | ms |
| `I61` | 四轮目标反算快照年龄 | ms |
| `I62` | 控制周期引用的功率计样本年龄 | ms |
| `I63` | 记录板角色 `record_role` | `0` 主底盘/云台板，`1` 独立底盘 IMU 采集板 |
| `I64` | IMU 来源，仅 schema 3 | 固定 `2`：CAN1 远端底盘 IMU |
| `I65` | 主板收到完整一组 IMU 后经过的时间 | ms；主板本地时钟 |
| `I66` | 第二板发送时的源样本年龄 | ms；由第二板自身时钟计算 |
| `I67`、`I68` | 源板样本时间高、低 16 位 | ms；源板时钟，仅诊断，不能直接减主板时间 |
| `I69` | 本组首片至末片的主板接收间隔 | ms |
| `I70`、`I71` | 接收端累计拒绝组数高、低 16 位 | uint32 计数，达到 `UINT32_MAX` 后饱和 |

schema 3 的 `I33`–`I45` 始终来自远端第二板；远端失效时对应测量填 0 并清除有效位，不切换成本地 IMU。schema 2 的这些列来自输出 CSV 的本板。

`I23` 和 `I26` 是**车体转速**，不是电机 rpm，也不是 rad/s：轮速反算中的 `wz_rpm` 乘 `1000/60` 后发送。换成 rpm 时将记录值乘 `60/1000`；换成 rad/s 时乘 `2π/1000`。

`I5` 有效位与配置位定义：

| bit | 含义 | 对应数据 |
| --- | --- | --- |
| 0 | 原始诊断快照新鲜 | 采集入口已发布，年龄不超过 20 ms |
| 1 | 最新四轮反算有效 | `I21`–`I23`，同时要求四轮在线且新鲜 |
| 2 | 速度估计有效 | `I27`、`I28`；可能为轮速降级值 |
| 3 | 本行融合有效 | `I27`–`I32`，要求状态为 FUSED |
| 4 | INS 运动输入有效 | `I36`–`I45`；schema 3 检查远端组有效性及下述年龄条件 |
| 5 | yaw、pitch 两轴输入均有效 | `I46`–`I49` |
| 6 | 底盘控制快照有效 | `I7` |
| 7 | 功控模型有效 | `I56`–`I58` |
| 8 | 最终控制快照有效 | `I9`、`I52`–`I55` |
| 9 | 最终快照对应的控制周期计算有效 | 结合 bit 8 使用 |
| 10 | 对应 CAN 组提交成功 | 仅表示提交，需由反馈判断实际执行 |
| 11 | 四轮目标反算有效 | `I24`–`I26` |
| 12 | 功率计样本有效 | `I59` |
| 13 | 供电配置为超电 | `1` 超电、`0` 直供；是构建配置，不代表电源在线 |
| 14 | 独立 IMU 采集模式 | 与 `I63=1` 对应 |
| 15 | 远端 CAN IMU 模式 | schema 3、`I64=2`；模式位本身不代表已接收有效数据 |

主板本地观测的新鲜度上限为 20 ms，融合估计允许最多 60 ms。schema 3 的远端 IMU 单独要求源有效、完整组通过校验、发送时源年龄 `I66≤20 ms`，且已知年龄下界 `I33≤60 ms`；字段存在或模式位为 1 均不能代替 bit 4。保留的原始年龄可超过上限。无效测量填 0，年龄未知或不能表示时填 `-1`，应结合有效位区分真实零值。`I8` 逐轮检查在线、时间和数值，bit 0–3 与所有四轮数组使用同一轮序。

`I6` 状态定义：

| 值 | 状态 | 含义 |
| --- | --- | --- |
| `-2` | IMU_CAPTURE_ONLY | 独立底盘 IMU 采集，无底盘速度估计 |
| `-1` | 未开启 | 未编入整车速度观测 |
| `0` | NO_SAMPLE | 尚无发布样本 |
| `1` | WHEEL_UNAVAILABLE | 四轮数据不可用 |
| `2` | UNCALIBRATED | 未标定，仍输出轮速反算 |
| `3` | CLOCK_INVALID | 时钟不可用 |
| `4` | IMU_UNAVAILABLE | IMU 不可用 |
| `5` | GIMBAL_UNAVAILABLE | 云台反馈不可用 |
| `6` | NOT_ALIGNED | 输入时间不满足对齐要求 |
| `7` | WARMUP | 等待中心补偿/融合历史 |
| `8` | REJECTED | 姿态、中心补偿或滤波拒绝 |
| `9` | FUSED | 观测已使用 IMU 融合 |

状态描述最后一次观测，是否仍新鲜必须看 `I5`。没有标定时，bit 3 不会置位，`I29`–`I32` 为 0；这不妨碍采集 `I13`–`I20` 和 `I33`–`I51` 的真实输入。

CAN1 推荐构建中，`I6=2` 表示未标定的轮速估计，bit 3 为 0，`I29`–`I32` 为 0；收到有效远端 IMU 不会改变这一点。旧的独立 UART 采集模式仍输出 schema 2，其 `I6=-2`、`I63=1`，仅有 IMU 相关测量；详见文末可选路线。

### 时间、年龄与来源

时间和计数用 `高位 × 65536 + 低位` 还原：本行板端时间为 `I1×65536+I2`，发送序号为 `I3×65536+I4`，INS 序号为 `I34×65536+I35`；schema 3 的源板样本时间为 `I67×65536+I68`，累计拒绝组数为 `I70×65536+I71`。拆分可避免 VOFA+ 将整个 32 位整数转成单精度时丢低位。时钟、发送序号和源 INS 序号按 uint32 回绕处理；累计拒绝组数达到 `UINT32_MAX` 后饱和，不回绕。

schema 3 的 `I33 = 发送时源年龄 + (主板当前时间 − 本组首片接收时间)`，括号内按主板 uint32 时间计算。它是**已知年龄下界**：没有包含首片发送排队、总线仲裁前的等待或传感器内部延迟，不能视为准确的跨板采样时间。`I65` 从完整组接收时刻算起，`I69` 记录组内首末片接收间隔，二者可帮助检查传输延迟。即使有效位为 1，也不表示已知真实端到端延迟小于 60 ms。

两板时钟没有同步。不要用主板 `I1/I2` 减源板 `I67/I68`，也不要把主板时间减 `I33` 当成同步后的精确样本时刻。主板本地样本及 schema 2 的本板样本才可按同一时钟，以本行时间减相应年龄还原 MCU 接收或读取完成时刻；这些时刻仍不同于设备内部采样时刻。各 INS 具有自己的导航参考系，源板导航系加速度也不能直接当作底盘前、右方向加速度。

`I27`/`I28` 与 `I29`/`I30` 用于融合对应时刻的速度对照，估计时刻由 `I11` 还原；`I21`/`I22` 和原始 IMU 属于更新后的输入，各有自己的年龄。不能把整行所有量当成同时采样。估计减去配对轮速得到的是**后验差**，不是滤波器校正前的 innovation。

## CSV 采集与交付

两块板上电后先保持静止，等待主板 schema 3 的 `I5` bit 4 持续有效、`I65` 保持较小，再开始动作；现有 INS 会在启动时进行陀螺零偏与重力标定。记录第二块板的实际安装轴向及 MPU6500 芯片相对底盘中心的偏移，靠近中心也不等于偏移严格为零。

每个工况只保存**主板的一份完整 CSV**，同时包含四轮/命令/功率与 CAN1 远端底盘 IMU。开始下一工况前保存上一份并清空采样缓冲区。每段动作前后各保留约 5 s 静止数据，低速动作重复 3–5 次，保留起停和换向过程。不要求先完成云台杆臂标定再开始底盘采集。

| 工况 | 建议记录时长 | 主要用途 |
| --- | --- | --- |
| 底盘、云台均静止 | 30–60 s | 零点、噪声与稳定性基线 |
| 云台尽量保持固定，低速前进/后退及起停换向 | 30–60 s | 前向轮速符号、加速度响应与滞后 |
| 云台尽量保持固定，低速左移/右移及起停换向 | 30–60 s | 横向轮速符号与响应 |
| 低速自旋，分别记录两个方向 | 每个方向 20–30 s | 轮速与底盘 IMU 旋转响应、安装偏移影响 |

导出时保留完整 **`I0`–`I71`**、原有表头和 VOFA+ 时间列，不删除有效位、发送序号、来源、各年龄或拒绝组数，不用波形截图替代 CSV。可命名为 `CAN1_静止.csv`、`CAN1_前后起停.csv`、`CAN1_左右起停.csv`、`CAN1_正反自旋.csv`。提交 CSV 时一并说明两块板烧录的固件/提交号、完整构建命令、第二板安装轴向和芯片偏移、实际动作方向、地面与载荷，以及该段出现的抖动、延迟或拒绝计数增长。

统一 CSV 表示主板在同一发送时刻汇总最新数据，不表示四轮与远端 IMU 同时采样。比较轮速与加速度时仍须保留各来源年龄、源样本序号和接收诊断，并考虑首片排队、传感器内部延迟与源板导航系方向。源序号可帮助识别同一样本被重复记录；拒绝组计数可帮助定位接收异常。

这些数据用于初始噪声、符号、偏置、低频响应和融合参数分析。80 ms 输出是降采样，即使 CAN1 以 50 Hz 传输，也无法从该 CSV 逐次重放高频滤波更新或完整辨识 Q/R；需要精确重放时，须另外保留每个融合输入及其原始时间。当前远端数据尚未参与融合，实际车速误差和防滑效果还需要独立速度参考。

## 可选：独立双 CSV 采集

不接两板 CAN1 时，可保留原有的两板独立 UART7 记录方式。这是可选路线，输出 **schema 2、64 列**，需要两个独立接收通道与两份 CSV。主板构建：

```powershell
make -j8 PROFILE=atype-vehicle BUILD_DIR=build/kalman-firewater CHASSIS_IMU_CAN_RX_ENABLE=0 VOFA_TELEMETRY_ENABLE=1 VOFA_TELEMETRY_MODE=1 CHASSIS_VELOCITY_FUSION_ENABLE=1 CHASSIS_VELOCITY_FUSION_CALIBRATED=0
```

第二块独立 IMU 板构建：

```powershell
make -j8 PROFILE=atype-vehicle BUILD_DIR=build/imu-firewater IMU_CAPTURE_ONLY=1 IMU_CAPTURE_CAN_TX_ENABLE=0 VOFA_TELEMETRY_ENABLE=1 VOFA_TELEMETRY_MODE=1 USB_TELEMETRY_ENABLE=0 CHASSIS_VELOCITY_FUSION_ENABLE=0
```

各自 UART7 接独立接收端，不把两个 TX 并接。主板 `I63=0`，`I33`–`I45` 来自本地云台 IMU；第二板 `I63=1`、`I6=-2`、`I5` bit 14 为 1，`I33`–`I45` 才是底盘 IMU。第二板的测量有效位仅使用 bit 0（采集快照）与 bit 4（IMU），底盘、轮速、云台和功率测量为 0、年龄为 `-1`、底盘模式为 `-1`。schema 2 没有 `I64`–`I71`。

两端均开始记录、各自 bit 4 持续有效后，再做上述工况。每段分别保存完整 `I0`–`I63`，可配对命名为 `主板_静止.csv` / `中心IMU_静止.csv`。可选记录底盘静止而云台 yaw 或 pitch 往复的工况，核对本地云台 IMU 与底盘 IMU 的来源。

这条路线需要离线配对：同场记录明显的“静止—低速起步—停车—静止”重复序列，按轮速变化与中心加速度粗配准。不能仅按行号、各自开机毫秒或电脑接收时间配对，该序列也不能提供毫秒级准确同步。分析须考虑时间偏移、时钟漂移、传感器内部延迟和两板导航系方向。
