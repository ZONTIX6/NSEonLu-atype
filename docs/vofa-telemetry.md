# 用 VOFA+ 查看 A 板无线遥测

## 编译固件

版本库中的 A 板配置和第一块主板预设默认 `VOFA_TELEMETRY_MODE=2`，在速度控制模式且 UART7 空闲时输出完整观测数据的 JustFloat 二进制帧，CSV 文件由 VOFA+ 在采集后导出。`VOFA_TELEMETRY_ENABLE=0` 可关闭输出。

| `VOFA_TELEMETRY_MODE` | 用途 | VOFA+ 协议 |
| --- | --- | --- |
| `0` | 原有 19 路遥测，默认 20 ms / 50 Hz，通道与单位保持不变 | JustFloat |
| `1`，主板开启 CAN IMU 接收 | schema 3，72 路观测数据，每组一行，发送间隔至少 80 ms | FireWater |
| `1`，未开启 CAN IMU 接收 | schema 2，64 路本板观测数据，发送间隔至少 80 ms | FireWater |
| `2`（默认），主板开启 CAN IMU 接收 | schema 3，72 路观测数据，目标发送周期 20 ms / 标称 50 Hz | JustFloat |
| `2`（默认），未开启 CAN IMU 接收 | schema 2，64 路本板观测数据，目标发送周期 20 ms / 标称 50 Hz | JustFloat |

在 [config/90_board/board_config.h](../config/90_board/board_config.h) 中修改 `VOFA_TELEMETRY_MODE` 后，正常编译烧录即可切换协议。构建命令也可显式覆盖该宏。力控模式、裁判使用 UART7 或 UART7 接有辅助设备时，默认关闭 VOFA+ 输出。USB 遥测可同时开启，也可用 `USB_TELEMETRY_ENABLE=0` 单独运行无线遥测。[A 板串口接线](atype-integration.md#接线)

当前推荐 **DM-IMU-L1 接主板 CAN2**，替代第二块 A 板采集 IMU。主板保留远端 IMU 与轮速的卡尔曼速度观测，将四轮、命令、功率、底盘 IMU 和融合结果汇总到一个 VOFA+ 窗口；融合仅观测，不参与底盘控制。模块须刚性固定，CAN 1 Mbps、主动上报 100 Hz，启用加速度、角速度和四元数；接线及 `MST_ID` 配置见 [DM 集成说明](dm-imu-integration.md)。

日常构建使用 [`config/00_flash/board_flash_config.h`](../config/00_flash/board_flash_config.h)，配置沿用 `BOARD_FLASH_1_` 前缀。只支持主板 `1`；DM 模块用厂商上位机设置，不刷第二块 A 板。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-board.ps1 -Action Show
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-board.ps1 -Action Build
# 连接所选物理板；构建成功后再烧录同一输出目录的固件
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-board.ps1 -Action Flash
```

可显式传 `-Board 1`；`-Board 2` 已不受支持。下载器用法见 [配置目录说明](../config/README.md#主板怎样构建与烧录)。Make/CMake 和 F5 不读取该预设，手动构建示例：

```powershell
make -j8 PROFILE=atype-vehicle BUILD_DIR=build/kalman-dm-main ONE_BOARD=1 CHASSIS_CONTROL_MODE=0 CHASSIS_IMU_CAN_RX_ENABLE=1 CHASSIS_VELOCITY_FUSION_ENABLE=1 CHASSIS_REMOTE_IMU_FUSION_ENABLE=1 CHASSIS_VELOCITY_FUSION_CALIBRATED=0 VOFA_TELEMETRY_ENABLE=1 VOFA_TELEMETRY_MODE=2
```

主板输出 schema 3 的 72 列，`I0=3`、`I63=0`、`I64=2`；`I5` bit 15/19 标识外部 CAN DM 输入，bit 16/17 表示开启远端融合并采用接收端估计时间。`I33`～`I45` 只取 DM 快照，超龄或无效时不换成本地云台 IMU。只有 `I6=9` 且 bit 3 有效才是真正融合，四轮有效而 DM 不可用时回退轮速。

固定安装旋转、芯片偏移和滤波噪声见 [远端 IMU 配置](../config/30_velocity_observation/chassis_remote_imu_config.h)。默认单位旋转、零偏移未实测，`CONFIG_VERIFIED=0`（bit 18=0）不会阻止算法运行，但不能用于证明精度。

需要纯采集对照时，只把 `BOARD_FLASH_1_CHASSIS_REMOTE_IMU_FUSION_ENABLE` 改为 `0`；手动命令同样仅将 `CHASSIS_REMOTE_IMU_FUSION_ENABLE=0` 并改用独立构建目录。DM 接收与遥测继续运行。

若另行验证主板原有的本地云台 IMU 融合路径，必须关闭远端接收及远端融合，提供目标车实测的 `chassis_velocity_fusion_calibration.h`，再设置 `CHASSIS_VELOCITY_FUSION_CALIBRATED=1`；不使用 `tests/.../stubs` 的合成参数代替实车标定。

模式 `1` 和 `2` 使用相同的 schema 2/3 通道顺序、缩放单位和有效位，均已替换原有 38 列功率测量格式，不能沿用旧列名。模式 `0` 的 19 路 JustFloat 格式与发送周期保持兼容；USB 遥测和日志串口不随此模式改变。仅检查本地 IMU 时可使用文末的[本地 UART 诊断](#本地-imu-uart-诊断)。

当前整车默认直供。已接入匹配的 F334 超电且整车使用超电供电时，构建时设置 `CHASSIS_POWER_SOURCE_MODE=1`。模式 `0` 的第 11–13 路是超电数据，其中第 12 路需要 F334 的 CAN `0x052` 输入功率反馈；模式 `1/2` 的 `I5` bit 13 标明供电配置。[超电协议](supercap-can-protocol.md)

## DM CAN2 接线与传输

DM 接主板 CAN2，CAN_H 对 CAN_H、CAN_L 对 CAN_L 并连接参考地，速率 1 Mbps。模块配置主动 100 Hz，`MST_ID` 与主板 `DM_IMU_CAN_RX_ID` 一致（项目示例 `0x11`，不是已确认出厂值）。上报加速度、角速度、四元数，Euler 可选；主板不自动写模块配置。

适配器按类型 `1→2→[3]→4` 在 10 ms 内组装，完整组按至少 18 ms 首片接收间隔（名义 100 Hz 输入约发布 50 Hz，为接收抖动留余量）发布；该组内顺序尚需实物抓包确认。错序、缺片、非法姿态和过期组不刷新样本。接线、供电、倾斜静止核对见 [DM 集成说明](dm-imu-integration.md)。旧第二板 CAN 协议已移除，历史资料见[旧验证记录](superpowers/verification/2026-11-12-remote-imu-fusion.md)。

## 连接调试器

1. 将塔克调试器的无线主机插到电脑 USB 口，接收端设为无线从机。普通款主机的 STA 灯为蓝色，从机为绿色。若尚未配对，按手册第 2.2 节完成配对并给两端重新上电。
2. 只连接**主板 UART7**：在 A 板位号 `16` 的串口组找到最右侧、丝印 `7` 的接口。接线前按 A 板和调试器的丝印核对引脚。[UART7 接口位置](referee-uart7-fix.md)

   | A 板 UART7 | 无线从机 |
   | --- | --- |
   | `TX`（PE8） | `RX` |
   | `GND` | `GND` |
   | `5V`（从 A 板取电时） | `5V` |

   单向遥测只需要上表中的连线。调试器引脚和供电方式见《塔克无线高速 DAP 调试下载器手册 V3.0.1》第 1.4、2.4.1 节，手册推荐从机使用 5 V 供电。

3. 上电后在 Windows 设备管理器的「端口（COM 和 LPT）」里确认主机新增的虚拟 COM 号。对应示意见手册第 2.5 节。

## 在 VOFA+ 中连接

1. 连接方式选 **SerialPort**，选择主板调试器的虚拟 COM 号，模式 `2` 设为 **230400、8 数据位、无校验、1 停止位、无流控**；模式 `0/1` 保持 **115200**。DM 只使用这一个接收通道。
2. 当前主板模式 `2` 选择 **JustFloat**，再打开串口。右侧数据栏以 `I0`、`I1` 等显示通道，点击通道名可重命名。字节接收区勾选 `Hex` 查看二进制数据；波形和通道值仍正常显示数字。模式 `0` 同样选 JustFloat；仅模式 `1` 选 **FireWater**，并关闭 `Hex` 查看逗号分隔文本。[JustFloat 协议](https://www.vofa.plus/docs/learning/dataengines/justfloat/)、[FireWater 协议](https://www.vofa.plus/docs/learning/dataengines/firewater/)
3. 主板与所选 IMU 上电后先保持静止，等待姿态稳定。在外部 CAN IMU 路线确认 **`I0=3`、`I63=0`、`I64=2`、`I5` bit 15 为 1**，DM 还须 bit 19 为 1；随后确认 bit 4 持续有效、`I65` 接近一组 CAN 发送周期且没有持续增长。`I65=-1` 表示尚无可报告的接收年龄。仅有 schema 和来源标记不能证明已收到有效 IMU。
4. 从控件栏拖入「波形图」，右键在 Y 轴菜单勾选要看的通道。模式 `1/2` 先看 `I21/I24` 的轮速反算/目标速度和 `I40`–`I45` 的底盘 IMU 响应；模式 `0` 可对照 `I0` 和 `I4` 的左前轮实测/目标转速。远端融合配置须另确认 bit 16/17；待 `I6=9` 且 bit 3 为 1 后，用 `I27/I29`、`I28/I30` 比较融合与配对轮速，保留 `I11` 年龄。标称 Δt 为模式 `0` 的 `20 ms`、模式 `1` 的 `80 ms`、模式 `2` 的 `20 ms`；观测数据的实际间隔和缺帧由板端时间与发送序号判断。[VOFA+ 波形图操作](https://www.vofa.plus/docs/learning/widgets/wave/)
5. 采完后用左上角 **文件 → 保存数据** 将完整 **`I0`–`I71`** 另存为一份 `.csv`。切换固件档位或开启下一次测量前，先保存上一批，再清空采样缓冲区，分别命名文件。

模式 `2` 的串口数据没有逗号或文本换行，VOFA+ 按二进制帧尾解析为完整的一组通道，再按组导出 CSV。模式 `1` 的文本接收区可能按窗口宽度折行，但每组在串口上仍只有一个行末换行。

### 230400 波特率的使用与影响

提高波特率只作用于启用模式 `2` 时的 UART7；模式 `0/1`、VOFA 关闭时的 UART7 初始化，以及其他串口保持原设置。切回旧模式时，VOFA 的波特率也要改回 115200。固件、VOFA 和无线从机的串口速率须匹配；只改电脑端不能证明整条链路已正确配置。

《塔克无线高速 DAP 调试下载器手册 V3.0.1》未明确给出串口支持波特率上限，也未保证电脑端设置自动同步到从机。`CONF.TXT` 的 `rate` 表示空中速率，不是 UART 波特率；手册的无线下载速度也不是串口透传吞吐保证。使用无线链路前确认设备支持并匹配 230400，以板端时间与发送序号验证持续接收；本次配置没有上板实测保证。

72 路数据流从约 7.3 kB/s 增至 14.6 kB/s，VOFA 的处理和保存数据量约翻倍。当前使用逐字节 `HAL_UART_Transmit_IT`，发送空中断平均约从 7300 次/秒增至 14600 次/秒，另有帧完成中断；实际 CPU 占用与控制任务延迟须实测。控制算法及其周期没有随此配置改变，不能据此断言运行时开销为零。更高串口速率也缩短了连线和时序容错余量，不会自动提高无线空中吞吐。

采集前核对模式 `2`、230400 / 8N1，再连续记录并检查相邻板端时间是否以约 20 ms 为主、发送序号有无缺口，以及控制任务是否新增超时。发生丢帧时先核对两端波特率、无线链路和接线，不跨缺口插值后当成真实连续采样。

## 原有 19 路 JustFloat 通道表（模式 0）

| 通道 | 数据 | 单位 |
| --- | --- | --- |
| `ch0`–`ch3` | LF、RF、LB、RB 电机转子实测转速 | rpm |
| `ch4`–`ch7` | LF、RF、LB、RB 电机转子目标转速 | rpm |
| `ch8` | 功率计实测功率 | W |
| `ch9` | 限制后模型估算功率 | W |
| `ch10` | 有效功率上限 | W |
| `ch11` | 超级电容输出侧底盘功率 | W |
| `ch12` | 超级电容输入功率 | W |
| `ch13` | 超级电容剩余百分比 | % |
| `ch14`–`ch16` | IMU 的 yaw、pitch、roll | ° |
| `ch17` | 电机在线位掩码，bit 0–3 对应 LF、RF、LB、RB | — |
| `ch18` | 数据有效位掩码，见下文 | — |

LF、RF、LB、RB 依次为左前、右前、左后、右后。将转子 rpm 除以 `REDUCTION_RATIO_WHEEL`（默认 19.0）即可换算为轮端 rpm。电机在线位清零时，该电机的实测和目标转速均发送 0。

`ch18` 的 bit 0 对应功控模型（`ch9`、`ch10`），bit 1 对应功率计（`ch8`），bit 2 对应电容输出与剩余百分比（`ch11`、`ch13`），bit 3 对应电容输入（`ch12`），bit 4 对应 IMU（`ch14`–`ch16`）。数据不可用时发送 0，可结合有效位区分真实零值。

每帧由 19 个小端 32 位浮点数和 `00 00 80 7F` 帧尾组成，共 80 字节。数据字节若恰好拼成帧尾，固件会调整冲突浮点数的最低尾数位，避免接收端提前切帧。发送周期跟随 `USB_TELEMETRY_PERIOD_MS`，默认 20 ms（50 Hz）。UART7 忙时跳过当期整帧。[JustFloat 解码器](https://github.com/je00/Vodka/blob/master/dataengines/justfloat/justfloat.cpp#L39-L50)

## 完整卡尔曼观测通道表（模式 1/2）

外部 CAN IMU 主板使用 **schema 3，每帧固定 72 路**；未开启远端接收时为 schema 2，每帧固定 64 路。模式 `1/2` 使用下表同一组通道、单位和有效位，整帧组好后一次提交给 UART7，串口为 **8N1**，模式 `2` 使用 **230400**，模式 `1` 保持 **115200**。

- 模式 `2`：64/72 个小端 float32 加 `00 00 80 7F` 帧尾，分别为 260/292 字节；目标发送周期 20 ms，标称 50 Hz。230400 / 8N1 下，72 路一帧线速传输约需 12.67 ms，20 ms 周期占用约 63.4% 串口带宽；64 路分别为 11.28 ms 和 56.4%。默认遥测任务周期仍为 20 ms。
- 模式 `1`：64/72 个十进制整数以逗号分隔，仅最后一列后加换行（LF）；发送间隔至少 80 ms，标称 12.5 Hz，保留原有 FireWater 行为。

UART7 忙时跳过整帧，后续发送尝试序号会出现缺口。CSV 由 VOFA+ 采集后导出；模式 `2` 按 20 ms 目标周期尝试发送最新快照，未改变 IMU、CAN 接收或融合器的内部更新率。即使输入名义频率也是 50 Hz，异步相位、调度抖动和链路延迟仍可能造成重复或漏采，不能保证每个输入样本都出现在 CSV 中。

模式 `2` 按固定 20 ms 时槽推进，轻微迟到仍保持周期相位；例如板端发送时刻可能为 0、21、40、61 ms，相邻间隔可为 19/21 ms，20 ms 不是最短间隔保证。长暂停后只发送最新快照，不补发旧帧；任务实际阻塞或 UART 忙仍可能漏组。

模式 `2` 先按表中单位生成整数测量值，再转成 float32，未改成 SI 浮点单位。float32 仅保证 `[-16777216,16777216]` 内的所有整数可精确表示，极端大整数会舍入。为避免数据字节误触帧尾，固件可能调整冲突浮点数的最低尾数位。CSV 后处理对序号分段、状态和掩码等整数语义字段先四舍五入再组合或做位运算；分成高低 16 位的时间与计数可据此还原，不能将所有 int32 测量值视为逐位无损。

schema 3 保留前 64 列的布局：`I0` 改为 `3`，`I33`–`I45` 改取远端底盘 IMU，并追加 `I64`–`I71` 的来源与接收诊断。`I63` 仍表示输出观测帧的主板角色，不能据此把 schema 3 的 IMU 判断成本地云台 IMU。

| `I50`、`I51` | yaw、pitch 编码器反馈年龄 | ms |
| `I52`–`I55` | 四轮最终尝试提交的 CAN 电流命令 | DJI 原始单位，LF、RF、LB、RB |
| `I56`–`I58` | 限制前模型功率、限制后模型功率、有效功率上限 | cW，除以 100 得 W |
| `I59` | 控制周期引用的功率计实测值 | cW |
| `I60` | 最终控制快照年龄 | ms |
| `I61` | 四轮目标反算快照年龄 | ms |
| `I62` | 控制周期引用的功率计样本年龄 | ms |
| `I63` | 记录板角色 `record_role` | `0` 主底盘/云台板，`1` 独立底盘 IMU 采集板 |
| `I64` | IMU 来源，仅 schema 3 | 固定 `2`：外部 CAN 底盘 IMU；bit 19 标识 DM |
| `I65` | 主板收到完整一组 IMU 后经过的时间 | ms；主板本地时钟 |
| `I66` | 输入年龄字段 | DM 为 `0`，不表示模块内部延迟为零 |
| `I67`、`I68` | 样本时间高、低 16 位 | ms；主板接收端估计时间，不是模块采样时间 |
| `I69` | 本组首片至末片的主板接收间隔 | ms |
| `I70`、`I71` | 接收端累计拒绝组数高、低 16 位 | uint32 计数，达到 `UINT32_MAX` 后饱和 |

schema 3 的 `I33`–`I45` 始终来自编译时选择的外部 CAN IMU；远端失效时对应测量填 0 并清除有效位，不切换成本地 IMU。schema 2 的这些列来自输出观测帧的本板。

`I23` 和 `I26` 是**车体转速**，不是电机 rpm，也不是 rad/s：轮速反算中的 `wz_rpm` 乘 `1000/60` 后发送。换成 rpm 时将记录值乘 `60/1000`；换成 rad/s 时乘 `2π/1000`。

`I5` 有效位与配置位定义：

| bit | 含义 | 对应数据 |
| --- | --- | --- |
| 0 | 原始诊断快照新鲜 | 采集入口已发布，年龄不超过 20 ms |
| 1 | 最新四轮反算有效 | `I21`–`I23`，同时要求四轮在线且新鲜 |
| 2 | 速度估计有效 | `I27`、`I28`；可能为轮速降级值 |
| 3 | 本行融合有效 | `I27`–`I32`，要求状态为 FUSED |
| 4 | INS 运动输入有效 | `I36`–`I45`；schema 3 检查远端组有效性及下述年龄条件 |
| 5 | yaw、pitch 两轴输入均有效 | `I46`–`I49` |
| 6 | 底盘控制快照有效 | `I7` |
| 7 | 功控模型有效 | `I56`–`I58` |
| 8 | 最终控制快照有效 | `I9`、`I52`–`I55` |
| 9 | 最终快照对应的控制周期计算有效 | 结合 bit 8 使用 |
| 10 | 对应 CAN 组提交成功 | 仅表示提交，需由反馈判断实际执行 |
| 11 | 四轮目标反算有效 | `I24`–`I26` |
| 12 | 功率计样本有效 | `I59` |
| 13 | 供电配置为超电 | `1` 超电、`0` 直供；是构建配置，不代表电源在线 |
| 14 | 独立 IMU 采集模式 | 与 `I63=1` 对应 |
| 15 | 远端 CAN IMU 模式 | schema 3、`I64=2`；模式位本身不代表已接收有效数据 |
| 16 | 远端 IMU 融合配置开启 | `CHASSIS_REMOTE_IMU_FUSION_ENABLE=1`；不是融合有效位 |
| 17 | 使用接收端估计时间 | DM 融合按首片接收时间估计采样时刻；不是硬件同步或时间误差通过 |
| 18 | 远端参数声明已实测审核 | `CHASSIS_REMOTE_IMU_CONFIG_VERIFIED=1`；默认 0，不控制算法是否运行，不代替精度验收 |
| 19 | DM-IMU-L1 来源（524288） | 外部 CAN 接收开启即标识 DM；不表示 IMU 有效或完成标定 |

主板本地观测的新鲜度上限为 20 ms，融合估计允许最多 60 ms。schema 3 的远端 IMU 单独要求完整组通过检查（`I66=0`，没有模块源年龄），且已知年龄下界 `I33≤60 ms`；字段存在或模式位为 1 均不能代替 bit 4。保留的原始年龄可超过上限。无效测量填 0，年龄未知或不能表示时填 `-1`，应结合有效位区分真实零值。`I8` 逐轮检查在线、时间和数值，bit 0–3 与所有四轮数组使用同一轮序。

`I6` 状态定义：

| 值 | 状态 | 含义 |
| --- | --- | --- |
| `-2` | IMU_CAPTURE_ONLY | 独立底盘 IMU 采集，无底盘速度估计 |
| `-1` | 未开启 | 未编入整车速度观测 |
| `0` | NO_SAMPLE | 尚无发布样本 |
| `1` | WHEEL_UNAVAILABLE | 四轮数据不可用 |
| `2` | UNCALIBRATED | 未标定，仍输出轮速反算 |
| `3` | CLOCK_INVALID | 时钟不可用 |
| `4` | IMU_UNAVAILABLE | IMU 不可用 |
| `5` | GIMBAL_UNAVAILABLE | 云台反馈不可用 |
| `6` | NOT_ALIGNED | 输入时间不满足对齐要求 |
| `7` | WARMUP | 等待中心补偿/融合历史 |
| `8` | REJECTED | 姿态、中心补偿或滤波拒绝 |
| `9` | FUSED | 观测已使用 IMU 融合 |
| `10` | CONFIG_INVALID | 远端安装、滤波或时间配置不合法，融合不可用 |

状态描述最后一次观测，是否仍新鲜必须看 `I5`。远端融合不使用云台输入，bit 5 为 0 本身不阻止它进入 FUSED；原车驱动安全仍可能因本地 INS/yaw 故障停机。只有在关闭远端融合且未开启本地标定时，bit 3 才始终为 0、`I29`–`I32` 为 0。bit 18 为 0 的远端试运行仍可能融合，不能把 `CALIBRATED=0` 或“未审核”误读为纯轮速。

DM 纯采集构建（远端融合开关为 0）在四轮有效时仍为 `I6=2`，bit 3/16/17/18 为 0。推荐远端融合构建经历配对与预热后可为 `I6=9`；远端失效且四轮有效时保留轮速降级估计，四轮失效则整体估计无效。本地 UART 诊断模式输出 schema 2，其 `I6=-2`、`I63=1`，仅有 IMU 相关测量；详见文末本地诊断。

### 时间、年龄与来源

DM 协议没有模块采样时钟或样本序号。`I34/I35` 是接收端生成的序号，`I67/I68` 是主板首片接收时间估计，`I66=0`。时间和计数按 `高位×65536+低位` 还原；模式 `2` 先四舍五入并转整数。时钟/序号按 uint32 回绕，拒绝组数饱和。主板重启后分段分析。

`I33=主板当前时间−首片接收时间`，是已知年龄下界，不包含模块内部采样、滤波与 CAN 排队延迟。`I65` 为完整组接收年龄，`I69` 为首末片跨度；有效输入要求完整组通过检查且 `I33≤60 ms`，不证明真实端到端延迟小于 60 ms。同一快照重复读取不刷新序号或时间；协议本身无法识别重复传输的一整个相同测量组。

融合用首片接收时间估计轮速配对时刻和物理 dt，输出时刻另对应三点补偿的中间样本。`I27/I28` 与 `I29/I30` 才是同一时刻的估计/配对轮速，不能与最新 `I21/I22` 或最新 IMU 列直接逐行比较。导航系加速度不是底盘前/右加速度；安装旋转和芯片偏移须实测。bit 17 只说明采用估计时间，不表示完成硬件同步。

## CSV 采集与交付

主板与所选 IMU 上电后先保持静止，等待主板 schema 3 的 `I5` bit 4 持续有效、`I65` 保持较小，再开始动作；DM 模块还要完成倾斜静止的重力扣除核对。记录所选 IMU 的实际安装轴向及芯片相对底盘中心的偏移，靠近中心也不等于偏移严格为零。

每个工况只保存**主板的一份完整 CSV**，同时包含四轮/命令/功率与所选外部 CAN 底盘 IMU。开始下一工况前保存上一份并清空采样缓冲区。每段动作前后各保留约 5 s 静止数据，低速动作重复 3–5 次，保留起停和换向过程。不要求先完成云台杆臂标定再开始底盘采集。

| 工况 | 建议记录时长 | 主要用途 |
| --- | --- | --- |
| 底盘、云台均静止 | 30–60 s | 零点、噪声与稳定性基线 |
| 云台尽量保持固定，低速前进/后退及起停换向 | 30–60 s | 前向轮速符号、加速度响应与滞后 |
| 云台尽量保持固定，低速左移/右移及起停换向 | 30–60 s | 横向轮速符号与响应 |
| 零输出手推旋转；有动力时仅使用已验证受限配置，分别记录可执行的方向 | 每个方向 20–30 s | 轮速与底盘 IMU 旋转响应、安装偏移影响；默认自旋档不是低速档 |

导出时保留完整 **`I0`–`I71`**、原有表头和 VOFA+ 时间列，不删除有效位、发送序号、来源、各年龄或拒绝组数，不用波形截图替代 CSV。使用 `DM_CAN2_` 文件名前缀，并附主板固件身份、模块参数截图和 bit 19。提交 CSV 时一并说明所用板卡的固件/提交号、完整构建命令、所选 IMU 安装轴向和芯片偏移、实际动作方向、地面与载荷，以及该段出现的抖动、延迟或拒绝计数增长。

统一 CSV 表示主板在同一发送时刻汇总最新数据，不表示四轮与远端 IMU 同时采样。比较轮速与加速度时仍须保留各来源年龄、源样本序号和接收诊断，并考虑首片排队、传感器内部延迟与模块导航系方向。源序号可帮助识别同一样本被重复记录；拒绝组计数可帮助定位接收异常。

这些数据用于初始噪声、符号、偏置、低频响应和融合参数分析。模式 `2` 的 20 ms 输出仍仅记录最新快照（模式 `1` 为 80 ms），无法保证捕获每次输入和滤波更新，也不能仅从该 CSV 完整辨识 Q/R；需要精确重放时，须另外保留每个融合输入及其原始时间。实际车速误差仍需独立速度参考；融合尚未进入控制，不能凭曲线宣称防滑效果。[实测与验收步骤](kalman-chassis-test-and-acceptance.md)

## 本地 IMU UART 诊断

`IMU_CAPTURE_ONLY=1` 仅运行本板 IMU 采样、温控和遥测，不启动整车电机/遥控任务，也不发送或接收外部 IMU CAN 数据。可用于排查本地传感器，不属于底盘 DM 融合方案。

```powershell
make -j8 PROFILE=atype-vehicle BUILD_DIR=build/imu-local-diagnostic IMU_CAPTURE_ONLY=1 CHASSIS_IMU_CAN_RX_ENABLE=0 CHASSIS_REMOTE_IMU_FUSION_ENABLE=0 CHASSIS_VELOCITY_FUSION_ENABLE=0 VOFA_TELEMETRY_ENABLE=1 VOFA_TELEMETRY_MODE=2 USB_TELEMETRY_ENABLE=0
```

输出 schema 2/64 列，`I63=1`、`I6=-2`、bit 14=1；只有本地 IMU 相关测量有效，控制/轮速列不可用。完整保存 `I0`～`I63`，不能把这一诊断固件当作正常整车固件。恢复整车时重新构建并烧录主板预设。
