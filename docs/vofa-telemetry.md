# 用 VOFA+ 查看 A 板无线遥测

## 编译固件

版本库中的 A 板配置默认 `VOFA_TELEMETRY_MODE=0`，在速度控制模式且 UART7 空闲时输出 JustFloat。本地若已把 [Inc/board_config.h](../Inc/board_config.h) 改为 `1`，正常构建会使用 FireWater；下方命令显式指定采集配置，避免依赖本地默认值。`VOFA_TELEMETRY_ENABLE=0` 可关闭输出。

| `VOFA_TELEMETRY_MODE` | 用途 | VOFA+ 协议 |
| --- | --- | --- |
| `0`（默认） | 原有 19 路遥测，默认 50 Hz | JustFloat |
| `1` | schema 2，64 路卡尔曼观测数据，每组一行，发送间隔至少 80 ms | FireWater |

在 [Inc/board_config.h](../Inc/board_config.h) 中修改 `VOFA_TELEMETRY_MODE` 后，正常编译烧录即可切换协议。构建命令也可显式覆盖该宏。力控模式、裁判使用 UART7 或 UART7 接有辅助设备时，默认关闭 VOFA+ 输出。USB 遥测可同时开启，也可用 `USB_TELEMETRY_ENABLE=0` 单独运行无线遥测。[A 板串口接线](atype-integration.md#接线)

FireWater 的 64 列替换原有 38 列功率测量格式，不能沿用旧列名；JustFloat 的 19 路格式保持兼容。两块 A 板使用同一工程的两种构建，分别导出底盘数据和独立中心 IMU 数据。第一块主底盘/云台板使用未标定观测固件：

```powershell
make -j8 PROFILE=atype-vehicle BUILD_DIR=build/kalman-firewater VOFA_TELEMETRY_MODE=1 CHASSIS_VELOCITY_FUSION_ENABLE=1 CHASSIS_VELOCITY_FUSION_CALIBRATED=0
```

这会采集四轮、INS 和云台原始输入；四轮有效时状态为 `UNCALIBRATED`，估计速度仍来自轮速。该板的 `I63=0`，其 INS 数据仍来自云台，不能当作第二块板的中心 IMU 数据。

第二块板刚性固定在底盘、尽量靠近几何中心，使用仅 IMU 采集模式：

```powershell
make -j8 PROFILE=atype-vehicle BUILD_DIR=build/imu-firewater IMU_CAPTURE_ONLY=1 VOFA_TELEMETRY_ENABLE=1 VOFA_TELEMETRY_MODE=1 USB_TELEMETRY_ENABLE=0 CHASSIS_VELOCITY_FUSION_ENABLE=0
```

该模式保留 INS 采样、加热和遥测，不初始化电机、底盘、云台或遥控。第二块板的 `I63=1`、`I6=-2`，不运行整车速度融合，也不接管底盘。两份固件分别烧入对应板，之后分别采集 CSV；目前没有两板通信或硬件同步，第二块 IMU 尚未实时输入第一块板的融合器。

本路线先做底盘与中心 IMU 的离线配对，不要求云台杆臂实测。若另行验证第一块板现有的云台 IMU 融合路径，需要目标车实测的 `chassis_velocity_fusion_calibration.h` 和 `CHASSIS_VELOCITY_FUSION_CALIBRATED=1`；不能使用 `tests/.../stubs` 的合成参数进行实车标定。[现有观测器的标定字段与读取方式](chassis-velocity-fusion.md)

当前整车默认直供。已接入匹配的 F334 超电且整车使用超电供电时，构建时设置 `CHASSIS_POWER_SOURCE_MODE=1`。JustFloat 的第 11–13 路是超电数据，其中第 12 路需要 F334 的 CAN `0x052` 输入功率反馈；FireWater 的 `I5` bit 13 标明供电配置。[超电协议](supercap-can-protocol.md)

## 连接调试器

1. 将塔克调试器的无线主机插到电脑 USB 口，接收端设为无线从机。普通款主机的 STA 灯为蓝色，从机为绿色。若尚未配对，按手册第 2.2 节完成配对并给两端重新上电。
2. 在 A 板位号 `16` 的串口组找到最右侧、丝印 `7` 的接口。接线前按 A 板和调试器的丝印核对引脚。[UART7 接口位置](referee-uart7-fix.md)

   | A 板 UART7 | 无线从机 |
   | --- | --- |
   | `TX`（PE8） | `RX` |
   | `GND` | `GND` |
   | `5V`（从 A 板取电时） | `5V` |

   单向遥测只需要上表中的连线。调试器引脚和供电方式见《塔克无线高速 DAP 调试下载器手册 V3.0.1》第 1.4、2.4.1 节，手册推荐从机使用 5 V 供电。

3. 上电后在 Windows 设备管理器的「端口（COM 和 LPT）」里确认主机新增的虚拟 COM 号。对应示意见手册第 2.5 节。

## 在 VOFA+ 中连接

1. 连接方式选 **SerialPort**，选择调试器的虚拟 COM 号，设为 **115200、8 数据位、无校验、1 停止位、无流控**。双板采集使用各自独立的 UART7 接收通道和 CSV 记录，按 `I63` 核对板角色；不要把两块板的 TX 并接到同一个接收端。
2. 按固件档位选择 **JustFloat** 或 **FireWater**，再打开串口。右侧数据栏以 `I0`、`I1` 等显示通道，点击通道名可重命名。FireWater 模式下，在字节接收区用字符串显示（关闭 `Hex`），并在 `Rx` 设置里显示采样数据包，即可看到每组完整的逗号分隔数据。 [VOFA+ FireWater 协议](https://www.vofa.plus/docs/learning/dataengines/firewater/)
3. 从控件栏拖入「波形图」，右键在 Y 轴菜单勾选要看的通道。JustFloat 可对照 `I0` 和 `I4` 的左前轮实测/目标转速；FireWater 可先对照 `I21` 和 `I24` 的轮速反算/目标前向速度，有融合数据后再比较 `I27` 和 `I29`。标称 Δt 为 JustFloat `20 ms`、FireWater `80 ms`；FireWater 的实际间隔和缺帧由板端时间与发送序号判断。[VOFA+ 波形图操作](https://www.vofa.plus/docs/learning/widgets/wave/)
4. 采完后用左上角 **文件 → 保存数据** 将采样缓冲区另存为 `.csv`。切换固件档位或开启下一次测量前，先保存上一批，再清空采样缓冲区，分别命名文件。

接收区可能按窗口宽度折行。即使 64 列在窗口里折行，每组在串口上仍只有一个行末换行，保存的 CSV 按组分行。

## JustFloat 通道表

| 通道 | 数据 | 单位 |
| --- | --- | --- |
| `ch0`–`ch3` | LF、RF、LB、RB 电机转子实测转速 | rpm |
| `ch4`–`ch7` | LF、RF、LB、RB 电机转子目标转速 | rpm |
| `ch8` | 功率计实测功率 | W |
| `ch9` | 限制后模型估算功率 | W |
| `ch10` | 有效功率上限 | W |
| `ch11` | 超级电容输出侧底盘功率 | W |
| `ch12` | 超级电容输入功率 | W |
| `ch13` | 超级电容剩余百分比 | % |
| `ch14`–`ch16` | IMU 的 yaw、pitch、roll | ° |
| `ch17` | 电机在线位掩码，bit 0–3 对应 LF、RF、LB、RB | — |
| `ch18` | 数据有效位掩码，见下文 | — |

LF、RF、LB、RB 依次为左前、右前、左后、右后。将转子 rpm 除以 `REDUCTION_RATIO_WHEEL`（默认 19.0）即可换算为轮端 rpm。电机在线位清零时，该电机的实测和目标转速均发送 0。

`ch18` 的 bit 0 对应功控模型（`ch9`、`ch10`），bit 1 对应功率计（`ch8`），bit 2 对应电容输出与剩余百分比（`ch11`、`ch13`），bit 3 对应电容输入（`ch12`），bit 4 对应 IMU（`ch14`–`ch16`）。数据不可用时发送 0，可结合有效位区分真实零值。

每帧由 19 个小端 32 位浮点数和 `00 00 80 7F` 帧尾组成，共 80 字节。数据字节若恰好拼成帧尾，固件会调整冲突浮点数的最低尾数位，避免接收端提前切帧。发送周期跟随 `USB_TELEMETRY_PERIOD_MS`，默认 20 ms（50 Hz）。UART7 忙时跳过当期整帧。[JustFloat 解码器](https://github.com/je00/Vodka/blob/master/dataengines/justfloat/justfloat.cpp#L39-L50)

## FireWater 卡尔曼观测通道表（schema 2）

每行固定 64 个十进制整数，以逗号分隔，仅在最后一列后加一个换行（LF）。整行组好后一次提交给 UART7，串口为 **115200、8N1**。发送间隔至少 80 ms，标称 12.5 Hz；UART7 忙时跳过整行，后续发送序号会出现间隔。

| VOFA+ 列 | 数据 | 单位或编码 |
| --- | --- | --- |
| `I0` | 格式版本 | 固定 `2` |
| `I1`、`I2` | 本行板端时间的高、低 16 位 | ms |
| `I3`、`I4` | 发送尝试序号的高、低 16 位 | 从 0 开始，包含未发出的尝试 |
| `I5` | 数据有效位与配置位掩码 | 见下表 |
| `I6` | 速度观测状态 | 见状态表，关闭观测 `-1`，独立 IMU 采集 `-2` |
| `I7` | 底盘模式 | `0` 零力、`1` 自旋、`2` 不跟随、`3` 跟随档；无效 `-1` |
| `I8`、`I9` | 四轮在线位、最终使能位 | bit 0–3 对应 LF、RF、LB、RB |
| `I10`–`I12` | 原始诊断快照、速度估计、最新轮速反算的年龄 | ms；未知或不可用 `-1` |
| `I13`–`I16` | 四轮原始转子转速 | rpm，LF、RF、LB、RB |
| `I17`–`I20` | 四轮接收反馈的年龄 | ms，LF、RF、LB、RB |
| `I21`、`I22` | 最新轮速反算 vx、vy | mm/s，底盘前、右为正 |
| `I23` | 最新轮速反算的车体旋转速度 wz | mrev/s，即 `1000 × 转/秒`；除以 1000 得转/秒 |
| `I24`、`I25` | 四轮目标反算的 vx、vy | mm/s，底盘前、右为正 |
| `I26` | 四轮目标反算的车体旋转速度 wz | mrev/s，同 `I23` |
| `I27`、`I28` | 速度估计 vx、vy | mm/s；只有有效位 bit 3 为 1 才表示融合 |
| `I29`、`I30` | 与融合对应的配对轮速 vx、vy | mm/s，底盘前、右为正 |
| `I31`、`I32` | 融合所用的中心平移加速度 X、Y | mm/s²，固定导航系 |
| `I33` | INS 原始运动快照年龄 | ms |
| `I34`、`I35` | INS 样本序号的高、低 16 位 | 同序号表示同一 INS 观测 |
| `I36`–`I39` | 本板 INS 四元数 w、x、y、z | 数值除以 1000000；原生传感器系到该板导航系 |
| `I40`–`I42` | 本板 IMU 去重力加速度 X、Y、Z | mm/s²，该板导航系，尚未进行杆臂校正 |
| `I43`–`I45` | 本板 IMU 角速度 X、Y、Z | mrad/s，原生传感器系 |
| `I46`、`I47` | yaw、pitch 原始编码器 | `0…8191`，保留零位前的原值 |
| `I48`、`I49` | yaw、pitch 转子转速 | rpm |
| `I50`、`I51` | yaw、pitch 编码器反馈年龄 | ms |
| `I52`–`I55` | 四轮最终尝试提交的 CAN 电流命令 | DJI 原始单位，LF、RF、LB、RB |
| `I56`–`I58` | 限制前模型功率、限制后模型功率、有效功率上限 | cW，除以 100 得 W |
| `I59` | 控制周期引用的功率计实测值 | cW |
| `I60` | 最终控制快照年龄 | ms |
| `I61` | 四轮目标反算快照年龄 | ms |
| `I62` | 控制周期引用的功率计样本年龄 | ms |
| `I63` | 记录板角色 `record_role` | `0` 主底盘/云台板，`1` 独立底盘 IMU 采集板 |

`I23` 和 `I26` 是**车体转速**，不是电机 rpm，也不是 rad/s：轮速反算中的 `wz_rpm` 乘 `1000/60` 后发送。换成 rpm 时将记录值乘 `60/1000`；换成 rad/s 时乘 `2π/1000`。

`I5` 有效位与配置位定义：

| bit | 含义 | 对应数据 |
| --- | --- | --- |
| 0 | 原始诊断快照新鲜 | 采集入口已发布，年龄不超过 20 ms |
| 1 | 最新四轮反算有效 | `I21`–`I23`，同时要求四轮在线且新鲜 |
| 2 | 速度估计有效 | `I27`、`I28`；可能为轮速降级值 |
| 3 | 本行融合有效 | `I27`–`I32`，要求状态为 FUSED |
| 4 | INS 运动输入有效 | `I36`–`I45` |
| 5 | yaw、pitch 两轴输入均有效 | `I46`–`I49` |
| 6 | 底盘控制快照有效 | `I7` |
| 7 | 功控模型有效 | `I56`–`I58` |
| 8 | 最终控制快照有效 | `I9`、`I52`–`I55` |
| 9 | 最终快照对应的控制周期计算有效 | 结合 bit 8 使用 |
| 10 | 对应 CAN 组提交成功 | 仅表示提交，需由反馈判断实际执行 |
| 11 | 四轮目标反算有效 | `I24`–`I26` |
| 12 | 功率计样本有效 | `I59` |
| 13 | 供电配置为超电 | `1` 超电、`0` 直供；是构建配置，不代表电源在线 |
| 14 | 独立 IMU 采集模式 | 与 `I63=1` 对应 |

除融合估计允许最多 60 ms 的年龄外，上述新鲜度上限为 20 ms；保留的原始年龄可超过该上限，不能仅因有年龄数值就使用对应测量。无效测量填 0，年龄未知或不能表示时填 `-1`，应结合有效位区分真实零值。`I8` 逐轮检查在线、时间和数值，bit 0–3 与所有四轮数组使用同一轮序。

`I6` 状态定义：

| 值 | 状态 | 含义 |
| --- | --- | --- |
| `-2` | IMU_CAPTURE_ONLY | 独立底盘 IMU 采集，无底盘速度估计 |
| `-1` | 未开启 | 未编入整车速度观测 |
| `0` | NO_SAMPLE | 尚无发布样本 |
| `1` | WHEEL_UNAVAILABLE | 四轮数据不可用 |
| `2` | UNCALIBRATED | 未标定，仍输出轮速反算 |
| `3` | CLOCK_INVALID | 时钟不可用 |
| `4` | IMU_UNAVAILABLE | IMU 不可用 |
| `5` | GIMBAL_UNAVAILABLE | 云台反馈不可用 |
| `6` | NOT_ALIGNED | 输入时间不满足对齐要求 |
| `7` | WARMUP | 等待中心补偿/融合历史 |
| `8` | REJECTED | 姿态、中心补偿或滤波拒绝 |
| `9` | FUSED | 观测已使用 IMU 融合 |

状态描述最后一次观测，是否仍新鲜必须看 `I5`。没有标定时，bit 3 不会置位，`I29`–`I32` 为 0；这不妨碍采集 `I13`–`I20` 和 `I33`–`I51` 的真实输入。

独立 IMU 模式中，测量有效位只使用 bit 0（采集快照）与 bit 4（IMU）；保留 `I1`–`I4` 的时间/发送序号、`I10` 的采集年龄和 `I33`–`I45` 的 IMU 数据。底盘、轮速、云台、功率字段不可用，数值为 0、年龄为 `-1`、底盘模式为 `-1`。`I63` 决定 IMU 来源：主板记录是云台 IMU，独立采集板记录才是底盘 IMU。两块 INS 各有自己的导航参考系，不能假设四元数和导航系加速度直接同轴。

时间和序号用 `高位 × 65536 + 低位` 还原：板端时间为 `I1×65536+I2`，发送序号为 `I3×65536+I4`，INS 序号为 `I34×65536+I35`。拆分可避免 VOFA+ 将整个 32 位整数转成单精度时丢低位。时钟和序号按 uint32 回绕；已知年龄的样本时刻可由本行板端时间减去年龄，按同样的回绕规则还原。CAN/INS 时间是 MCU 接收或读取完成时间，不是设备内部采样时刻。

`I27`/`I28` 与 `I29`/`I30` 用于融合对应时刻的速度对照，估计时刻由 `I11` 还原；`I21`/`I22` 和原始 IMU 属于更新后的输入，各有自己的年龄。不能把整行所有量当成同时采样。估计减去配对轮速得到的是**后验差**，不是滤波器校正前的 innovation。

## CSV 采集与交付

两块板上电后先保持静止，等待各自 `I5` 的 bit 4 持续有效，再开始动作；现有 INS 会在启动时进行陀螺零偏与重力标定。第二块板记录其实际安装轴向及 MPU6500 芯片相对底盘中心的偏移，靠近中心也不等于偏移严格为零。

每个工况同时保存两份独立 CSV：主板的轮速/命令/功率，以及第二块板的底盘 IMU。先按 `I63` 确认两个接收窗口没有弄反，开始下一工况前清空各自的采样缓冲区。每段动作前后各保留约 5 s 静止数据，低速动作重复 3–5 次，保留起停和换向过程。云台单轴动作是核对当前 IMU 来源的可选记录，不要求先完成云台杆臂标定再开始底盘采集。

| 工况 | 建议记录时长 | 主要用途 |
| --- | --- | --- |
| 底盘、云台均静止 | 30–60 s | 零点、噪声与稳定性基线 |
| 可选：底盘静止，仅云台 yaw 往复 | 20–30 s | 核对当前云台 IMU 的来源与旋转响应 |
| 可选：底盘静止，仅云台 pitch 往复 | 20–30 s | 核对当前云台 IMU 的来源与旋转响应 |
| 云台尽量保持固定，低速前进/后退及起停换向 | 30–60 s | 前向轮速符号、加速度响应与滞后 |
| 云台尽量保持固定，低速左移/右移及起停换向 | 30–60 s | 横向轮速符号与响应 |
| 低速自旋，分别记录两个方向 | 每个方向 20–30 s | 轮速与车体旋转响应，供后续中心 IMU 对照 |

导出时保留完整 **`I0`–`I63`**、原有表头和 VOFA+ 时间列，不删除有效位、发送序号或各来源年龄，不用波形截图替代 CSV。可按 `主板_静止.csv` / `中心IMU_静止.csv`、`主板_前后起停.csv` / `中心IMU_前后起停.csv` 配对命名，其他工况沿用相同前缀。提交 CSV 时一并说明每块板烧录的固件/提交号、完整构建命令、安装轴向与位置、标定头（若有）、实际动作方向、地面与载荷，以及该段出现的抖动或延迟。

两块板独立计时且没有硬件同步。两端都开始记录后，在同一现场保留明显的“静止—低速起步—停车—静止”重复序列，供离线按轮速变化与中心加速度做粗配准；它不能提供毫秒级准确同步。不能仅按行号、各自开机毫秒或电脑接收时间配对。分析时需同时考虑时间偏移、时钟漂移、传感器内部延迟以及两板导航系方向，再比较轮速和中心加速度。

这些数据用于初始噪声、符号、偏置、低频响应和融合参数分析；第二块板的参数分析还需要其实际采集数据和时间配对结果。80 ms 输出是降采样，无法逐次重放高频滤波更新或完整辨识 Q/R；需要精确重放时，须另外保留每个融合输入及其原始时间。轮速与融合结果一致也不能证明打滑时真实车速准确，真实速度误差和防滑效果需要独立速度参考。
