# 精简卡尔曼闭环观测（schema 9）

双 A 板远端融合默认输出 **64 路 `I0`–`I63`**，`I0=9`。VOFA+ 选择 **JustFloat、230400 / 8N1**，清空旧数据后重新连接；旧通道名称与曲线绑定需按新表更新，保存全部 64 路原始 CSV 即可。完整逐路表及有效位见 [VOFA 通道定义](vofa-observation-channels.md#schema-9-kalman_control)。

默认去掉原始 IMU 四元数/加速度/陀螺、滤波重放输入与噪声/安装参数、重复源时钟、yaw PID 内部量。需要这些专项诊断时，在 `config/_vofa/vofa_config.h` 中设置 `VOFA_KALMAN_FULL_DETAIL=1`，重新构建得到兼容旧布局的 109 路 schema 8；设回 0 恢复精简档。非远端融合的快照模式仍使用 schema 7。

## 日常需要看的通道

| 通道 | 内容 | 用法 |
| --- | --- | --- |
| I0–I9 | 格式、采集时间/序号、有效位、状态、模式、轮在线与融合年龄 | I7：0 零力、1 小陀螺、2 不跟随、3 跟随 |
| I10–I12 | 轮速估计 vx/vy/wz | m/s、m/s、rad/s |
| I13–I15 | 送入四轮解算的目标 vx/vy/wz | 已包含当前卡尔曼修正 |
| I16–I18 | 融合 vx/vy、IMU 年龄 | 按 I5 有效位判断能否使用 |
| I19–I21 | yaw 相对角、云台连续航向、小陀螺圈数 | 圈数须检查 I5 bit 11 |
| I22–I24 | 控制门控位、控制记录年龄、控制器当时读取的融合样本年龄 | I24 与 I9 来自更新前后不同快照，不能互相替代 |
| I25–I30 | 修正前请求、实际反馈参考、实际反馈速度，各 vx/vy | 小陀螺参考不带前馈相位超前；反馈已转到当前底盘坐标 |
| I31–I32 | 实际加入命令的 vx/vy 修正 | 最终限幅后的增量；m/s |
| I33–I36 | 当前四轮目标转子 rpm | LF、RF、LB、RB；I22 bit 8 表示发布成功 |
| I37–I38 | 累计底盘控制周期数，高/低位 | 每个底盘周期更新 |
| I39–I40 | 累计反馈有效周期数，高/低位 | 死区内也可增加 |
| I41–I42 | 累计非零修正周期数，高/低位 | 实际输出增量非零时增加 |
| I43–I44 | 累计成功提交的修正目标版本数，高/低位 | 电机侧证据，同一控制版本只计一次 |
| I45–I47 | 上次发布的非零修正 vx/vy 及距今 ms | 当前修正归零后仍保留；检查 I22 bit 10 |
| I48–I53 | 上次非零修正的控制版本及四轮目标 | 版本高/低位 + LF、RF、LB、RB |
| I54–I59 | 当前发布版本、电机已采用版本、最近电机记录年龄与状态位 | 两任务异步，版本可相差一拍 |
| I60–I63 | 最近电机周期四轮最终电流命令 | 有符号 DJI 计数，不是安培 |

所有 uint32 计数按 **round(高位)×65536+round(低位)** 还原，跨回绕使用 uint32 差值。直接画低位 I42/I44 可快速观察增长，跨 65535 时须结合高位。计数从主板启动起累计，比较同一试次内的增量，不能把进入试次前的历史算作本次生效。

## 怎样证明反馈已走到控制输出

1. 确认 I7=1 正在小陀螺，I5 bit 14（16384）为 1，表示控制记录存在且年龄不超过 20 ms。
2. **I41/I42 还原值增加**：控制器确实生成过非零速度修正。I31/I32 显示当前修正；若当前为零，I45/I46 和 I47 保留最近一次已发布修正及其年龄。
3. **I43/I44 还原值增加**：电机周期实际使用了带修正标记的全部四轮目标，四轮均使能且对应 CAN 邮箱接受提交。同一版本重复执行不重复计数；CAN 失败、任一轮未使能、调参替换目标均不计入。
4. I33–I36 / I50–I53 可核对当前和最近修正时的四轮目标；I54–I57 关联发布和电机采用版本。I60–I63 是最终尝试提交的电流命令，结合 I59 的 CAN 接受位解读。

I5 bit 13 和 I22 bit 6 只表示采样该周期的反馈门控通过，死区内可以修正为零。FIFO 仍主要在新滤波调用、状态/模式变化及 100 ms 心跳时捕获，**不因每次控制门控翻转而额外发帧**；每周期累计和保留的上次修正用来覆盖两帧之间的活动。FIFO 排队后按原捕获时刻计算年龄，不按发送时刻重算。

I22（trial_flags）：bit 0 试验已启用，1 模式允许，2 融合快照有效，3 FUSED，4 轮速有效，5 控制读取时年龄通过，6 反馈门控通过，7 当前修正非零，8 四轮目标发布成功，9 发布时允许驱动，10 有上次已发布非零修正。

I59（applied_flags）：bit 0 电机记录存在，1 实际四轮目标与修正版本目标一致，2 全部对应 CAN 邮箱接受提交，3 该控制版本驱动开启，4–7 各轮在提交时使能（LF/RF/LB/RB）。I58 是最近电机周期距捕获时刻的年龄；I5 bit 15（32768）要求该记录不超过 20 ms。I5 bit 4 和 bit 10 在精简档保留为零，因为不发送完整滤波尝试/yaw 控制记录。

这些信号能证明闭环修正进入了实际软件控制与 CAN 提交路径。电机是否按指令执行、轨迹是否改善，仍需轮速反馈、尺量和同条件开关对照共同判断。最终电流还受速度 PID、功率限制和安全门控影响，不能从电流单独反算卡尔曼贡献。

## CSV 分析和传输

`scripts/analyze-vofa.py` 自动识别 schema 9，报告传输缺口、FIFO 溢出和可比较端点之间的控制/反馈/修正/提交次数增量。未发送的滤波调用计数标记为未知，不冒充零；精简 CSV 不支持完整滤波重放或参数拟合。旧 schema 4–8 的解析与重放保持兼容。

64 路加帧尾是 **260 字节**，50 Hz 约 **13.0 kB/s、11.28 ms/帧**，230400/8N1 占用约 **56.4%**。比旧 440 字节减少约 **40.9%**，16 槽 FIFO 的事件捕获频率保持原样。无线链路实际丢帧率需新固件复采验证。
