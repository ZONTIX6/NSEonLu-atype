# 卡尔曼底盘重新采集步骤

适用：主板 FIFO 采集、双 A 板远端 IMU 融合，当前 schema 7 / 108 通道（包含 yaw 编码器、云台航向和 yaw 控制环诊断）。旧 schema 5/6 仍可交给分析器，但缺少部分云台观测。

本次修复只改变记录链路，轮速、IMU 安装、卡尔曼参数和控制逻辑保持原值。软件测试和构建不能代替实车链路检查；先录一份短静止数据确认连续，再做运动试次。

## 1. 更新主板固件

本次只需更新整车主板 Board 1。下方 IMU 板 Board 2 若仍是当前配套 CAN1 采集固件，无需重刷；两板 CAN 选择和接线保持一致。下载器接到整车主板，车体保持静止、急停有效，在工程根目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-board.ps1 -Action Flash -Board 1
```

此命令先构建，成功后烧录。对应输出为 `build/board-1-main/basic_framework.bin`。也可使用现有烧录入口，但必须选择 Board 1，不能把主板固件烧到下方 IMU 板。

保持 `config/_vofa/vofa_config.h` 中 `VOFA_OBSERVATION_PROFILE=2`，主板预设 `VOFA_TELEMETRY_MODE=2`、`CHASSIS_REMOTE_IMU_FUSION_ENABLE=1`。本次不改任何滤波参数，也不设置 `CHASSIS_REMOTE_IMU_CONFIG_VERIFIED=1`。

## 2. 先检查 30 秒静止记录

1. VOFA+ 连接主板 UART7，协议 **JustFloat**，**230400 / 8N1**，保存 **I0–I107 全部 108 列**。继续使用现有无线串口接线。
2. 保持车体静止。先启动记录，再按主板复位，使 CSV 包含初始化和第一次滤波调用。不要在采集中途清空曲线或截掉启动部分。
3. 静止记录至少 30 秒，结束后再等 2 秒让记录发送完毕，再停止记录、导出 `00_静止连续性检查.csv`。
4. 把原始文件交给助手检查。正常运动/静止时约 50 行/秒；启动、预热或故障时允许较低频率的状态记录，不能只凭总行数判定连续性。

正常融合时通常 `I0=7`、`I6=9`、`I48=63`。`I5` 按位判断：原来的 31 加 FIFO 标志 64 为 95；yaw 编码器和云台 IMU 均有效时再加 256、512，可为 863；yaw 控制快照有效再加 1024，可为 1887，不能把 `I5` 必须等于某个数作为验收条件。初始化期间不同是正常的。不要手改异常行、列名或单位。

助手使用分析工具检查：

```powershell
python scripts/analyze-vofa.py '原始CSV路径' --output-dir build/vofa-analysis/recapture-check
```

输出目录每次使用新名称。连续性检查应满足：

- `quality.capture_mode = event_fifo`。
- `quality.capture_overflow_observed = false`。若为 true，表示主板本次启动曾发生队列溢出，先保存记录查原因。
- 稳定记录区间无捕获记录序号缺口、`missing_filter_calls = 0`，无意外重启/倒序。
- 存在从未初始化状态开始的连续滤波输入，或至少有足够长的连续段。状态心跳造成的同次调用重复应由分析器去重。

`missing_attempts` 在 FIFO 模式指捕获记录缺口；`missing_filter_calls` 是可比较记录端点之间缺失的滤波调用，两者不能混称串口丢包。FIFO 无法修复上游 IMU CAN 漏组、无线链路丢帧或电脑导出丢行；发现这些问题仍需按记录定位。

## 3. 连续性通过后，分文件重采

每个文件都先开始记录再复位主板，先静止 10 秒，随后执行动作。结束时停稳至少 10 秒，再等 2 秒后停止记录。空间受限时缩短单次运动，保留完整起步、运动和停止过程。

| 文件 | 动作 |
| --- | --- |
| `01_静止60秒.csv` | 全程实际静止 60 秒，不推车、不转云台。此文件可作为静止噪声依据。 |
| `02_前后左右.csv` | 低速前进、后退、左移、右移；每个方向保持约 3–5 秒，方向之间停稳 5 秒，完整重复两轮。 |
| `03_斜向平移.csv` | 低速左前、右前及反向斜移；每段约 3–5 秒，段间停稳 5 秒。 |
| `04_正反低速自转.csv` | 平移摇杆回中，分正反两个方向旋转，匀速段约 5 秒，方向之间停稳至少 5 秒，各重复两次。使用已经确认的受限旋转操作，不直接切入默认高速自旋。 |

若当前操作方式不能实现受限正反旋转，单独录制零输出下缓慢手推旋转，并在文件名注明 `手推旋转`。不要为采集临时改变机械尺寸、传感器比例或滤波参数。

另外保存同样动作的一轮独立复测，文件名加 `_复测`。参数选择和验证使用不同完整试次，不随机拆分相邻行。

小陀螺切换右偏另存一份原始 CSV，保持 yaw 输入不动，切换前后各保留 3–5 秒。`I99=1` 标记小陀螺，`I96/I97` 为相对底盘的编码器/对齐偏角，`I100` 减切换前基准才是云台头短时偏航。有效位和重复切换方法见[小陀螺切换偏差采集](vofa-telemetry.md#小陀螺切换偏差采集)。

## 4. 一并提供的简短信息

提交原始 CSV，说明哪些文件为完全静止、动力运动或手推动作，以及测试中是否有断电/急停/碰撞。保留本次固件提交号和烧录输出。

前次数据中稳定自转的陀螺/轮速角速度幅值相差约 24%。正反低速试次用于检查这一问题；如果需要确定绝对速度精度，还需独立参考，例如带时间记录的已知距离运动或视频。无需自行选择 Q/R，也无需预处理 CSV，助手继续做质量检查、回放和候选参数验证。

小陀螺固定偏差的第一轮复测、I102–I107 以及积分/输出限幅判断见 [yaw 控制环诊断](vofa-telemetry.md#小陀螺-yaw-固定偏差第一轮控制环诊断)。本轮先采集原参数基线，再依数据调整积分限幅或补偿。
