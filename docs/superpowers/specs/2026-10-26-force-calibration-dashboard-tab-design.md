# 力控标定接入原 USB 仪表盘的标签页方案

日期：2026-10-26。

状态：设计方案，尚未实施本次标签页整合。本文根据用户要求，将原 USB 仪表盘扩展为统一入口，并共用当前串口连接。

关联文档：

- [原标定工具设计](2026-10-26-chassis-force-calibration-tools-design.md)
- [原标定工具实施计划](../plans/2026-10-26-chassis-force-calibration-tools.md)

本文调整原设计的网页入口与电脑端连接装配方式。单轮限流、板端高速记录、冻结导出及物理标定方法沿用原设计。原计划中“独立标定操作页面、切换页面需要重新连接串口”的安排由本文替代；板端保护及其尚未完成的验证仍须按原计划完成。

## 1. 目标与范围

用户在原仪表盘连接一次 A 板，即可在同一个页面完成监测、在线调参、PID 自动整定和力控标定。

一级标签固定为：

```text
实时监测 ｜ 在线调参 ｜ 自动整定 ｜ 力控标定
```

连接栏保留在各标签上方，整个应用只有一套连接、断开和连接状态。切换标签不重新选择串口、不改变 USB DTR、不清空已有监测历史或标定报告。

本次改造包括：

- 将标定操作内容移入原仪表盘第四个标签。
- 统一串口所有权、输入分发、发送安排与连接生命周期。
- 将标定与 PID 整定、参数写入的互斥显示到同一个页面。
- 保留单轮脉冲、实时状态、冻结记录、曲线、测量表、CSV/JSON 导出及离线分析。
- 补充普通遥测与力控遥测的识别，防止共享页面显示错误来源或旧读数。

沿用原项目的原生 JavaScript、Web Serial 和本地服务，不新增前端框架、电脑串口库或跨页面串口共享服务。本次方案不涉及烧录和实机加载。

## 3. 页面结构与交互

### 公共区域

顶部保留连接状态、连接/断开入口和固件能力摘要。显示暂停只控制普通监测画面，不暂停串口接收、标定状态、心跳或安全提示。

存在准备中、已准备、加载中或停止待确认的控制会话时，公共区域持续显示：

- 当前控制功能及所选轮子。
- 当前板端状态和停止原因。
- “立即停止”按钮。

停止按钮在所有一级标签及移动端保持可见和可操作，不受普通请求忙碌、曲线绘制或文件下载禁用。

### 力控标定面板

内容顺序沿用已有标定流程：

1. 固件能力、准备条件和真实限值。
2. 单轮选择、有符号电流、上升/保持/下降时间和指令等效 A。
3. 手动准备、夹具确认、单次开始及停止状态。
4. 实时监测：请求/最终电流、原始/控制使用转速、温度、反馈年龄和负载/预算功率。
5. 冻结记录读取、板端时间曲线、缩放和原始点查看。
6. 测量条件、增长窗口 T、额外裕量及转矩测量表。
7. CSV/JSON 导出与历史文件导入。

面板不再提供第二套连接、断开按钮。首次进入只读取能力和状态；不隐式 ARM、START，不通过切换标签自动恢复上次试验。

### 标签切换

| 场景 | 预期行为 |
| --- | --- |
| 空闲、已冻结或已确认停止 | 直接切换，连接、历史和报告保留 |
| 从标定标签切走，标定仍处于准备或加载 | 立即请求 STOP，等待同一连接/会话的后续状态确认零电流提交，再完成切换 |
| 停止超时或状态无法确认 | 明确显示“停止尚未确认”，保留公共停止入口和控制互斥，不将本地超时显示为已归零 |
| 切换期间反复点击标签 | 合并待切换目标，执行同一次停止流程，禁止重复 ARM/START |
| 返回标定标签 | 展示当前状态及保留报告；下一次试验仍需显式准备和开始 |

切换到其他标签不会自动启动该标签的控制功能。PID 自动整定已有的停止与恢复语义继续保留。

## 4. 串口所有权与输入分发

`app.js` 创建且持有唯一 `TelemetrySerial.SerialSession`。所有功能只取得受控的发送与状态接口，不能调用端口选择、创建读取循环、修改 DTR 或关闭端口。

新增 `tools/usb-telemetry/serial-router.js`，只负责有界行组装和按协议分发：

| 输入行 | 交付对象 |
| --- | --- |
| 普通 CSV v1–v5 表头及数据 | 原遥测解析、存储与导出路径 |
| `force-v1` 表头及数据 | 力控遥测解析与对应公共监测来源 |
| `@T1` | 在线调参客户端 |
| `@A1/@A2` | PID 自动整定客户端 |
| `@FC1` | 力控标定协议及客户端 |

分发要求：

- 支持任意字节分片、拆开的 CRLF、多行合并及不同协议交错。
- FC1 回执不计入遥测坏行或历史样本，也不被 T1/A1/A2 客户端消费。
- 行缓冲有上限，依据实际遥测最大行长确定；FC1 继续执行其自身更严格的长度与字段校验。
- 超长、含 NUL 或损坏的行整行丢弃，从下一个行边界恢复，不把合法后缀重新解释为命令回执。
- 世代改变或断连时清空半行状态和旧请求；旧回执不能完成新连接的请求。

标定客户端改为与现有调参/整定客户端相近的接口：注入发送函数，由应用交付协议行和连接状态。客户端内部继续负责 FC1 请求 ID、generation、session、capture 身份、超时和 CRC 校验。

停止标定会话与关闭 USB 连接必须成为不同操作。客户端的会话取消、请求清理和心跳结束不直接关闭公共端口。

## 5. 发送安排与控制互斥

`SerialSession.send()` 已有的串行写入负责字节顺序；新增 `tools/usb-telemetry/control-coordinator.js` 负责功能间的发送安排与控制所有权。

### 发送顺序

1. 停止、取消。
2. 活跃会话的心跳。
3. 用户显式操作。
4. 普通状态和参数查询。

STOP 取消尚未发送的普通请求，尽快进入同一串口写入路径。已经交给浏览器串口的字节不能撤回，因此停止优先必须在排队阶段落实，并依赖板端停止优先及最终许可复查共同完成。

标定准备和加载期间暂停非必要的 T1 参数轮询、A1/A2 后台查询，标定 STATUS 降为有界频率。心跳由会话维持，不依赖面板是否正在绘制，也不允许并发堆积。

冻结数据仍按小块读取，每块验证后再申请下一块；停止可在块之间抢先。不得一次将整份导出请求压入公共发送队列。

### 功能所有权

| 当前所有者 | 允许 | 阻止 |
| --- | --- | --- |
| 无 | 普通监测、查询，以及用户显式申请的控制操作 | 能力不匹配的控制操作 |
| PID 自动整定 | 整定协议、停止、持续接收监测 | 力控标定准备、参数应用与保存 |
| 力控标定 | FC1 会话、停止、持续接收监测 | PID 整定、参数应用、源码参数同步及 Flash 保存 |
| 停止或操作结果尚未确认 | 停止与用于确认的状态查询 | 新的准备、开始和参数写入 |

协调器在发送 ARM/整定开始之前取得本地所有权，防止两个按钮同时申请。请求超时表示结果未知，不能据此释放锁。只有确认申请失败且未取得会话，或板端状态证明会话结束并已成功提交零电流，才恢复相关操作。

前端互斥用于统一交互和减少冲突；板端所有权、限值、心跳、能源及 CAN 最终检查继续作为最终保护。

## 6. 遥测、图表与数据真实性

普通 CSV 与 `force-v1` 各自保留原始字段及导出格式，公共显示只归一化双方实际提供且有效的量。

- 功率单位、转子 rpm、车体角速度及命令电流分别转换，不按列位置猜测对应关系。
- 未提供的 IMU、遥控器、目标转速或其他字段显示缺失，不能沿用前一个固件的读数或补零。
- 标定固件若未提供有效普通力控快照，公共区域标记该来源不可用；所选轮的标定实时状态来自 FC1 STATUS。
- 标定高速曲线仍由冻结 RX/CONTROL 事件生成，横轴使用板端相对时间。
- 普通监测的显示暂停、缩放、标签隐藏不影响标定采样、心跳及停止。
- 隐藏标签停止无用重绘，返回时按已缓存数据刷新，避免重复初始化客户端、轮询器或事件监听。

CSV/JSON 导出保留原始记录、限值、脉冲、数据完整性和测量条件。未知电压、提交号或脉冲身份继续明确标记为未知；文件导入、演示和分析不会调用 ARM/START 或参数写入。

## 7. 连接生命周期与旧入口

| 事件 | 处理 |
| --- | --- |
| 连接成功 | 统一通知各客户端，读取能力；只显示固件支持的操作 |
| 能力 disabled 或旧固件不支持 FC1 | 标定面板给出中文原因，普通可用功能继续工作 |
| 用户断开 | 先取消未发送的控制请求并尽力停止活跃会话，再由公共连接管理关闭 DTR、读取循环和端口 |
| 物理拔线、读取错误、世代变化 | 统一使所有请求和会话失效，停止心跳；保留带原身份的历史数据和报告 |
| 浏览器进入后台、刷新或关闭 | 尽力 STOP；不能保证浏览器发送成功，板端许可与心跳负责撤力 |
| 重新连接 | 查询能力与状态，不恢复控制所有权、ARM、START 或自动整定 |

原 `/force-calibration.html` 保留为兼容书签的轻量入口，跳转到 `/#force-calibration`。旧入口不加载标定应用、不创建串口；哈希定位只切换面板，不发起任何控制动作。

本地服务继续仅监听 localhost，保持现有静态路径白名单和 `/api/tuning` 的同源校验。

## 10. 验收标准

| 检查项 | 必须观察到的结果 |
| --- | --- |
| 唯一连接 | 一次连接只有一次 `requestPort/open`，一个 reader 和一个读取循环；反复切换标签均不重新打开端口 |
| 无隐式动作 | 连接、选择标定标签、哈希跳转、重连、刷新、导入历史均不发送 ARM/START |
| 混合协议 | 普通 CSV、force-v1、T1、A1/A2、FC1 任意分片交错后正确交付，无相互误消费 |
| 请求身份 | 不同前缀相同 ID、旧 generation、旧 session 和迟到回执不能完成错误请求 |
| 停止优先 | 查询或 READ 排队时点击停止，未发送的普通请求取消；停止不受 UI 忙碌禁用 |
| 心跳 | 普通显示暂停及重绘不影响心跳；无并发心跳堆积；停止及断连后停止续租 |
| 功能互斥 | 标定和整定不能同时取得控制；标定期间不能应用、同步或保存参数；结果未知时不提前解锁 |
| 切换停止 | 活跃标定切走时发送 STOP；仅在后续状态确认归零后完成切换；超时显示未确认 |
| 生命周期 | 断开、拔线、后台和刷新触发对应取消逻辑；重连保持历史但不恢复试验 |
| 来源真实性 | 缺失或失效的字段显示不可用；不保留旧固件读数；高速曲线来自板端事件 |
| 报告 | 实际下载 CSV/JSON，核对原始记录、身份、单位、完整性与未知值；不完整记录不产生完成结论 |
| 兼容入口 | 旧地址只跳转到统一仪表盘标签，无第二个串口实例 |
| 可访问性 | 四标签支持方向键、Home/End 和焦点切换；停止键可达；390 px 无页面横向溢出 |
| 回归 | 原网页测试及受影响的固件协议测试通过；模拟串口测试不枚举或打开真实设备 |

验证应使用主机测试及 Playwright 模拟串口，保留桌面、390 px 截图与模拟下载文件。软件检查不替代后续硬件验收，本次标签页整合不自动执行实机测试。
