# 第二块底盘 IMU 在线融合观测

日期：2026-11-12；实现基线：`d209c08`。

用户已明确授权：把第二块固定底盘 IMU 接入卡尔曼，仅做融合观测，暂不接底盘控制，并更新测试和验收文档。

## 范围与方案

保留 CAN1 `0x520` 和 FireWater schema 3/72 列。新增独立远端融合开关，脚本主板预设开启，第二板关闭；本地云台标定路径保持独立。新增纯数值适配器，由现有底盘观测入口调用，遥测仍是融合快照的唯一生产消费者。现有电机目标、PID、功控、随动、自旋和安全门控不消费融合结果。

选择“带明确时间限制的远端旁路融合”。另一选择是新增双向时间同步协议，能进一步约束时间误差，但需要额外协议、调度和硬件延迟验证；当前只做观测，不扩展该协议。直接将远端值替换本地 IMU 指针不可接受：时钟不同、安装模型不同，重复样本也不能当作新测量。

## 数据与时间

- 底盘任务将有效轮速反算及真实反馈代表时间存入 32 项固定历史环，无动态内存。
- 主板估计采样时刻为 `first_rx_tick_ms - source_age_ms`；保留首片传输排队及内部采样延迟未知的事实，标记 `timing_estimated`，不宣称硬件同步。
- 在上述估计时刻作有界轮速历史配对/插值；没有合格历史时等待或降级，不用当前轮速伪造同刻数据。
- 每个新远端源序号最多推进一次。源板时间用于中心三点差分和卡尔曼的物理 dt；独立保存输出对应的主板估计时间。无新样本时不刷新输出时间。
- 源时序、主板估计时序均检查单调性和回绕。序号/时刻倒退、源重启、异常间隔/抖动、无效姿态、远端过期均清历史后恢复预热。50 Hz 漏一组导致约 40 ms 间隔时，按现有中心算法 15～30 ms 范围重置，不偷偷放宽本地门槛。
- 当前四轮不可用时整体估计无效；远端不可用且轮速正常时退回当前轮速。不能悄悄切回本地云台 IMU。

## 坐标与参数

远端配置使用固定 `sensor_to_body_quaternion` 和 `imu_offset_body_m`，内部前/左/上，外部速度前/右为正。复用安装旋转数学，令 yaw/pitch 为零，不依赖云台编码器；复用三点中心补偿和现有速度/加速度 KF。

名义安装初值为单位旋转、零偏移，噪声参数是试运行初值，不是实测标定。`CHASSIS_REMOTE_IMU_CONFIG_VERIFIED=0` 明确保留未验证身份；实际测量、冻结参数后才能修改标识。该标识不控制算法是否运行，也不能代替实际验收。

## 观测与兼容

- 新宏 `CHASSIS_REMOTE_IMU_FUSION_ENABLE`：默认 0，板 1 预设 1，板 2 预设 0。要求正常单板速度后端、CAN IMU RX、整车观测开启，本地 `CALIBRATED=0`。
- `I27/I28` 为估计，`I29/I30` 为真正使用的配对轮速，`I31/I32` 为中心导航系加速度；只有状态 FUSED 且新鲜时 bit 3 才置位。
- `I33`～`I45` 继续为最新远端原始输入；`I33` 的已知年龄下界含义保持。
- `I5` bit 16=远端融合配置，bit 17=采用接收端估计时间，bit 18=配置声明已经实测审核。均不替代 bit 3。
- 详细时间、配对、重置及更新计数放入融合快照，不增加 CSV 列或改变发送带宽。

## 验证与完成条件

行为测试先失败再实现：安装旋转、非零固定偏移旋转、加减速融合有别于轮速、时间偏移/回绕/重启、重复源抑制、历史缺失、过期及恢复；应用层证明本地 IMU/云台无效不阻止有效远端观测；遥测证明融合列、有效位和旧模式兼容。保留原本地融合、CAN、INS、功控和安全回归。

构建默认整车、脚本两板、手动纯采集、本地合成标定构建及 CMake 远端主板；检查非法组合、ELF/内存和软件架构边界。更新实测手册、融合与 VOFA 说明和两板配置说明，明确软件完成不等于上板验收。只提交本任务文件，保留已有用户修改，不推送、不烧录。
