# 自转达到转速上限但功率未用满的改进方案

日期：2026-10-24。状态：设计方案，尚未实施。

基于当前工作区代码以及已提交的底盘整体速度反馈功能 `c22a411`。本文中的参数属于建议初值，不代表实车已验证的能力。

## 1. 目标与结论

推荐采用“软上限 + 硬上限 + 实际速度跟随判断”：自转达到日常软上限后，如果实际转速跟得上、功率仍有余量且保护允许，则继续有界提速；如果实际跟不上或已经达到硬上限，则停止增加目标并报告原因。

优先使用基础功率额度，基础功率达到确认条件后，才允许缓冲能量支持短时超限。低能量保护始终有效。

不能承诺所有工况都达到限制功率：轻载、供电能力不足或允许的最高转速先到顶时，持续功率可能低于额度。禁止为了填满功率读数而人为加阻力、让电机相互对抗或绕过电流限幅。

## 3. 三种处理方式

| 方式 | 优点 | 局限 | 结论 |
| --- | --- | --- | --- |
| 直接提高固定 max Wz | 改动少，易验证软件限速是否过早 | 无法区分跟不上和仍有余量，也缺乏物理速度约束 | 只适合作为受控标定手段 |
| 软硬上限配合跟随判断 | 有余量时继续提速，受限时停止积累目标，可诊断 | 需要补上限状态、物理约束和遥测 | 推荐 |
| 自转外环整体改为物理角速度控制 | 控制量和显示量统一 | 改动涉及现有正解算标度、参数和模式，需要更大范围重标定 | 本轮不采用 |

## 4. 生效范围与数据口径

首轮针对自适应自转、直供功率优先路径实现。固定、正弦和超级电容路径保持现有策略。初版只在纯自转或小平移条件下开放软上限扩展，大幅平移时冻结扩展并退回日常范围。

使用以下量：

- `P_base`：现有基础功率目标，正常为有效基础限功率的 98%。
- `P_goal`：功率阶段最终发布的目标，基础阶段等于 `P_base`；缓冲增补阶段等于基础目标加获准增补。
- `P_meas`、`P_filtered`：新鲜功率计数据及其现有滤波值。模型值不能替代实测值完成资格确认。
- `W_soft`：正常自转目标软上限，推荐沿用当前实际生效的 max Wz。
- `W_hard`：标定得到的绝对 Wz 指令边界，必须不小于 `W_soft`。
- `R_body_hard`：底盘几何中心绝对旋转速度上限，单位圈/s。
- `N_wheel_hard`：各轮转子绝对转速上限，单位 rpm。

`Wz` 是现有指令单位，不是 °/s 或圈/s。`actual.wz_rps` 是四轮反馈逆解的轮速里程计结果，受轮径、减速比、安装方向和打滑影响，不能视为独立的地面测速传感器。

整车快照有效期为 20 ms；自转增长资格继续执行现有更严格的逐轮反馈新鲜度检查。扩展确认依靠新功率帧及四轮新反馈，不因控制任务反复读取旧帧而累计时间。

## 5. 上限调节方式

### 5.1 保留一个功率误差控制器

不另加一套功率 PID 去调“最大转速”。保留现有功率误差到 Wz 的控制器，软上限作为准入门槛：

```text
未获得扩展资格：Wz 最大允许值 = W_soft
获得扩展资格：  Wz 最大允许值 = W_hard，再受物理速度和跟随差距限制

rate = 现有功率误差控制器(P_goal - P_filtered)
Wz > W_soft 区域内的正增长斜率 <= 扩展区上升斜率
负增长保留现有下降斜率和保护优先级
```

开放资格只放宽允许范围，不直接跳到硬上限。控制器必须从上一周期实际发布的 Wz 开始累加，输出被任何边界截断后，将内部目标同步到截断后的输出，禁止隐藏积分继续增长。

### 5.2 扩展准入条件

以下条件连续满足确认窗口才允许越过软上限：

1. 当前处于允许扩展的自适应自转路径，已接近软上限。
2. `P_goal - P_filtered > max(3 W, 5% × P_goal)`，瞬时功率也低于批准的物理功率上限。
3. 目标/实际整体旋转方向一致，整体旋转跟随误差在阈值内。
4. 四轮均在跟随误差范围内；扩展准入不能只靠“四轮正在加速”的趋势放行。
5. 无模型限流、电流饱和、快保护、制动、数据降级、低能量恢复或整车禁用。
6. 硬上限配置有效，候选下一步目标未触及轮速/整车速度硬边界。
7. 目标平移速度低于允许扩展的门槛。

软上限阻塞位只表示正在等待扩展资格，不能反过来作为第 5 条的保护受限条件，否则会形成永远无法开放的循环。

### 5.3 目标领先实际的限制

采用逐轮领先量和整体旋转误差共同约束。候选 Wz 经现有正解算得到四轮目标，任一轮的跟随误差超过允许值，停止增加目标。不要单凭平均转速接近，就忽略某个轮子掉队。

在纯自转中允许用整体转速误差辅助判断；在平移叠加下必须使用完整四轮目标，不能把总轮速简单除以某个常数当作旋转量。若当前目标已经超出跟随差距，只允许保持或下降；持续落后则按下降斜率收回目标，不因实际速度瞬时下降而猛跳目标。

### 5.4 硬边界与超速行为

对每个候选命令同时检查 Wz、四轮目标 rpm 和逆解后的整车目标圈/s。三个边界任何一个先达到，就停止正增长；若平移本身已占满轮速额度，不允许用提高自转目标突破它。

实际轮速或整车转速达到硬边界时，撤销正增长资格；实际超过硬边界时按受控下降路径降低速度需求，并由现有电流/功率保护限制输出。实际速度有惯性，软件裁剪目标不等于能保证瞬时实际速度永不超限。

硬边界不通过提升 PID MaxOut、修改电流限制或绕过快保护来突破。

## 6. 状态与退出条件

上限状态与已有 `spin_power_phase` 分开记录，避免把“功率阶段”和“速度受限原因”混成一套枚举。

| 上限状态 | 进入条件 | 动作与退出 |
| --- | --- | --- |
| NORMAL | 新进入自转，未到软上限 | 现有策略，目标不超过软上限 |
| QUALIFY | 接近软上限且功率不足 | 仅新样本累计扩展确认；条件失效清零 |
| EXTENDED | 扩展确认完成 | 沿功率误差继续提速；达到功率目标后保持资格，功率回落可继续调整 |
| TRACKING_HOLD | 轮速落后、饱和或保护禁止增长 | 立即停升；持续跟不上时回收目标；恢复健康且再次确认后允许扩展 |
| HARD_LIMIT | 触及任一硬边界 | 不再升速；保留误差诊断，允许正常下降；低于退出滞回后重新确认 |

“达到功率目标”本身不是撤销 EXTENDED 的理由，否则会反复从高转速退回软上限。EXTENDED 下发生短时跟随问题先停止正增长；持续问题、大幅平移、缓冲恢复或数据失效撤销扩展资格。

退出自转/零力：清除本次扩展资格和确认计时。反馈失效、周期异常、制动和预算明显下降：沿用现有控制器的降级/重置行为，并清除扩展确认。数据恢复后重新确认，不能继承失效前的资格。

参数下降时立即阻止发布超过新硬边界的目标；其他正常收回过程按下降斜率执行。硬边界优先于舒适性斜率。

## 7. 与缓冲能量控制协同

基础阶段仍先贴近 `P_base`。仅达到软上限且功率未到目标，不进入缓冲增补；允许扩展的目的，是先提高可利用的基础功率。

需要修改当前 `spin_capability_limited`：

- 碰到软上限但具备继续扩展空间：不等于硬能力到顶。
- 达到真正硬边界、持续跟随失败或电流饱和：仍是能力受限。
- `SOFT_LIMIT_WAIT` 可以阻止未确认时的增长，但不能直接当成永久能力饱和。

进入 BUFFER_ASSIST 前仍满足现有基础功率连续确认和能量门槛。增补后 `P_goal` 增大，EXTENDED 可继续有界提速；新增额度不绕过硬上限。

保持现有“能力受限持续 100 ms 则撤销增补”的规则。为防止“硬上限 → 撤销增补 → 降速 → 再次增补”的反复切换，增加一次能力受限锁存：只有在基础预算下健康运行、实际和目标都低于硬边界至少 5%，连续 500 ms 后才重新允许缓冲准入，同时重新完成基础功率确认。重复样本不能解锁；退出自转清除锁存。

缓冲撤销造成的预算下降继续走现有降速处理，不为了保持高转速而忽略低能量恢复或物理功率上限。

## 8. 建议参数与标定规则

以下确认时间、误差和斜率是首轮工程建议，需要用遥测评估；不是已经完成的实车整定结果。

| 参数 | 建议初值/规则 | 说明 |
| --- | --- | --- |
| 软上限 | 沿用当前生效 max Wz，工作区为 8000 | 升级时保留旧值的语义为日常上限 |
| 扩展开关 | 默认关闭，完成硬边界标定后开启 | 未标定时仍可显示完整诊断 |
| Wz 硬上限 | 未标定时等于软上限 | 不臆定 10000/12000 等实车边界 |
| 整车/轮电机硬上限 | 必填的有限正值，标定得到 | 未配置则禁止扩展，不伪装成已验证硬保护 |
| 扩展功率缺口 | `max(3 W, 5% × P_goal)` | 与 1 W 控制死区区分 |
| 扩展确认时间 | 200 ms | 按新功率和反馈样本确认 |
| 接近软上限 | 距软上限不超过 1% | 只在需要时触发确认 |
| 整体旋转跟随误差 | `max(0.05 圈/s, 5% × |目标圈/s|)` | 与逐轮跟随条件同时满足 |
| 逐轮跟随误差 | 沿用当前 500 rpm 起步 | 通过数据决定是否收紧，禁止自动扩大 |
| 扩展区上升斜率 | 600 Wz/s，且不超过现有 rise | 当前普通 rise 为 1200 Wz/s |
| 下降斜率 | 沿用当前 fall，工作区为 2400 Wz/s | 原有硬故障退出优先 |
| 允许扩展的目标平移速度 | `hypot(target.vx_mps,target.vy_mps) <= 0.10 m/s` | 超过时冻结扩展并按斜率收回软范围 |
| 持续跟随受限确认 | 100 ms | 单次异常立即停升，持续异常回收 |
| 硬边界退出滞回 | 5% | 避免边界抖动 |
| 缓冲能力锁存释放 | 基础预算健康且有 5% 速度余量持续 500 ms | 之后还需现有基础功率确认 |

硬上限标定流程：先确认轮径、减速比、方向和轮序正确；用当前软上限采集实际/目标、功率、原始电流请求和限流原因；仅在实际跟随良好时逐级提高试验边界。根据实车稳定性、供电、电机和机构允许范围确定硬值，并保留余量。架空验证用于核对方向与单位，不能直接作为带载最高速度结论。

参数校验拒绝非有限数、非正硬速度、`W_hard < W_soft`、扩展 rise 超过普通 rise，以及不一致的模式组合。旧 Flash 升级只恢复已有字段；新增扩展配置用明确的禁用默认值，不能把旧数据尾部解释为新参数。

## 9. 遥测和调试入口

保留现有统一速度指针：

```c
chassis_velocity->target.wz_rps
chassis_velocity->actual.wz_rps
```

跨任务仍通过 `ChassisGetVelocitySnapshot()` 读取一致数据。新增上限诊断放在自转控制状态/底盘遥测快照中，不向速度指针塞入功率控制状态。

拟追加诊断字段：

- 软上限、Wz 硬上限、本周期有效上限。
- 整车和轮电机物理硬上限。
- 上限状态、限制原因：软上限等待/硬指令上限/整车速度/轮速/跟随/电流/模型/保护/平移。
- 扩展确认时间、资格是否有效。
- 当前功率目标、实测功率缺口、最大逐轮跟随误差、整体转速跟随误差。
- 缓冲能力锁存与释放确认时间。

协议升级为 CSV v5，保留 v4 前 111 列的顺序和单位。固件格式、网页解析、导出、演示数据和最大行长检查一起更新；若原因位超过当前 1023，必须同步扩展解析校验，不能只改固件枚举。

网页在现有目标/实际曲线附近显示“软上限确认中 / 扩展中 / 跟随受限 / 已达硬上限”，让“功率未用满”的原因可以直接读出。未提供新字段的旧固件显示缺失，不补造零值。

## 10. 实施顺序

1. 增加独立测试：软件限速、实际跟不上、硬边界、旧帧重复、功率达标保持资格、退出重入。
2. 扩展自转配置/状态与参数校验，保留原功率误差控制器，实现准入和上限裁剪后的内部状态同步。
3. 在底盘集成中接入一致的四轮反馈、整体速度和候选轮速物理约束，区分软/硬限速原因。
4. 更新缓冲能力判断、硬边界锁存和释放，覆盖跨阶段联动测试。
5. 若对外开放新参数，同步运行时调参、网页范围、参数文件和 Flash 迁移；否则首版使用编译参数并明确展示生效值。
6. 追加 CSV v5 及网页诊断，保留 v1–v4 兼容。
7. 完成主机测试、固件构建和代码审查，再按标定流程验证实车。保存新策略与原策略同工况的遥测对比。

## 11. 验收标准

| 场景 | 必须满足的行为 |
| --- | --- |
| 软上限处功率不足且跟随良好 | 确认后平滑超过软上限，单周期增量不超过扩展斜率 × dt |
| 功率已达标 | 不因资格撤销反复掉回软上限；稳态使用原功率死区调节 |
| 四轮平均看似跟上但单轮落后 | 不允许扩展，报告具体跟随受限 |
| 实际转速长期跟不上 | 目标不无限积累；持续受限后收回需求 |
| 达到任一硬上限 | 目标不越界，明确报告功率仍未用满的限制原因 |
| 实际因惯性超过速度边界 | 撤销升速并降低需求，记录峰值；不宣称瞬时无超调 |
| 同一功率/反馈帧重复读取 | 不增加扩展、恢复或缓冲释放确认时间 |
| 平移突然增大 | 停止扩展，完整四轮候选目标遵守轮速边界 |
| 低能量、掉线、急停或周期异常 | 原保护行为保持，扩展资格清除，恢复后重新确认 |
| 达到硬边界触发缓冲撤销 | 无高频重复准入，只有满足余量和释放确认才重开 |
| 参数热更新/旧 Flash | 新边界立即生效，旧存储不会意外开启扩展 |

实车报告至少包含：相同基础功率限制下的平均实测功率利用率、实际圈/s、最大跟随误差、硬边界触发次数、缓冲最低值和恢复次数。分别报告基础阶段和缓冲阶段，不能用加速瞬间或缓冲释放峰值代表持续功率利用率。

验收的重点是“软件软上限不再无故阻止有效输出，真实边界仍受约束”；如果硬边界已到而功率仍低于额度，应判为能力/速度边界限制，而不是继续提高功率或转速要求。
