# 裁判缓冲能量动态利用与超级电容协同方案

日期：2026-10-12。状态：可评审设计草案。本轮交付为方案，尚未实现或进行实车验证。

本文补充[普通行驶、自转与冲刺方案](2026-10-10-chassis-energy-policy-design.md)。沿用其运动目标、遥控拨轮映射、电容能量门槛和冲刺释放后重新申请机制；本文取代旧方案中所有仅因低缓冲而禁止电容增补、限制冲刺进入或锁定本次冲刺的规定，包括第 4.3、6 节及相关参数与验收项。缓冲不足时禁止主动超取电，但健康电容仍可在自身安全范围内辅助底盘，让裁判缓冲恢复。

## 1. 目标与边界

目标是在需要加速或补充电容时利用裁判缓冲，减少机动性能损失，并保留能应对测量误差、通信延迟和功率限制变化的能量。

缓冲能量是裁判系统中的能量额度，不是另一块物理储能装置。超级电容才是实际储能装置。不能把缓冲能量与电容电量相加，也不能在负载功率预算中把同一份输入能力计算两遍。

不把“缓冲必须离开 60 J”作为控制目标。没有运动或充电需求时停留在满缓冲是合理的；不通过提高速度或制造负载主动耗掉能量。短时超取电依赖真实需求，恢复依赖实际取电低于限额，不能依赖强制周期震荡。

本文按用户给定的 60 J 上限设计。公开的 [RMUC 2026 规则手册 V1.4.0](https://bbs-web-static.robomaster.com/38afa6d7914345f7bb5d496692fd429b1773977681621/RoboMaster%202026%20%E6%9C%BA%E7%94%B2%E5%A4%A7%E5%B8%88%E8%B6%85%E7%BA%A7%E5%AF%B9%E6%8A%97%E8%B5%9B%E6%AF%94%E8%B5%9B%E8%A7%84%E5%88%99%E6%89%8B%E5%86%8CV1.4.0%EF%BC%8820260320%EF%BC%89.pdf)给出 60 J 缓冲上限和 10 Hz 功率结算。官方[规则目录](https://bbs.robomaster.com/wiki/20204847/809871?source=7)已列出 V2.2.0；本次未读取到该版本全文。部署时按实际赛别及裁判系统配置核对上限和结算机制，不把本方案的 25/45 J 门槛当作规则阈值。

## 3. 功率和能量必须分开

| 符号 | 定义 |
| --- | --- |
| `P_ref` | 有效裁判数据给出的原始功率限额，W |
| `P_in` | 电管至底盘供电系统的实际输入功率，含充电与转换损耗，W |
| `P_load` | 电容供能汇入后，底盘电机总负载功率，W |
| `P_cap` | 电容向母线提供的功率；放电为正、充电为负，W |
| `P_loss` | 供电系统内相应转换及线路损耗，W |
| `P_board` | F334 报告的底盘总可用功率，包含输入侧贡献，W |
| `E_buffer` | 裁判缓冲能量，J |
| `E_LB` | 含测量和时延裕量的缓冲能量保守估计，J |
| `r_cap` | 电容板协议上报比例，0～1 |

在测量边界一致时，能量关系为：

\[
P_{in}+P_{cap}=P_{load}+P_{loss}
\]

裁判缓冲变化采用裁判功率测量口径对应的输入功率：

\[
E_{k+1}=\operatorname{clip}\left(E_k+(P_{ref}-P_{in})\Delta t,\ 0,\ E_{max}\right)
\]

例如限额 80 W、负载 150 W、电容输出 75 W、损耗 5 W，则输入仍为 80 W，缓冲不消耗。相反，负载 30 W、电容充电吸收 65 W、损耗 5 W，输入为 100 W，缓冲每秒消耗 20 J。

F334 本地 `pReferee` 可用于输入功率估计，`chassisPower` 是负载功率，两者已经在固件中区分。F407 的功率计用于负载闭环前仍须核对安装位置；位于负载侧的功率计不能用于积分裁判缓冲，也不能从 `0x051.chassis_power_w` 推出 `P_in`。

## 4. 方案比较与推荐

| 方案 | 优点 | 主要问题 |
| --- | --- | --- |
| 三档固定功率 | 简单，便于台架验证 | 切换突变，无法直接覆盖数据延迟和短时消耗 |
| 连续能量调节 + 状态滞回 + 预测限幅 | 参数少，便于接入已有双板控制，能解释每次限幅原因 | 需要标定输入功率误差和执行延迟 |
| 完整模型预测控制 | 可联合规划电容与缓冲使用 | 依赖容量、效率、负载预测和求解器，当前基础不足 |

推荐第二种。第一版不增加能量积分环：能量本身就是功率差的积分，比例调节配合预测保护即可形成连续恢复。若实测存在稳定偏差，先校准采样与损耗，再决定是否需要额外积分。

## 5. F334：输入取电与缓冲控制

### 5.1 常态能量调节

第一版取共同参考能量 `E_target=45 J`，保守估计的正常工作区约 45～50 J；实际裁判读数因不确定度预留会略高。场景优先级由 F407 的负载预算表达，不新增场景指令或第二套缓冲闭环。

输入功率的期望偏移为：

\[
\Delta P_{wish}=\operatorname{clip}\left(K_E(E_{LB}-E_{target})-P_{margin},\ -P_{recover,max},\ P_{burst,max}\right)
\]

\[
P_{in,wish}=P_{ref}+\Delta P_{wish}
\]

初值取 `K_E=2 W/J`、`P_margin=5 W`、总恢复差额上限 `P_recover,max=20 W`、主动超取电上限 `P_burst,max=20 W`。式中的 20 W 恢复上限已包含 5 W 余量，不能再叠加扣除。输入目标始终限制在 0 与硬件能力之间，不沿用固定的 10 W 恢复下限。

采用这些初值，在 `E_LB=55 J` 时希望超取电 15 W；在 `E_LB=35 J` 时希望少取电 20 W。忽略饱和与需求不足时，平衡点约为 47.5 J。所有数值都属于待测试初值。

### 5.2 三个区间与滞回

| 保守缓冲能量 | 输入侧策略 | 电容协同 |
| --- | --- | --- |
| 45～60 J | 满足需求及预测条件后允许有限超取电 | 优先补充电容；底盘助力仍按场景预算 |
| 25～45 J | 禁止主动超取电，连续降低输入目标 | 降低非必要自转消耗，允许健康电容补足短时需求 |
| 低于或等于 25 J | 强制恢复，撤销所有正向输入增量 | 取消额外快速充电；有余能时继续辅助底盘，电容不足时降低负载 |

超取电允许状态首次启动及退出后，须 `E_LB >= 48 J` 且稳定 200 ms 才重新使能；`E_LB <= 45 J` 或任何关键条件失效立即撤销。恢复状态在 `E_LB <= 25 J` 进入，`E_LB >= 30 J` 且稳定 200 ms 才退出。恢复退出后处于中间区间，仍不能立即超取电。

正向偏移还必须满足电容/DCDC 健康、输入采样有效，并且有实际充电需求。第一版将 `r_cap < 0.90` 且电压、电流控制允许充电作为快速充电条件；电容接近满电、充电受限或无有效需求时，将正向偏移压到 0。保持已有满充电压控制及硬件电流限制。

第一版的缓冲超取电主要用于把高缓冲时的额度转移到电容，后续由电容承担加速峰值；不要求普通行驶主动增加负载功率。电容无法工作时禁止主动超取电，按有效基础预算降级。

### 5.3 预测安全边界

不能仅凭“还有 25 J”判断安全。设 `T_guard` 为从发现风险到输入降至安全范围所需的最坏时间，包含下次裁判结算相位、执行/通信等待和功率环下降响应。第一轮取 0.30 s，下调前必须用波形证明实际最坏响应更短。

设 `epsilon_P` 为输入功率可能高于指令的有界误差，则主动超取电的预测上限为：

\[
\Delta P_{safe}=\max\left(0,\frac{E_{LB}-E_{guard}}{T_{guard}}-\epsilon_P\right),\quad E_{guard}=25 J
\]

最终正向偏移不得超过 `min(P_burst,max, DeltaP_safe)`。还应使用当前输入功率上界计算下降期间的风险：

\[
E_{pred,LB}=E_{LB}-\max(P_{in,upper}-P_{ref},0)T_{guard}
\]

若 `E_pred,LB <= E_guard`，跳过升功率限速，立即下调到恢复目标。安全下调优先于平滑；物理功率环仍需要时间降功率，预测应覆盖这段时间。

举例：`E_LB=55 J`、持续超出限额 20 W，只消耗到 45 J 的理想时间为 0.5 s，触及 25 J 下界的理想时间为 1.5 s。实际主动超取电须在前者附近退出，并为执行延迟保留余量，不能把 1.5 s 全部当作可用时长。

裁判原始限额下降时重新计算全部边界并立即收紧目标。过流、欠压、过压、过温和电容故障保护始终高于缓冲策略；有界预测不替代这些硬件保护。

### 5.4 能量估计及重复帧

F334 使用本地输入功率按真实时间步长积分，并以裁判缓冲值作保守校正。首个有效数据建立估计；后续收到 `0x061` 时，估计只能立即向较低的裁判值校正，不能每收到同一个较高缓存值就向上重置。能量恢复来自输入低于限额的积分，且不超过当前裁判上报值。

用 `E_LB=max(0, E_est-E_uncertainty)` 决策。`E_uncertainty` 第一轮取 3 J，其后用输入功率偏差、能量量化、裁判相位差及记录到的通信误差确定。估计已积分覆盖的时间不再次作为旧数据消耗扣除。

F407 周期透传不等于裁判产生了新样本。第一版保持 `0x061/0x051` 布局；上述保守校正允许在没有新增裁判样本序号的情况下工作。F407 继续执行裁判数据 300 ms 有效期，失效后发送关闭 DCDC 的完整安全指令。F334 的通信失效不得伪造满缓冲或继续正向超取电。

能量更新节拍、有效指令看门狗与当前复用的 `communicationTimeoutCnt` 拆开。收到有效指令只刷新指令在线状态，不把重复数据当作新的能量测量，也不使用帧数替代控制时间。失效时清除能量增量及相关积分状态，恢复须重新通过有效性和滞回条件。

## 6. F407：负载预算与运动场景

F407 不控制第二套输入能量 PID，也不发送伪造的功率限额或缓冲值。它按场景安排负载需求，F334 决定实际输入取电及充放电。

在输入安全控制已更新、反馈健康的条件下，负载预算采用：

\[
P_{base}=\max(0,P_{ref}-R_{buffer})
\]

\[
H_{cap}=f_{cap}\min(H_{scene,max},H_{global,max},\max(0,P_{board}-P_{base}))
\]

\[
B_{goal}=\min(P_{board},P_{base}+H_{cap}),\qquad P_{load,target}=k_{safety}B_{applied}
\]

`R_buffer` 是负载侧计划让出的恢复功率，不是对实际输入功率的测量。F407 按相同的能量比例律，只取其中非负恢复部分，范围 0～20 W；使用本地新鲜裁判数据的保守能量值。F407 没有输入侧实测功率时，以经过标定的最大输入超额乘样本年龄作保守扣减，不能拿负载功率积分。

`H_cap` 是允许的负载预算增补，不是对电容实际放电功率的测量。`P_board` 是总能力，不能再加 `P_ref`；也不额外叠加一个“缓冲增补 20 W”。F334 调整输入目标后上报的总能力必须同步收紧，F407 把它作为硬上界。电容可提供的能力须经过电压、能量和故障限制，不能仅靠电压乘电流就声称具有足够续航。

| 场景 | 正常缓冲 | 缓冲恢复期间 |
| --- | --- | --- |
| 普通行驶 | 无额外电容增补；有输入余量时自动充电 | 主动让出 `R_buffer`，减小负载预算 |
| 自转 | 电容增补上限 40 W，并预留原方案 15% 机动功率余量 | 自转主动降速；电容增补可补偿恢复差额，但不用于继续提高自转速度 |
| 冲刺 | 电容增补上限 100 W，保持平移目标，自转让速 | 电容有余能时允许本次短时平移需求；禁止从输入侧借新的缓冲额度 |

自转恢复期间将场景增补上限进一步收紧为 `min(40 W, R_buffer)`，使它最多补偿让出的恢复差额；目标调节器禁止增速并主动降低自转目标。冲刺恢复期间仍保留电容增补上限，但受电容能量与实际总能力约束。

低缓冲时，电容辅助是有条件且不可长期维持的：沿用自转 20%/25% 电量滞回和冲刺 10%/25% 电量门槛。电容不足、状态过期、输出禁用或故障时移除增补，负载预算回到恢复后的基础预算。不能在电容增补为 0 后重新把预算抬到完整 `P_ref`，否则恢复目标会被负载侧抵消。

电容健康时 `r_cap` 偏低但仍在允许区间，可以辅助恢复；低于最低允许门槛时必须降负载。第一版不根据缓冲低于 25 J 单独锁死冲刺；低电容、反馈故障和输入失效仍锁住本次请求并等待释放后重新申请。预测保护触发时允许直接收紧负载预算，自转先让速，平移仍受到最终功率与电流保护约束。

输入目标和负载预算各自执行上升限速；下降立即生效。F407 保留原自转 200 W/s、冲刺 1000 W/s 的预算上升初值；F334 输入目标上升初值 100 W/s。功率模型纠偏不能改变真实负载目标，也不能绕过恢复功率扣减。

## 7. 电容充电与两份能量的联合判断

| 裁判缓冲 | 电容能量 | 优先动作 |
| --- | --- | --- |
| 高 | 较低且可充电 | 允许受预测限制的短时超取电，补充电容 |
| 高 | 较高或接近满电 | 保存额度，等待实际运动需求，不强迫耗能 |
| 低 | 充足 | 压低输入，电容辅助短时底盘需求，并减少自转消耗 |
| 低 | 不足 | 同时降低负载与充电需求，优先恢复裁判缓冲 |

充电与负载争用同一份输入额度。功率平衡必须计入损耗，不把 `P_ref-P_load` 全部当成电容实际充电功率。电容接受不了充电时，停止正向超取电并处理执行饱和；不能让能量或功率环继续积累正向修正。

当前 `r_cap=V_cap²/V_max²` 包含低于最低工作电压的不可用能量。若要预测冲刺续航，须先标定容量 `C`、最低电压 `V_min` 和放电效率，使用：

\[
E_{cap,usable}=\tfrac12 C\max(0,V_{cap}^2-V_{min}^2)
\]

电容能量比例足够也不等于功率能力足够；低电压时仍受电流限制。第一版继续用协议比例作门槛，不把 10%/20% 等比例直接解释为还能冲刺几秒，也不假定制动能量必然能恢复裁判缓冲。

长期平均功率受输入限额和损耗约束。假设限额 80 W，短时输入 100 W 持续 0.5 s 消耗 10 J；之后输入 60 W，需要约 0.5 s 恢复相同缓冲。实际恢复可能更久，取决于负载、充电需求和限制状态。策略允许这样的按需循环，不主动驱动固定循环。

## 8. 数据失效与恢复

沿用旧方案的电容/功率计助力新鲜度 20 ms、控制及电机反馈 5 ms、驾驶命令 30 ms、裁判整体有效期 300 ms。助力恢复须通过稳定条件；通用在线看门狗不能代替更短的新鲜度判断。

- 裁判失效或输出不允许：执行现有关闭输出指令，取消积极策略。
- F334 指令失联：关闭 DCDC、清除主动超取电及其估计有效状态；原固件把缓冲改为 50 J 的做法不能继续作为有效能量依据。重新收到有效使能指令后重建估计与允许状态，不能因失联前的使能缓存残留而绕过恢复检查。
- 电容失效：移除负载增补，按有效裁判预算及恢复扣减降级。
- 输入采样失效：F334 禁止超取电，进入保护；负载侧功率计不能替代输入采样。
- 负载功率计失效：取消冲刺申请和自转增速，用恢复后的基础预算及模型保护降级。
- 台架模式：现有链路提供固定限额但缓冲为 0 J；不能据此启用动态超取电。算法验证使用明确标记的模拟输入，真实供能验证使用有效裁判数据。

## 9. 初值与验收

| 参数 | 第一轮初值 |
| --- | ---: |
| 缓冲上限，按本方案假设 | 60 J |
| 参考能量 | 45 J |
| 保守估计的预计常态工作区 | 45～50 J |
| 超取电撤销 / 重新允许 | 45 J / 48 J |
| 强制恢复进入 / 退出 | 25 J / 30 J |
| 预测下界 `E_guard` | 25 J |
| 恢复稳定时间 | 200 ms |
| `K_E` | 2 W/J |
| 输入余量 `P_margin` | 5 W |
| 总恢复差额 / 主动超取电上限 | 20 W / 20 W |
| 输入目标上升速度 | 100 W/s |
| `T_guard` | 0.30 s |
| 能量不确定度初值 | 3 J |
| 快速充电比例上界 | 90% |

输入采样误差 `epsilon_P` 不预设为已验证的常数。启用主动超取电前，必须由同口径参考测量确定其上界；若未完成标定，正向额度取 0，仍可验证连续恢复和电容协同。这是启用条件，不是允许运行时跳过的参数。

记录至少包括：原始限额、原始缓冲及数据年龄、估计缓冲、保守缓冲、预测缓冲、输入目标/实测输入功率、输入偏移与限幅原因、总可用功率、负载目标/实测负载功率、电容比例与充放电方向、运动场景、恢复状态及冲刺退出原因。输入功率和估计缓冲可先在 F334 本地调试记录；不把未在现有 CAN 帧中传输的字段声称为 F407 已可观测。

验收按以下顺序执行：

1. 同口径标定输入和负载功率，确定误差上界、能量估计误差和功率环最坏下降时间；据此校核 3 J 和 0.30 s。
2. 超取电关闭时验证 45/48 J 和 25/30 J 滞回、限额变化、缓冲持续恢复及输出饱和；重复发送缓存缓冲不能把估计向上重置。
3. 在有效裁判数据与电容充电条件下，由小额度逐步增加至 20 W；检查真实缓冲下降、退出时延及最低能量，要求始终高于保护下界。
4. 在低缓冲、不同电容比例下比较辅助恢复与双低能量降负载；健康电容可以补峰，电容不足时实际输入不能持续超限。
5. 在相近初始电量、载荷和地面条件下比较平移达到目标 90% 的时间、自转与平移组合响应、缓冲最低值、电容变化和保护次数。功率需求不足时不要求增加耗能。
6. 覆盖裁判、电容、输入采样、负载功率计、驾驶命令及双板通信失效和恢复；下降立即执行，恢复不携带旧增量或旧冲刺请求。

验收通过意味着在测试覆盖工况下满足边界，并不把未测出的采样误差、时延或硬件能力当作保证。

## 10. 后续实现范围

先更新并验证 F334 的输入能量策略，再接入 F407 的场景负载预算与恢复扣减，最后联合验证冲刺与自转。两边能力确认前不启用新的主动超取电策略。

第一版保留 CAN 载荷含义和布局，真实裁判限额及缓冲继续原样透传；不把场景预算塞入原始限额字段。新的观测量先用板端调试记录，增加 CAN 诊断能力作为后续独立改动。

后续控制代码按纯算法、适配层和遥测分开：F334 管理 `P_in`、缓冲估计和充放电硬件；F407 管理负载预算、场景目标和轮级保护。F407 的裁判快照接口需同时提供原始缓冲数据的有效接收时间，读取缓存不能刷新该时间；这是本地接口扩展，不改变 CAN 载荷。移除或明确停用未接入的 F407 缓冲 PID，避免形成两个相互竞争的能量调节器。

本设计没有启用新策略、修改固件或完成实车验证；当前工作区已有控制参数改动不属于此次方案提交。
