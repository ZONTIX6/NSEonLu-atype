# 底盘跟随策略宏切换方案

日期：2026-10-23

状态：方案草案；已确认操控行为，本次仅交付文档，未修改控制代码。

## 1. 目标与操作感受

保留原有底盘跟随模式，增加“云台朝向为正前方、车身不自动跟转”的策略，通过一个编译期宏选择。后续实现建议默认启用新策略，改宏即可恢复旧策略。

用户已确认：**云台朝向始终作为前进方向，但底盘车身不再自动转到与云台对齐。**

新策略的具体表现：

- 云台朝前，前进输入使整车向云台前方移动。
- 云台转向车身侧面，前进输入使整车沿该侧向移动，车身不主动追着云台转。
- 云台朝后，前进输入使整车沿车身后方移动。
- 左右平移也以云台当前朝向为参考，后退与云台前方相反。
- 移动过程中转动云台，移动方向随实际云台朝向连续改变。
- 没有平移输入时，仅转动云台不会产生底盘主动跟转指令。

这里的“车身不自动跟转”指底盘旋转目标为零，不新增车身绝对航向锁定。受到云台反作用力、地面打滑等影响时，不能承诺车身物理角度完全不变；角度发生变化后仍用云台与车身的实时相对角重新换算移动方向。

## 2. 当前代码已具备的能力

本方案以当前工作区源码为依据，涉及以下位置：

| 位置 | 现有行为 |
| --- | --- |
| `application/gimbal/gimbal.c`，`GimbalTask()` | 发布 yaw 电机的单圈实测角度 |
| `application/cmd/robot_cmd.c`，`CalcOffsetAngle()` | 用实测角度减去 `YAW_CHASSIS_ALIGN_ECD` 对应角度，再经 `theta_format()` 处理环绕 |
| `application/cmd/robot_cmd.c`，`RemoteControlSet()` | 右侧开关中档选择 `CHASSIS_FOLLOW_GIMBAL_YAW` |
| `application/cmd/robot_cmd.c`，`VideoTransmissionControlSet()` | `Key_X` 计数模 4 等于 2 时选择 `CHASSIS_FOLLOW_GIMBAL_YAW` |
| `application/chassis/chassis.c`，`ChassisTask()` | 先按模式计算 `wz`，然后统一将云台坐标系平移命令换算为底盘坐标系命令 |

**现有跟随模式本来就以云台朝向解释平移输入，同时还让车身自动对齐云台。** 新需求的核心是取消跟随档中的自动对齐旋转，继续使用现成的平移方向换算。

当前旧跟随实际公式为：

```text
wz = clamp(-50 × theta_format(offset_angle), -4500, +4500)
```

这是带限幅的比例控制。源码旁“误差角度平方”的注释与实际表达式不一致，后续修改该分支时同步纠正注释；旧公式、符号和限幅保持原样。`wz` 使用工程现有命令单位，不解释为电机 rpm。

现有 `CHASSIS_NO_FOLLOW` 已经采用 `wz = 0` 加相同坐标换算，因此它的运动表现与新策略接近。但该模式还参与自动整定许可判断，不宜直接用它替换原跟随档的模式编号。

## 3. 实现方式比较

| 方式 | 优点 | 代价与结论 |
| --- | --- | --- |
| 在原跟随分支中用宏选择旋转策略 | 保留操作入口、模式编号、消息结构和旧公式；改动集中 | 同一模式编号在不同固件中代表不同策略，需要在配置文档说明。**推荐** |
| 在 CMD 层用宏把跟随档改发 `CHASSIS_NO_FOLLOW` | 可复用现有不跟随分支 | 改变模式语义，并与现有整定许可判断发生耦合；不采用 |
| 增加独立运行时模式枚举 | 两种行为的编号清晰 | 要同步检查遥测显示、模式切换与双板兼容；当前只要求宏切换，收益有限，不采用 |

采用第一种方式：保留 `CHASSIS_FOLLOW_GIMBAL_YAW` 作为原跟随档入口，宏只决定该入口是否生成车身自动跟转指令。

## 4. 宏设计

新增唯一需要用户设置的宏：`CHASSIS_FOLLOW_MODE`。

| 宏值 | 策略 | 平移参考方向 | 旋转目标 |
| --- | --- | --- | --- |
| `0` | 原车身跟随 | 云台当前朝向 | 保留原比例公式，自动对齐云台 |
| `1` | 云台方向平移 | 云台当前朝向 | 每个控制周期明确写入 `0`，不自动对齐 |

建议在 `application/robot_def.h` 的底盘配置区域定义默认值 `1`，用 `#ifndef` 允许构建参数覆盖，并对非 `0/1` 的数值配置触发编译错误。选择宏与 `CHASSIS_DRIVE_TYPE`、`CHASSIS_SPIN_MODE` 相互独立。

以下为**后续实现后的配置用法**，当前仓库尚未接入该宏：

```c
#define CHASSIS_FOLLOW_MODE 1  // 新策略：云台为前方，车身不跟转
// 改为 0 即恢复原车身跟随策略
```

将宏名加入 `config/atype-options.txt`，复用项目 Make/CMake 已有选项透传机制。切换宏需要重新构建并烧录，不增加运行时切换按键或 Flash 参数。

实现后的 Make 对比构建示例：

```powershell
make -j4 PROFILE=atype-vehicle BUILD_DIR=build/follow-original CHASSIS_FOLLOW_MODE=0
make -j4 PROFILE=atype-vehicle BUILD_DIR=build/follow-gimbal-forward CHASSIS_FOLLOW_MODE=1
```

CMake 对应配置参数为 `-DCHASSIS_FOLLOW_MODE=0` 或 `1`。不同宏值使用独立构建目录，避免 Make 复用不同配置的旧对象文件。双板部署时统一记录配置；本策略实际在执行底盘控制的固件中生效。

## 5. 控制数据流与坐标换算

```text
遥控器 / 图传平移输入
        ↓
CMD 发布 vx、vy、offset_angle 和原跟随模式编号
        ↓
ChassisTask 根据 CHASSIS_FOLLOW_MODE 选择 wz
        ↓
复用云台坐标系 → 底盘坐标系的平移换算
        ↓
现有麦轮 / X 型全向轮运动学解算
        ↓
现有功率限制与电机闭环输出
```

继续使用实测 yaw 编码器角度计算相对角，不能使用鼠标/摇杆给定的目标 yaw 替代。目标角尚未跟到时，前方必须对应云台实际朝向。

保持现有公式：设 `θ = offset_angle × DEGREE_2_RAD`，则

```text
chassis_vx = vx × cos(θ) - vy × sin(θ)
chassis_vy = vx × sin(θ) + vy × cos(θ)
```

不能清零 `offset_angle`，也不能再次对输入进行同样旋转；前者会使前进方向固定到车身，后者会重复变换。零位继续沿用 `YAW_CHASSIS_ALIGN_ECD`，不引入底盘 IMU 绝对航向或世界坐标系。

以下是公式层面的验算，输入 `(vx, vy) = (V, 0)`，`V > 0`：

| 相对角 | 输出 `(chassis_vx, chassis_vy)` | 新策略 `wz` |
| --- | --- | --- |
| `0°` | `(V, 0)` | `0` |
| `+90°` | `(0, V)` | `0` |
| `-90°` | `(0, -V)` | `0` |
| `±180°` | `(-V, 0)` | `0` |

该表验证数学变换，不直接等同于当前遥控器通道的正负号。现有遥控器与图传输入包含各自的符号映射，后续应分别验证“向前推 / W”确实沿枪口方向移动；若发现偏差，先核对输入符号、编码器增角方向与机械零位，不能凭表格直接反转现有公式。

## 6. 其他模式与切换边界

- 遥控器右侧中档及图传 X 键的原跟随入口使用宏选择的策略，保持现有云台 `GIMBAL_GYRO_MODE`。
- `CHASSIS_NO_FOLLOW` 保持现有行为和编号；新策略不借用其模式值，不扩大自动整定许可。
- `CHASSIS_ROTATE` 继续由现有小陀螺策略生成旋转指令，两种宏值下保持全向平移。
- 从小陀螺切入新策略时，当周期将旋转目标置零，不能残留上一周期 `wz`；真实车身会按闭环与功率约束完成减速，不承诺瞬间停转。
- `CHASSIS_ZERO_FORCE`、急停、失联处理、功率限制和最终电机输出许可沿用现有逻辑，宏不改变这些判断。
- 不新增模式枚举和通信字段，不改变结构体大小。遥测模式编号仍表示原跟随档，验收时结合构建宏值和 `wz` 判定所用策略。

## 8. 验证与验收

本次仅做文档审阅；以下是后续实现时需要执行的验证，尚未完成。

### 主机验证与构建

1. 宏 `0`：旧跟随在 `0°`、`±30°`、大角度及环绕附近保持原输出；例如 `+30° → -1500`、`-30° → +1500`，大误差保持 `±4500` 限幅。
2. 宏 `1`：全部有效相对角均输出 `wz = 0`；从小陀螺切入后不保留旧旋转目标。
3. 两种策略的平移结果相同，覆盖前后左右输入、`0°/±90°/±180°`、跨 `0/360°` 以及 `±180°` 边界；连续角度变化不出现方向突跳。
4. 原 `NO_FOLLOW`、小陀螺、零力和自动整定许可的行为不受宏影响。
5. 宏 `0/1` 分别通过固件构建，非法数值必须构建失败；确认 Make/CMake 实际将选项传入编译器。默认省略宏时等价于 `1`。
6. 回归现有底盘运动学测试，并核查急停及失联情况下输出许可仍被撤销。

### 实车验收

先架空核对轮向，再低速验证实际位移：分别将云台置于车身前、侧、后方，检查前进和侧移输入；之后边移动边转动云台，确认移动方向随枪口改变且车身没有主动对齐命令。遥控器和图传各验证一次。

切回宏 `0`，确认车身重新自动对齐云台；两种配置分别检查小陀螺进出、停止及急停。验收区分“目标 `wz` 已归零”与“实际车身已停止旋转”，后者受机械与闭环响应影响。
