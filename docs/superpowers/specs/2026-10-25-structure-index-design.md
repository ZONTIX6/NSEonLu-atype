# 结构体数据字典设计

用户已确认采用 Markdown 索引与一键更新脚本，并要求完整覆盖、中文用途查找和成员名反查。

## 输出与查找

- `docs/structure-index.md` 为统一入口，包含中文用途导航、来源统计、类型总表、成员反查表和每个类型的详细说明。
- 每个类型记录定义路径与行号、源码注释、中文模块关键词、成员声明与注释、嵌套类型链接。
- 成员反查按成员名排序，同名成员保留全部所属类型；匿名内嵌类型有稳定的来源标识，能沿父子关系查找。
- 同名类型按文件与行号区分，测试桩和便携副本不能覆盖主工程定义。联合体作为关联数据类型一并收录。

## 覆盖范围

扫描仓库全部 `.c`、`.h` 文件，包含 application、modules、bsp、Inc、Src、Drivers、Middlewares、portable_modules 和 tests，以及以后新增的源码目录。排除 `.git`、构建输出、依赖缓存、node_modules 和脚本生成的临时文件。压缩包不是展开源码，不扫描压缩包内容。

包含 typedef、带标签的定义、函数内部和 `.c` 私有定义、匿名嵌套、数组、指针、函数指针、位域、逗号声明、CMSIS packed 形式以及所有条件编译分支。只前向声明和类型引用不是新的定义。预处理条件作为来源信息显示；不声称这些分支在同一固件中同时生效。同文件的简单字段声明宏和 X-macro 字段列表展开成独立成员，并记录宏定义行与调用位置；未知、递归或包含字符串化/拼接的字段宏明确报错。其余任意宏不作完整预处理。

## 实现

Python 标准库完成词法扫描和括号配对，不依赖 Arm 编译器、编译数据库或联网安装软件。保留行号，屏蔽注释及字符串对语法的干扰，支持 UTF-8 BOM、GB18030 和 Windows-1252 历史源文件，解码失败明确报错。中文用途从维护的小型模块关键词表与原有注释组合生成；无源码说明的字段明确显示“源码未注释”，不猜测数据含义。

生成前完成解析与完整性检查，不能解析的定义/成员报告位置并以非零状态退出，避免静默缺项。输出按来源和位置稳定排序，不写入每次变化的时间戳。先写同目录临时文件并完成关闭，再原子替换现有索引，发布失败保留旧文件并清理临时文件。`--check` 用于验证索引是否需要更新，失败时不覆盖现有文档。

`scripts/update-structure-index.ps1` 从任意工作目录运行，允许 `-Python` 指定解释器并尝试发现本机 Python；`scripts/update-structure-index.cmd` 支持 Windows 双击，显示执行结果。自动化调用可以设置 `STRUCTURE_INDEX_NO_PAUSE=1` 禁用窗口暂停。

## 验证

使用标准库 unittest 对注释、匿名/具名嵌套、同名类型、自引用、联合体、函数指针、位域、条件分支、编码、成员反查、确定性输出和失败时保留旧索引进行验证。对实际仓库核对每个定义、成员、链接目标和行号；运行更新入口及 `--check`，随后只提交本次任务涉及文件。
