# 恢复随动、限功率优先自转与积极缓冲利用方案

日期：2026-10-24

状态：用户确认后已实施并完成主机/构建验证，尚未实车验收。当前行为、参数与旧 Flash 值处理见 [自转功率说明](../../chassis-power-priority.md)，执行记录见 [实施计划](../plans/2026-10-24-chassis-follow-power-priority.md)。旧 `buffer_PID` 已在方案起草阶段按用户授权清理。

## 1. 需求与推荐结论

本次解决三个问题：

1. **恢复原随动**：云台转动后，底盘车身重新自动跟转对齐；平移仍以云台实际朝向为前方。
2. **自转先用足基础限功率**：先让实测功率接近裁判限功率，再考虑缓冲增补，避免预算有余量但转速需求没有建立。
3. **缓冲利用更积极**：能量充足时快速释放额外功率，降低正常运行的能量保留目标；接近低能量区仍及时收回增补。

用户已确认第二点的含义：**先贴近裁判功率上限；达到后，利用富余缓冲短时超过上限；低能量保护始终生效。** 因此“再启动闭环”仅指开放正常能量增补调节，能量观测、预测和低能量保护不能延迟启动。

推荐采用“基础功率跟踪 → 缓冲增补”的两阶段策略，复用现有快速功率保护和能量观测器。以当前直供配置为首要验收对象；这里的缓冲是裁判缓冲能量，不是超级电容剩余能量。

基线为 `64cfb32` 及本次开始时的工作区；初始已有未提交修改：电机速度环 `Kp=0.75`、自适应开启、固定自转目标 `6000`、最高目标 `8000`。本次保留这些修改，不将其当作新方案已验证参数，也不纳入本次提交。

## 4. 恢复原随动

将 `CHASSIS_FOLLOW_MODE` 默认值从 `1` 恢复为 `0`，保留宏为 `1` 的可选行为。原跟随公式保持：

```text
wz = clamp(-50 × theta_format(offset_angle), -4500, +4500)
```

继续保留云台坐标到车身坐标的平移转换、现有操作入口和模式编号。遥控器右侧中档、图传 X 键对应的跟随档都恢复车身跟转。检查构建参数没有显式覆盖为 `1`；更新默认策略测试和当前配置文档，历史设计稿保留为历史记录。

验证 `+30° → -1500`、`-30° → +1500`、大角度限幅、角度环绕、自转切回随动及失联零力。宏 `1` 的显式覆盖仍应通过测试。

## 5. 自转：先建立基础功率，再开放缓冲增补

### 5.1 统一功率目标

定义：

- `P_limit`：当前有效裁判限功率；台架测试时单独记录台架设定值和来源。
- `P_base = 0.98 × P_limit`：第一版的基础实测功率目标，沿用现有安全系数。
- `ΔP_buffer`：能量环允许的额外实测功率，单位 W。
- `P_set = P_base + ΔP_buffer`：提供给自转功率跟踪和功率反馈环的共同目标，恢复状态除外。

`P_set` 是实测功率口径，不是电流模型内部预算。适配现有字段时，正常预算可按 `P_set / 0.98` 换算；物理保护上限单独受 `P_limit + ΔP_buffer` 与硬件上限约束，不能再重复乘安全系数，也不能把模型补偿量作为允许持续超功率的额度。必须测试 target、nominal、ceiling 到最终电流的整个链路。

先用 `0.98` 做可验证基线，目标是接近上限。后续只有实测表明计量误差和动态超调可控，才讨论进一步缩小这 2% 余量。

### 5.2 状态与优先级

状态名称为拟新增的策略状态，不替换已有快保护状态。

| 状态 | 目标与动作 | 退出条件 |
| --- | --- | --- |
| `BASE_TRACK` 基础跟踪 | `ΔP_buffer=0`，主动调整自转目标以接近 `P_base` | 满足到达确认和充足能量条件后进入 `BUFFER_ASSIST` |
| `BUFFER_ASSIST` 缓冲增补 | 在 `P_base` 上开放能量环，主动建立匹配的自转需求 | 能量下限降至 `15 J`、不再有自转需求或持续达到执行能力边界时撤销增补；低能量优先恢复 |
| `RECOVER` 低能量恢复 | 禁止增补，按缺口将目标降至基础目标以下 | 下限达到 `20 J` 并持续 `0.1 s` 后回到 `BASE_TRACK` |
| `DEGRADED` 数据降级 | 禁止增补和新的向上自适应；执行原数据失效处理 | 数据重新连续有效后，重新从基础阶段确认 |

每周期先执行原有输出许可与故障处理，再检查能量硬底座/回充，最后计算正常阶段目标。低能量进入条件采用第 6 节参数；不能因为尚未达到基础功率而延迟回充。

进入 `BUFFER_ASSIST` 的初始建议条件：

1. 自转有效，计量、电机、裁判及时间连续性均有效，没有制动、快保护故障或低能量恢复。
2. 滤波实测功率连续 `100 ms` 处于 `P_base ± max(2 W, 3% × P_base)`；瞬时实测不能超过基础阶段物理上限。
3. 保守能量下限至少 `30 J`，预测能量高于硬底座。
4. 未达到可达转速上限、电流硬上限或持续失速等执行能力边界。

到达判据以新增有效功率样本及其时间为依据，重复读取同一帧不能积累确认。进入增补后不再要求功率留在基础功率带内；退出后若需重新进入，重新确认基础阶段，避免状态抖动。裁判限功率改变、退出自转或反馈失效时撤销旧的到达资格。

这里“持续达到执行能力边界”指达到转速/电流硬上限或持续失速，初始以 `100 ms` 确认；基础模型限流或单次升速禁止只影响该周期增长许可，不直接退出增补，否则容易在正常功率限制附近反复切换。故障及能量硬底座处理不等待此确认。

### 5.3 解决“功率有余量但无法升速”

按原因分别处理，第一版不增加自转 PI 积分器，继续使用现有“功率误差 → 目标变化率”的结构：

| 情况 | 拟采取的动作 |
| --- | --- |
| 轮速已跟上、实测低于目标、没有保护限制 | 提高自转目标，上升速度按第 7 节调整 |
| 轮速仍在正常加速、功率未满 | 用“实际转速持续同向增长且误差未持续扩大”的有效反馈趋势允许有限继续增长；初始按正常上升率的 25%，禁止无界堆高目标 |
| 模型已限流、实测功率偏低 | 暂停目标继续上堆，使用现有功率慢环核对/修正模型；记录正修正是否达到 `8 W` 上限，不能直接删除模型限制 |
| 快保护、电流硬限、制动、反馈失效、持续不跟随 | 禁止向上增长，按原保护或降目标逻辑处理，明确输出原因 |
| 已到可达最高转速仍未到基础功率 | 保持上限并报告能力受限，不为“用满功率”继续抬高目标或强行消耗能量 |

趋势窗口初值为 `50 ms`，使用新电机样本；连续 `100 ms` 误差未改善且功率仍不足时停止趋势放行。原 `500 rpm` 门槛仍用于“已跟上”判据，趋势通道是受限的补充，不替代电流/快保护检查。启动时的有效 IDLE→RUN 应有受限升速通路，避免必须先有驱动需求才能产生驱动需求。

基础限流、执行器饱和和快保护应分别传递，不再只用一个合并布尔量解释所有升速禁止原因。模型慢环和自转需求控制分工：模型限流时优先校正模型；需求不足时提高转速目标，避免两个调节器同时无界向上推。

进入增补阶段后，能量预算先公布**可用增补容量**，自转目标按斜率产生真实需求，电机限流器仍只响应真实电流请求。不能继续把“上一周期需求已经超限”设为自转增补容量的必要条件，否则可能无法建立新需求。该例外只用于已通过到达确认的自转，普通平移仍沿用按需求分配逻辑。

## 6. 缓冲闭环：更快释放、降低保留目标

### 6.1 控制律

第一版采用显式能量目标的比例调节，保留当前观测器，不新增积分：

```text
E = 当前保守能量下限，单位 J
E_ref = 20 J
T_release = 0.25 s
ΔP_energy = max(0, (E - E_ref) / T_release)
ΔP_guard = max(0, (E - E_floor) / T_guard - P_margin)
ΔP_buffer = min(ΔP_energy, ΔP_guard, ΔP_max, 硬件剩余功率空间)
```

只在 `BUFFER_ASSIST` 状态允许正增补；其余状态为零。增补上升限斜率，降低/撤销立即更新预算，并通过原快速保护与电机闭环完成物理减速。实际超限消耗按输入实测功率观测，不能按命令功率假装能量已经消耗。

`E_ref` 与 `T_release` 让“积极程度”有直接含义：希望更快用掉高于保留目标的能量。初值下，`E=40 J` 给出 `80 W` 的能量请求，最终仍受 `60 W` 增补上限及保护约束；`E=25 J` 给出 `20 W`；接近 `20 J` 时逐渐回到基础功率。以上是目标示例，不是实车输出保证。

快保护应根据本周期获准的动态功率额度工作，不能仍把裁判基础值当作增补阶段唯一绝对上限；但模型修正、旧积分或阶段切换都不得绕过获准额度。裁判原始限功率仍用于能量收支估计，不用动态额度替换它。

### 6.2 建议参数

以下是**后续首轮验证候选值**，本次不写入固件。能量单位均为保守下限口径。

| 项目 | 当前值 | 建议首轮值 | 目的 |
| --- | --- | --- | --- |
| 能量调节保留目标 | 没有独立目标，增补以进入回充门槛计算 | 新增 `20 J` | 让增补自然收敛，避免正常运行反复用到回充门槛 |
| 进入增补能量条件 | 无独立阶段门槛 | `30 J` | 确保达到基础功率后仍有可用余量 |
| 能量释放时间 | `0.5 s` | `0.25 s` | 富余能量更快转换为增补请求 |
| 输入增补上限 | `60 W` | 暂保留 `60 W` | 先解决释放速度与需求闭锁，暂不同时增加绝对峰值 |
| 输入预算上升斜率 | `600 W/s` | `1200 W/s` | 缩短增补建立时间；新实测目标口径与旧预算口径需统一转换 |
| 进入回充 | `15 J` | `10 J` | 减少过早回充，释放更多可用能量 |
| 退出回充 | `30 J` | `20 J` | 减少回充对连续自转的打断 |
| 硬底座 | `5 J` | 保留 `5 J` | 保留低能量最后约束 |
| 回充最大减让 / 目标时间 | `20 W / 1 s` | 保留 | 本次“激进”主要指积极用能，不指耗尽后继续强拉 |
| 回充退出确认 | `0.1 s` | 保留 | 避免低能量反复切换 |
| 保护预测窗口 | `0.3 s` | 保留 | 不靠缩短保护窗口换取峰值 |
| 结算延迟、能量余量、功率余量 | `0.1 s / 3 J / 5 W` | 保留 | 先用波形确认估算偏差，避免同时放松全部约束 |

正常增补在 `20 J` 附近趋于零，`15 J` 为提前退出增补边界，`10 J` 为回充进入边界，`5 J` 为预测硬底座；这些门槛职责不同。预测跌破硬底座时，无论实际下限是否已到 `10 J`，都必须立即转入恢复。

原有新裁判帧向上校正上限 `20 J/s` 暂保留。若实测发现估算下限长期明显低于裁判能量且持续触发恢复，先核对时间戳、计量位置和损耗计算，再针对有证据的误差优化观测器。

不能承诺一直高于裁判限功率：有限缓冲只能支持有限时长。粗略计算，在净超出 `40 W` 时消耗 `20 J` 仅需 `0.5 s`；实际还会受预测保护提前收回。这种持续时间应在波形中解释清楚。

## 7. 自转响应参数与持久化

| 参数 | 当前值 | 建议首轮值 |
| --- | --- | --- |
| 功率误差到目标变化率增益 | `40` | `80`，单位保持现有 `wz/(W·s)` |
| 自转上升斜率 | `400/s` | `1200/s` |
| 自转下降斜率 | `2000/s` | `2400/s` |
| 功率低通时间常数 | `0.1 s` | `0.05 s` |

上述数值是响应候选，不代表直接全部放大即可达标。先完成状态和门槛修正，再逐项调整，以实测功率、轮速跟踪及保护触发率决定保留值。

不继续盲目提高现有 `6000/8000` 目标；先根据当前轮速链路和实测电机可达范围校验。进入自转时使用受限斜坡建立目标，避免因初始化直接跳到大目标而触发长时间饱和。当前用户设定的电机 `Kp=0.75` 不作为本方案自动修改项。

当前功率和自转参数支持运行时调参与 Flash 恢复。后续不能只改编译默认值：启动遥测要能核对实际生效参数及其来源；若结构新增字段，明确版本迁移并验证旧记录不会覆盖新语义。不得为了迁移顺手清空其他无关参数。

| 5 | `chassis_energy_config.h`、预算配置与调参边界 | 增加能量目标和阶段门槛，采用积极释放候选参数 |
| 6 | 主机测试、固件构建、实车记录 | 验证先后顺序、低能量保护与真实功率利用率 |

本次已授权的小清理仅涉及 `chassis.c`：删除旧 `buffer_PID` 静态变量、`Buffer_pid_conf`、对应 `PIDInit` 调用及误导注释。保留所有实际使用的电机 PID、功率慢环和能量观测状态。

新增策略状态集中归功率策略/预算层维护，自转模块只消费最终目标与许可，不分别维护两套能量模式。正常自转策略主要针对 `CHASSIS_SPIN_MODE=1`；固定/正弦模式保持兼容，不在本次自动切换或改写其目标波形。

当前直供下使用已确认覆盖底盘输入的功率计；若计量安装点并非裁判约束的输入点，先核实差异，不能把负载侧数值当作输入功率。超级电容配置需区分输入能量与负载功率，并保留输入目标确认；本轮不将直供公式直接用于电容侧，也不宣称完成其性能验收。

## 9. 遥测与验收

### 9.1 需要能解释“为什么没用满”

复用现有 USB 遥测、波形查看与捕获功能，按需补充：阶段、`P_limit/P_base/P_set`、实测原值/滤波值、能量请求/实际获准增补、模型预算/修正/最终上限、缓冲原值/下限/预测值、自转目标、四轮目标/实测转速、到达确认时间和升速禁止原因。

原因至少区分：能量不足、未到基础功率、计量过期、轮速过期、跟踪未稳定、模型基础限流、电流硬限、快保护、制动、转速上限。增加字段时同步检查格式版本、接收端和行缓冲容量。

### 9.2 主机验证要求（后续实施时执行）

1. 基础阶段能量很高但功率未达标时，增补仍为零；有效功率稳定达标且能量足够后才开放增补。
2. 同一功率帧重复读取不满足到达确认；过期、乱序、时间跳变和非有限数禁止增补。
3. 增补打开后即使上一周期需求没有超限，也能在后续受限升速中建立真实需求；停止自转时不再请求额外功率。
4. `40/25/20 J` 能量点的目标计算、斜率、上限正确；保护预测逼近 `5 J` 时立即恢复，不等到实际下限变低。
5. 回充在 `10/20 J` 及确认时间上正确切换；健康普通基础运行不会因为“增补资格不足”被额外减功率。
6. 模型限流与执行器饱和被区分；功率偏低时不会一边长期限流，一边无限提高自转目标。IDLE→RUN、趋势放行超时和转速上限均覆盖。
7. 裁判限功率突降立即收缩目标/上限并重新确认；退出自转、急停、制动、失联时旧增补和增长状态不残留。
8. 生产策略、预算、自转和限流器联合测试，检查 `0.98` 换算、批准超限额度、真实电流输出以及慢环补偿不突破额度；不能只分别测试手写公式。
9. 回归原跟随/可选不跟转、自转固定/自适应/正弦、普通平移、参数恢复和直供/电容兼容构建。

优先扩展 `tests/chassis_motion`、`tests/chassis_spin`、`tests/chassis_buffer_budget`、`tests/chassis_power_budget`、`tests/chassis_power_module`、`tests/chassis_power_transient`、`tests/chassis_power_outer_loop`，并运行受接口变化影响的遥测/持久化测试。

### 9.3 实车评价标准

先对比同一组配置、同一电压和场地负载下的波形；记录实际生效参数，避免 Flash 旧值干扰。分别验证原地自转、平移叠加自转、低缓冲入场、限功率切换和数据失效。

- **随动**：车身重新跟转对齐，平移参考方向正确，进出自转不残留命令。
- **基础功率利用**：在机械可达、反馈有效且没有保护限制的持续自转下，建议以入场后 `1 s` 为初步响应目标；稳定 `1 s` 窗口平均功率达到限功率的 `95%～100%`。不能到达时必须有明确原因及相应波形，不靠提高显示预算通过验收。
- **增补顺序**：波形清楚显示基础到达确认在先、增补在后；低能量情况下无论到达与否都先保护。
- **增补效果**：能量充足且执行器可达时，实测功率跟随增补目标上升，允许短时超出基础限功率；建议以额外目标建立后 `300 ms` 内明显响应作为初测标准，同时核对超调与预测能量。
- **保护与连续性**：记录阶段切换次数、低能量回充时长、快保护触发次数、瞬时峰值及能量最小值；不允许通过连续硬保护抖动获得较高平均功率，也不以估算下限冒充裁判原始能量。

响应时间是待实测验证的设计目标；若机械能力不足，应报告能力边界并修订目标，不能宣称软件保证实际功率必然达到上限。
