# VOFA 功率与卡尔曼专用观测设计

日期：2026-11-13。状态：方案待用户确认，尚未修改固件。

## 用户目标

日常只选择两个观测用途：底盘功率与超级电容调参、底盘卡尔曼速度观测调参。用户通过 VOFA 自带功能直接导出 CSV，把原文件交给助手；助手读取、分析、提出有依据的参数修改、修改配置并验证，用户再烧录和复采。

不另做 CSV 导出器，不要求用户配置 CSV 字段、改列名、换算单位或转换文件。固件通道顺序及其解析定义由工程维护。

## 方案选择

1. 推荐：将观测用途与传输协议分开，增加功率/卡尔曼两个用途选项。两者使用现有 JustFloat 传输。旧模式 0/1 保留兼容，日常构建只需更改用途选项。
2. 直接重定义旧模式 0：配置项较少，但旧 19 路数据和接收设置失去兼容性，增加误读旧 CSV 的可能。
3. 一帧包含所有信息：无需切换，但无关数据挤占串口带宽，无法优先保证实际滤波输入及功率诊断信息。

推荐方案的日常入口在 `config/00_flash/board_flash_config.h`：新增 `BOARD_FLASH_1_VOFA_OBSERVATION_PROFILE`，`1` 表示功率/超电，`2` 表示卡尔曼，默认保留卡尔曼。传输继续使用 `VOFA_TELEMETRY_MODE=2`。直接 Make/CMake 构建支持同名去前缀选项。

两档使用 UART7、JustFloat、230400 / 8N1、20 ms 目标周期。用途切换通过重新构建烧录完成，不增加串口命令或遥控器切换逻辑。

## 固件共同约定

- 两档采用不同的新 schema 标识，旧 schema 2/3 的 CSV 不按新布局解释。
- 每帧固定布局，包含 schema、板端时钟、发送尝试序号、有效位、状态和所需数据年龄。32 位计数/时钟拆分高低 16 位，避免 float32 丢失整数精度。
- 新档的物理量采用明确单位：功率 W、能量 J、转子 rpm、平移速度 m/s、加速度 m/s²、角速度 rad/s。DJI 命令/反馈保留原始计数，不标成安培。四轮顺序为 LF/RF/LB/RB。
- 数据可用性由有效位判断；未知年龄用 -1，不把无效零值当成真实测量。
- 保留异步发送、忙时整帧跳过和帧尾冲突处理。每档最多 96 通道，静态检查验证最大帧能在 20 ms 内通过 UART；不提高现有波特率。
- 固定预算优先用于调参必需输入，删除跨用途的重复字段。通道数上限不能替代实际 CPU、无线吞吐和丢帧测试。
- 记录参数来源、配置版本及本档分析必需的实际生效参数；不能仅凭源码默认值判断 Flash/在线覆盖后的参数。无法追溯实际参数时，报告明确限制，不生成声称已验证的配置修改。

## 功率与超级电容档

主要复用 `ChassisPowerSnapshot_s`、`SuperCapSnapshot_s` 和裁判快照。

必须包含：

- 四轮目标/实测转速、限幅前请求、最终整数 CAN 电流命令、反馈电流、轮反馈年龄和在线/使能位。
- 控制周期引用的功率计功率、事件序号及年龄，最终命令提交状态。
- 限制前后模型功率、名义预算、目标功率、有效上限、快保护修正、慢环修正及滤波功率。
- 启动/限制/恢复状态、驱动/制动位、预测保护功率及缩放、超额能量和启动额度。
- 超电输入/输出功率、剩余比例、可供上限、输出状态、错误位、两路反馈年龄。
- 超电发送的输入功率目标、反馈回显目标、输入控制活动位和发送失败信息。目标相等不单独视作强命令确认。
- 裁判限额、缓冲能量、估计能量下界/预测值、恢复状态及数据年龄。

`ChassisPowerGetSnapshot()` 当前合并最近电机周期与最新策略，二者不一定同周期。新增观测需保留控制周期实际采用的预算/修正或其明确版本与时刻，并独立标识最新策略；不能将异步数据伪装成同时采样。

超电协议没有电容内部电压、电流和温度数值。本档不虚构这些测量，也不把负载侧功率计数值当作超电内部量。

## 卡尔曼档

面向当前 CAN2 DM-IMU 固定底盘路径，融合仍是只读观测。

保留轮速反算、目标运动、融合速度、源 IMU 四元数/去重力加速度/角速度及来源与年龄。移除本用途不需要的功率和云台编码器列，为下列信息留出带宽：

- 实际调用 `ChassisVelocityFusionUpdate()` 时的导航系轮速 X/Y、中心补偿后加速度 X/Y。
- 这次输入的中间样本时刻、调用时刻、输入可用性及滤波尝试序号。记录发生在调用之前，被滤波器拒绝时也保留真实输入。
- 更新/重置计数、配对跨度、源与接收间隔、融合/回退/拒绝状态。
- 当前生效的轮速方差、加速度方差、jerk 密度及残差门限。

发送时最新 IMU 与三点补偿的中间样本不能混用；配对轮速和加速度必须记录在同一导航系。后验融合速度减轮速不命名为校正前 innovation。

50 Hz 最新快照不能保证包含每次滤波更新。解析按滤波尝试序号去重、识别缺口和重置，只对连续记录分段重放；缺口后重新预热，不用插值冒充板上输入。若连续段不足，要求补采而非给出无依据的最优参数。

## 原始 CSV 到参数修改

1. 用户选用途、采集、用 VOFA 导出原始 CSV。无需手动列名映射。
2. 工程分析入口根据 schema、通道数和数据值识别新档及受支持的旧档。可处理 VOFA 时间列、默认通道名及重命名通道；不能唯一确定布局时停止并说明原因，不静默错配。
3. 首先检查时钟/序号、重启、重复、缺帧、有效率、数据年龄和实际配置，输出数据质量报告及可用区间。
4. 功率静态模型复用现有 `scripts/power_model_*` 的稳态筛选、样本去重、拟合与生产 C 对照。慢环、启动与超电参数根据响应分段提出候选，20 ms 快照不声称重现全部快速控制历史。
5. 卡尔曼复用生产 C 滤波器重放连续输入段，以静止噪声提供尺度依据，比较噪声、响应、拒绝与重置。避免同时随意缩放 Q/R 后把相同输出当成改善。
6. 助手报告具体参数旧值/新值、证据、适用工况和待验证项；数据充分时修改对应配置，运行相关测试与固件构建，自动创建仅包含本次修改的本地提交，不自动推送。
7. 用户烧录并按相同动作复采，用独立试次比较修改前后。参数拟合和验证不使用随机拆分的相邻数据行冒充独立试验。

仅靠该 CSV 可以做噪声与响应调试；真实车速精度/打滑误差需要独立速度或位移参考。IMU 安装旋转、芯片偏移和未知模块延迟不能由任意单段 CSV 唯一推断。第一次采集需要简短说明实际动作、地面/载荷、供电方式和 IMU 安装；这不是 CSV 字段配置。

## 验证与完成标准

- 两档分别验证通道顺序/单位/schema、异常数值、有效位、计数回绕、UART 忙、周期与帧尾冲突；旧格式回归保持通过。
- 验证功率档记录最终命令和正确计量来源，异步策略年龄/版本不会丢失。
- 验证卡尔曼档记录真实配对输入、拒绝输入、重复/缺口与重置；加入连续段生产 C 重放对照。
- 解析测试覆盖原始 VOFA CSV 表头、附加时间列、重命名列、缺列、混合 schema、重复/缺帧和错误数据。
- 两档主板配置均可构建；更新 VOFA 操作说明和两套精简采集动作表。
- 本次准备观测与分析流程，不在没有实车数据时宣称已经优化物理参数或完成硬件验证。
