# 单轮力控标定与高速记录工具设计

日期：2026-10-26。本文是待审核的工具设计，尚未实现工具；已有力控及标定文档见 [力控方案](../../chassis-direct-force.md) 和 [标定方法](../../chassis-force-calibration.md)。

## 目标与使用流程

用户后续可以通过 USB 连接 A 板，选择一个轮子，发送受限的正/负电流脉冲，记录原始反馈和实际发送电流，停机后导出数据。用于测量四轮输出轴转矩常数、验证接地牵引力，以及统计转速增长裕量。

工具独立封装，正常力控配置的三个必测组继续留 0，不能通过设置虚假标定值运行测试。工具不自动写回物理标定参数，不修改 `CHASSIS_FORCE_CALIBRATION_VALID`。

推荐流程：

1. 编译独立启用标定工具的台架固件，保持正常力控未标定锁定。
2. 固定夹具、准备重物或测力装置，打开独立中文标定页面并连接 USB。
3. 页面读取固件能力、轮序和实际限制；准备好遥控器中位、台架许可及辅助电机停机条件。
4. 选择 LF/RF/LB/RB、正负电流与脉冲时序，确认本次轮子和夹具后手动开始。
5. 板端检查条件后执行一次，自动撤力、记录尾段，冻结数据。
6. 页面读取状态、失败原因和数据，下载 CSV 与 JSON；下一次测量必须重新开始。

测试不是自动寻找机械极限，也不自动拉升电流直到打滑。重物、力臂和地面条件由用户填写到报告中。

## 接入方案选择

| 方案 | 使用方式 | 取舍 |
| --- | --- | --- |
| 推荐：复用 USB 服务，独立网页 | 使用已有 `start.cmd`，访问独立标定页面 | 无需新增串口库；有中文按钮、状态和导出，适合重复测量 |
| 调试器变量入口 | 在调试器中配置并触发测试 | 接入少，但会话、记录和批量导出需要更多手动操作 |
| 独立串口命令行程序 | 命令行发脉冲、接收数据 | 便于脚本化，但需要额外处理电脑串口环境 |

采用第一种。独立页面与现有仪表盘共用本地服务；同一串口同一时间由一个页面持有，页面明确提示先断开其他页面。现有 PID 整定、调参和普通遥测协议保留。

## 封装与依赖

| 位置 | 职责 |
| --- | --- |
| `modules/chassis_force_calibration/` | 纯 C 标定会话、脉冲状态机、独立限制、定长记录缓存和编码；不依赖 RTOS、CAN、USB 或 application |
| `modules/motor/DJImotor/dji_force_calibration.[ch]` | 绑定四个底盘电机；读取真实反馈、执行最终许可复查、记录发送结果，与正常力控互斥 |
| `modules/telemetry/force_calibration_protocol.[ch]` | 独立命令前缀、请求/回执、导出分块；解析在慢任务执行 |
| `application/board/board_force_calibration.[ch]` | 本车标定测试边界、轮序与适用构建组合，中文单位和说明 |
| `tools/usb-telemetry/force-calibration.html` | 独立中文操作页面，由已有本地服务提供 |
| `tools/usb-telemetry/force-calibration-*.js` | 串口会话、协议与记录解码、报告计算及 UI 分文件封装 |
| `tools/usb-telemetry/serve.cjs` | 在现有静态资源白名单中加入独立标定页面，继续仅监听本机 |
| `tests/force_calibration/` | 状态机、记录、协议与实际驱动集成测试 |

`application/chassis/chassis_force_app.c` 仅增加必要的状态/许可装配调用，`dji_force_adapter.c` 仅委托标定适配器，不放置命令解析、缓存管理或标定算法。继续使用现有唯一 CAN 打包和发送路径，不新增第二处电流发送。

## 构建和输出所有权

新增 `CHASSIS_FORCE_CALIBRATION_ENABLE`，默认 0，并通过共用 Make/CMake 选项清单传递。工具首版只支持 ONE_BOARD、OMNI_X、力控后端、台架固件和 USB 遥测开启的组合；不满足时构建失败并说明条件。

标定工具不依赖已经测好的 K_out、接地轮力和增长裕量。标定固件通过独立测试许可和独立限值运行，正常力控仍执行原有配置有效性检查；不存在回退到旧速度 PID 的路径。

显式启用标定工具的固件中，四轮只能接受标定状态机的受限输出，普通驾驶请求不参与混合输出。未进入标定会话或会话结束时四轮归零，恢复普通驾驶需要重新使用关闭标定工具的固件。这样不需要在未标定普通力控与直接电流测试之间做隐式切换。

现有 PID 自动整定和运行时参数写入/Flash 保存与标定会话互斥。开始标定前确认没有其他试调或待执行控制修改；正在标定时拒绝其他控制修改，避免改变滤波或控制条件。标定数据仅在 RAM 中，不自动写 Flash。

## 单轮电流测试

每次测试只能选一个轮子。输入为有符号 CAN 电流命令，页面同时显示换算值 `I_cmd_A = command × 20 / 16384`，并明确这是指令对应的转矩电流，反馈原始电流不直接标为 A。

首版提供一次性梯形脉冲：上升、保持、下降后归零，正负方向都支持；开始后参数不可修改，不自动循环、不自动换轮，也不在重新连接后恢复测试。

建议板级初始硬边界：

| 设置 | 初始值 | 含义 |
| --- | --- | --- |
| 最大电流命令幅值 | 1500 CAN 单位 | 沿用当前力控近零速调试上限；约 1.83 A 指令等效值 |
| 页面初始脉冲 | 300 CAN 单位 | 低幅试验起点，不保证能克服静摩擦 |
| 页面初始上升/保持/下降 | 50/100/50 ms | 一次总计 200 ms |
| 最大通电总时长 | 500 ms | 包括上升、保持、下降，不是长期堵转许可 |
| 转子转速上限 | 1000 rpm | 独立调试限值，不依赖正常力控标定是否有效 |
| 温度停止门槛 | 50 ℃ | 保守调试值，须核对实际温度反馈 |
| 心跳间隔/失效时限 | 50/150 ms | 页面周期保持会话，失效时电机任务主动归零 |
| 测试前静止确认 | 连续 100 ms，四轮绝对转速不超过 20 rpm | 每次测试重新确认，反馈过期则确认失效 |

以上是待实物复核的测试边界，不是新完成的物理标定。测试只能验证这个电流/速度范围，不能据此验收 15000 电流上限。以后扩大范围必须显式修改板级边界、重编译并重测。

反馈、许可和周期检查至少保持现有力控的严格程度：四轮反馈不超过 5 ms、电机周期不超过 5 ms、命令/操作源累计年龄不超过 10 ms。继续要求现有台架中位、急停链路及辅助电机停止证明。不能因为网页连接成功就取得电机许可。

标定使用独立电流及时长边界，并保留有效能源预算和负载侧功率监测；预算下降、功率超限、测量失效均撤销加载。测试预算沿用台架已配置的物理限制，不能因未标定而伪造正常力控已校准或绕过能源许可。增长裕量未测得前，不声称正常力控的动态功率包络已经验收。

## 状态与终止

状态为：未启用、等待准备、已准备、上升、保持、下降、尾段记录、数据冻结、异常终止。每次开始分配新的会话和测试编号，命令同时携带 USB 连接世代，旧连接或旧会话的指令被拒绝。

停止命令、USB 关闭或连接世代变化、心跳过期、中位/台架许可消失、急停、辅助电机未停止、反馈失联、超速、超温、功率超限、周期超限、CAN 提交失败、缓存将满，都会终止加载并归零。故障归零不等待下降斜率。

最终 CAN 入队前再次检查当前许可、世代、时长和四轮输出，确保只有所选轮可非零。邮箱等待期间出现停止必须影响这一帧；记录必须来自最终打包电流及真实提交结果，不把准备阶段的请求当作已发送电流。

异常会话不会自行恢复。清除故障原因后重新确认静止和许可，手动开始新测试。旧数据在用户明确清除或开始新测试前保持可导出。

## 高速记录

按所选轮真实 CAN 接收事件记录原始转速，并记录每次电机控制与最终发送事件。不能用 20 ms USB 遥测插值生成高速数据，也不能把重复读取同一反馈当作新采样。

记录至少包含：

- 数据格式、事件类型、测试编号、轮子编号。
- 单调微秒时间戳、反馈序号和接收时间戳。
- 原始转子 rpm、当次控制使用的滤波后 rpm、原始反馈电流、温度。
- 电流请求、四轮最终发送命令、CAN 提交结果。
- 实际控制周期和准备/最终复查/发送时间，当前许可及终止原因。

接收中断只做有界字段复制及缓存追加；不解析字符串、不格式化 CSV、不调用 USB 发送、不动态分配内存。RX 和电机事件的生产者同步需要短临界区，不能将任务级锁当作中断互斥。

缓存使用固定容量，默认记录内存预算不超过 64 KiB；实现时根据记录尺寸和事件频率给出页面可见的可记录时长上界，并检查最终链接 RAM 占用。一次加载加前后观察段必须在容量内；运行时容量不足则先撤力、冻结并标记不完整，不能覆盖、丢弃后仍宣称数据完整。仅记录选定轮反馈，四轮按独立测试依次获得结果。

正常结束后保留至少 100 ms 撤力尾段，再冻结数据；发生终止时尽可能保留已有数据和可用尾段，同时明确终止原因。样本间隔、序号间隙、缓存状态和未提交命令都在导出中可见，不对实际采样率做未经实测的保证。

只有输出已归零、记录被冻结后才导出。通过 USB 慢任务进行带索引和校验的分块读取；端点忙时保留原块，下次重试，成功提交后才前进。导出可以重试，USB 断连不会恢复驱动。

## 协议和电脑端

新增 `@FC1` 行前缀，与现有 CSV、`@T1`、`@A1/@A2` 区分。操作包括能力/状态查询、准备会话、开始单次脉冲、心跳、停止、读取冻结数据和清除记录；请求编号、会话、字段数量和边界都严格校验。

USB ISR 继续只将接收字节放入接收队列，慢任务解析并投递邮箱，电机任务消费测试命令。读取能力不取得输出许可，状态查询不隐式开始新测试；停止命令优先于普通排队命令。RX 溢出和协议世代变化撤销活动会话。

独立页面显示能力、真实限制、所选轮、指令单位、实际状态、终止原因和采样质量。测试开始需要用户点击；连接、重新连接、页面刷新和导入历史文件都不自动开始。真实硬件发送与演示/离线数据严格区分，离线文件只能分析。

CSV 提供事件原始记录和单位；JSON 同时包含构建模式、限制、滤波配置、测试条件、统计、采样缺口、异常原因及数据完整性。没有观察到的电压等字段标为未观测。

页面允许填写质量、力臂、拉力及方向，用于输出转矩/电流的测量表；不会只凭轮速自动声称测得 K_out 或接地轮力。转速包络分析由用户提供预测窗口 T 和额外裕量，计算未来窗口最大原始转速相对当次控制使用转速的增长；排除尾部不足窗口和缺口，数据不完整时禁止给出“标定完成”结论。计算结果是待复核候选，不自动回填源码或解除标定锁定。

## 验证与完成标准

先写行为测试，再实现对应功能：

- 单轮映射、正负方向、梯形脉冲、时长和电流边界；任何路径不允许第二个轮子非零。
- 中位/静止准备、每种终止条件、重连不恢复、旧会话拒绝、计时与序号回绕。
- 真实 DJI 驱动下四轮 PID 跳过、最终字节一致、邮箱等待期间停止、CAN 失败及其他电机保持停止。
- 高频 RX 与控制事件、容量边界、冻结一致性、分块校验、忙重试和断线后重读。
- 协议分片、越界/非数/多字段、命令溢出、停止优先和调参/Flash 互斥。
- 电脑端用已知记录独立核算时间、CSV、增长窗口、数据缺口及计算单位；网页模拟串口检查操作和下载，不能在测试中向真实板发送命令。
- Make/CMake 普通速控、普通力控与标定固件通过；非法宏组合明确失败；默认固件不编入标定缓存与驱动入口。
- 原有力控、驱动、USB、PID 整定和架构测试通过，更新使用说明及三项标定文档中的工具缺口。

交付包含源码、测试、可直接打开的中文工具页面、可复制的构建命令和测量步骤。本地软件验证不能替代首次上板的急停、限制、实际采样率、RAM/栈余量和夹具验证；不得通过自动烧录或实机加载来代替用户的后续测量。
