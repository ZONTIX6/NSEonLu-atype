# 底盘功率控制改进与模型重建

- 日期：2026-10-29
- 状态：待用户评审的实施设计，尚未修改控制代码或完成实机重标定。
- 基线：`f7f4398`；工作区已有 PID、自旋配置、力控注释和索引修改，另行保留。
- 用户目标：兼顾功率跟踪与运动性能，减少超功率、充分使用额度，使启动和旋转更平顺。
- 对象：`CHASSIS_CONTROL_MODE=0` 速度路径。承接[预测功控交付](../../predictive-power-speed.md)和[速度控制优化设计](2026-10-29-chassis-speed-control-improvement-design.md)。

## 1. 推荐路线及首批交付

采用“修正现役可靠性 → 建立可复现辨识 → 实测验证动态影子 → 分阶段接管”。首批是一个可独立验收的软件包：发送历史修正、真实生产参数回归、离线静态模型辨识与验证、数据契约和采集说明。无需假造硬件参数即可完成这批工作。

| 路线 | 优点 | 限制 | 选择 |
|---|---|---|---|
| 只重新拟合原六项系数 | 改动小，兼容现役接口 | 不解决命令/反馈混用、失败发送历史、动态延迟 | 用作对照 |
| 修正现役控制并重建数据与模型链 | 能逐项证明收益，复用保护和影子模块 | 真实新系数和接管需要实测数据 | 推荐 |
| 一次替换为完整 MPC/在线学习 | 可联合考虑运动和储能 | 当前数据、执行延迟和超电状态不支持可靠标定 | 不作为首批 |

首批不改变用户既有 PID、自旋配置；不修改力控或 F334，不烧录或启动电机。它是后续模型重标定的基础，不等于已经完成硬件性能提升。

## 3. 首批现役控制修正

### 3.1 发送结果与历史

区分三个量：本周期尝试提交的最终命令、最近成功入队命令、由反馈支持的电机状态。CAN 入队成功仍不等于电调已执行。

- 诊断继续保留实际打包字节和失败结果；失败不能伪装成发送了零命令。
- 失败提交不得更新供增长保护使用的成功历史。整组提交不完整时，不把整组认定为成功。
- 失败结果继续表示执行不确定；反馈不足期间保留最近成功提交历史，不能因为一次次失败尝试而累积新的电流增长额度。相反方向的历史不授予该方向增长额度。
- 恢复沿用原有反馈新鲜度、成功提交、停机/离线和配置版本门控，不新增未经验证的执行确认状态机。保留旧成功命令只维持发送节流语义，不证明电机继续执行该值；不能把“清零软件历史”当成电机已停。
- 快层、慢层和影子都继续使用各自明确的有效性信息，避免修正快层时放宽现有慢层门控。

先建立失败测试，再决定最小状态字段与接口修改。回归覆盖连续失败、失败后更大请求、换向、停止失败、恢复和时间回绕。默认成功通信路径应保持逐条最终 CAN 命令一致。

### 3.2 真实生产参数回归

速度路径和测试引用同一份纯数据定义；保持当前六项系数的数值，不复制成另一份易漂移的测试常量。测试覆盖实际使用范围的有限性、求根/量化后预算、低速非单调情况和无可行解。另保留旧参数作历史对照，不让旧样例替代生产配置回归。

功率计失联时负向修正逐步回零的问题列为后续策略对照项：它可能在缺少新测量时恢复已压低的需求。先复现并测量，不在首批同时改变恢复时间、外环增益和模型系数，以免无法归因。

## 4. 模型重建的输入契约

### 4.1 测量边界和单位

先明确功率计测的是底盘电调负载、超电输入还是其他总线边界。同一拟合任务只用一个边界；电池侧、负载侧和超电充放电功率不能混为一个标签。无法确认边界的数据只出诊断，不导出可安装参数。

显式区分：`command_raw`（最终整数 CAN 命令）、`current_feedback_raw`（反馈协议数值）、等效反馈电流与经独立核对的 A。速度统一注明转子 rpm 或 rad/s，`omega = rpm * 2*pi/60`。轮序为左前、右前、左后、右后，命令与反馈保持相同方向坐标。

官方 [C620 手册](https://cdn-hz.robomaster.com/robomasters/public/document/RoboMaster%20C620%20Brushless%20DC%20Motor%20Speed%20Controller%20V1.0.pdf)给出的控制命令范围 ±16384 对应转矩电流 ±20 A。它可以核对协议解释，不能证明本车反馈量、内部滤波与实测安培已经一致。

### 4.2 两级数据质量

**静态候选级：**允许导入现有 26 列标定 CSV 和已解码 CPC1。要求记录格式、计量边界、命令归一化、稳定段选择方式、帧龄和无法获知的字段。首版兼容系数拟合要求四轮在线并使能、功率计有效；否则分开报告，不能按四轮公共基线直接拟合。使用明确的稳态驱动片段，逐轮检查符号；任一轮制动或方向不确定的片段另列。稳定静止且命令为零的记录单独归为空载基线，不能因符号为零全部删除。使用功率计接收事件去重；旧格式只能以接收时刻近似去重时注明其限制。同一接收时刻不能臆造多次独立测量。

缺少提交和采样对齐证明的旧数据可以生成“仅分析、不可部署”的系数候选；不通过标定发布门槛。不能通过填入 `submitted=1` 或把接收时刻改名为采样时刻绕过检查。

**动态级：**需要逐轮原始反馈、反馈事件序号与时间、最终命令和提交结果、功率事件序号、功率边界和延迟说明；命令和反馈按时间事件保存。参数清单还需记录固件提交、工作区差异、编译配置、实际 Flash/PID 值、轮向、设备身份、电压、温度和实验编号。未知信息明确为空并使相应能力不可用，不用猜测值填满。

后续新增速度专用采集开关和版本化格式，复用已有快照/缓冲/传输；不依靠打开力控标定取得原始反馈。记录丢失计数、有界缓冲和非阻塞输出，保留旧解码器。此项单独验收，未完成前不声称默认固件能够输出全部动态字段。

## 5. 离线重建方法

### 5.1 第一阶段：稳态正向耗电

保留原六项命令模型作为基线，同时比较更易约束的五项模型：

```text
P_load = P0 + sum(R*i_j^2 + Km*max(0, i_j*omega_j)
                  + K1*abs(omega_j) + K2*omega_j^2)
P0, R, Km, K1, K2 >= 0
```

首批命令代理模型使用 `i_j=command_raw_j/1000`，明确它只是命令特征。反馈模型另用经说明标度的反馈电流，单独拟合和报告；不能把反馈系数放进接收命令的旧 `PowerModelPredict()`。`P0` 是同一测量边界的整车基线，只计一次。首版共享轮参数，只有独立激励证据充分时才增加逐轮参数。

在全驱动稳态域，命令代理五项模型可换算为旧六项格式：`k0=P0/4`、`k1=0`、`k2=K1*(2*pi/60)`、`k3=Km*(2*pi/60)`、`k4=R`、`k5=K2*(2*pi/60)^2`，`current_conversion=1000` 不变。这个换算不使旧接口获得制动分支能力。

离线采用特征缩放后的有界最小二乘；实现可用 [SciPy 的 lsq_linear](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.lsq_linear.html)，依赖版本写入报告。训练前检查设计矩阵秩、缩放后的条件数和各特征覆盖；秩不足时拒绝输出“已辨识模型”，允许明确降阶后重新训练。异常帧按数据质量规则排除，高功率真实样本不能只因残差大就删除。

按完整实验段/采集批次划分训练、校准和测试，不能随机打散相邻行造成泄漏。训练段拟合均值；校准段确定误差余量；测试段只验收，不回调系数或余量。小数据或单一自旋工况不足时，工具解释缺少哪类激励。

保护上界从验证域中的均值和保守余量形成；校准残差最大低估值加独立仪表/对齐误差是候选余量，仍属有限数据下的经验包络，不是全状态硬保证。测试域外、制动及边界未知时回退，不授予额外功率额度。

### 5.2 第二阶段：动态与制动

先辨识命令到反馈电流，再辨识局部转速响应和功率残差：

```text
i(t+dt) = exp(-dt/tau)*i(t) + (1-exp(-dt/tau))*gain*u(t-delay)
omega(t+dt) = omega(t) + dt*(a*i(t) - b*omega(t) + disturbance)
```

按实际 dt 和分段常值命令历史拟合，分别处理命令延迟、测量延迟、滤波与量化。当前局部速度模型不含独立负载观测，参数只在测得的地面、负载和速度域有效；不能从一条闭环自旋轨迹唯一辨识惯量、转矩常数和摩擦。

现有 `PPModel` 与 `PPPredict()` 可作为对照，但必须先解决调用端电流单位、变化命令历史和预测覆盖率。其上界当前保留完整初始电流再加响应增量，可能过于保守；后续用响应区间内的分段峰值构造上界，并验证凸性与覆盖，不能简单去掉余量来换取动力。

制动样本单独建模和验收。当前 `braking_valid=true` 仅允许相关输入进入预测，不代表再生分支已被识别。没有负载侧双向计量与电气能力证据时，不把负机械功率抵扣其他轮的耗电预算。

## 6. 控制结构的后续改进

数据与模型合格后，继续保留速度 PID 产生运动需求；预测分配处理真实瓦特预算下四轮候选电流，功率计外环只补偿缓慢残差，现有超限保护独立生效。

- 将平移、跟随旋转和自旋的误差映射到统一的四轮目标代价，按实测设定权重，避免只按单轮误差分配破坏车体方向。
- 对限功率后的最终命令增加速度环抗饱和跟踪；坐标、反转和前馈分量必须一致。当前 Ki=0，不预设必须增加积分。
- 用功率余量和可达加速度约束目标增长，分别比较启动响应、连续旋转波动和组合运动，避免在快限流、外环与自旋调节之间反复争夺。
- 平均预测、保护上界、裁判输入限制和超电负载额度分别报告；模型补偿不是新增电源能力。保留现有预算转换与发送失败门控。
- 超电能量规划需要电容容量、有效电压、输入响应和板上身份数据；不能从现有百分比反馈直接编造焦耳或宣布完整双储能 MPC 已完成。

这些属于后续独立实施包，不扩大首批到同时替换所有环路。

## 7. 工具产物与验收

首批离线命令行工具输出模型候选 JSON、数据质量/指标 JSON、可读报告和可选的六项 C 初始化片段。只有命令代理、静态全驱动域、单位明确的候选允许生成兼容片段；不自动覆盖固件常量或调用动态模型安装接口。输出包含原始文件 SHA-256、实验分组、剔除数量/原因、系数、标度、有效域、版本、基线对比以及是否具备发布证据。

| 类别 | 必须检查 |
|---|---|
| 算法与数据 | 已知合成参数恢复；含噪/异常输入；秩不足；NaN/Inf；错误单位；混合驱动/制动；重复/乱序/回绕；实验分组泄漏；不合格候选不能发布 |
| 生产一致性 | 兼容静态模型调用生产 C 预测与限流复核；动态后续调用现有生产 C 回放，不只比较 Python 自己生成的曲线 |
| 现役修正 | 连续发送失败不增加增长历史；成功路径输出一致；恢复、停机、失联、配置版本与量化边界 |
| 构建与回归 | 现役模型、瞬态、功率模块、外环、DJI 集成、预测影子；默认速度和影子固件构建 |
| 实机后续 | 同轨迹/负载/初始能量对照；功率峰值、超限积分能量、持续高需求时额度利用率、速度积分误差、启动 t90、自旋波动和限流解除恢复 |

模型验收按工况分别比较 RMSE、MAE、偏差和低估尾部，不能靠总体平均掩盖启动或制动退化。软件先要求新候选不劣于相同测试段的当前模型，并报告包络覆盖和保守损失。实际提升阈值、仪表允许误差和闭环非劣容差在实机测试前根据基线冻结，未填写时工具报告“未获得实机放行”，不能自行填为零误差。
