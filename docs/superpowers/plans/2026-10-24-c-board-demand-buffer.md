# A 板恢复 C 板需求触发缓冲增补

**Goal:** 取消自转必须先达到基础实测功率的门槛，使用 C 板需求触发增补规则，保留非零起转和功率保护。

**Architecture:** 自转复用普通预算分支的需求/能量/预测保护计算。专用状态只报告预算结果，不批准增补；CSV 和 Flash 格式保持兼容。

**Tech Stack:** C11 主机测试、STM32 ARM GCC、现有 Make。

## 规则与范围

- 预测未限流需求超过 `0.98 * P_limit` 且反馈、计量、能量连续有效时即可增补，不要求实测接近基础额度，不等待基础确认时间。
- 增补取需求余量、能量余量、预测保护余量和配置上限的最小值，使用普通预算的安全系数与斜率口径。50 W / 实测 42 W / 需求 60 W / 能量充足时，稳态目标为 65 W，名义预算为 65/0.98 W。
- 取消自转专用 30 J 准入、15 J 撤销、能力锁存及释放等待，统一采用通用能量回充和预测保护；保留 A 板当前通用保护参数，不复制 C 板旧参数数值。
- 非零起转、逐轮跟随、电流/速度硬边界、模型补偿和实测快保护保持生效。数据失效、制动、负计量不发布自转增补。
- 遥测阶段 1 表示基础预算，阶段 2 表示需求增补；基础确认和能力锁存兼容字段置零。
- 用户原有 chassis.c 和 spin_config.h 差异保留且不提交。
