# A 板整车控制、功率管理与超级电容融合实施方案

日期：2026-10-22

状态：软件实施与自动化验证已完成；硬件验收待执行。交付与验证记录见 [A板交付说明](../../atype-integration.md) 和 [验证报告](../../atype-validation.md)。

目标：参照已正常运行的 A 板整车工程，修改第一套工程，最终形成具备完整整车控制、功率管理、超级电容和调试能力的独立 A 板代码。

## 1. 工程身份与已确认要求

| 项目 | 第一套：修改与交付主体 | 第二套：实车适配参考 |
| --- | --- | --- |
| 目录 | `D:\nsezxb\NSEonLu - atype` | `D:\nsezxb\gimbal-fed infantry (1)\gimbal-fed infantry` |
| 检查时 Git HEAD | `a00dc8f` | `b4491b9` |

| 主要价值 | 功控、电容、功率计、缓冲能量管理、USB 遥测、在线调参、Flash 保存和 PID 自动整定 | 已运行的整车引脚、底盘、云台、发射、图传键鼠、热量控制和 MPU6500 适配 |

**实施方向固定为“照着第二套改第一套”。** 最终源码、文档和固件都在第一套目录内交付；第二套作为参考保留，不在其上反向进行融合。

已经确认的要求：

1. 目标是官方 RoboMaster A 型开发板，建立独立 A 板版本。
2. 第一套已启用、未启用的模块都纳入适配范围。
3. 第二套已运行的整车功能迁入第一套，包括云台、发射、图传键鼠和热量控制。
4. 超级电容采用第一套配套硬件及协议；电容、功率计与功控相关接线沿用第一套，其余接线沿用第二套。
5. 默认小陀螺保持第二套定速行为；第一套自适应、正弦模式作为可选功能保留。
6. 第一套配置宏保留其实际功能，按硬件、行为与覆盖关系逐项调整，不整份覆盖配置头文件。
7. 第一套当前未提交改动也是输入基线，不用历史提交覆盖它们。

“全部适配”不等于将全部互斥功能同时打开。第二套已运行的整车功能默认启用；其他可选模块保留配置入口和独立验证路径。缺少外接设备时，必须明确标注尚未实物验证。

## 2. 规划时的检查与基线

### 2.1 编译检查

两套工程已经使用本机 Arm GNU Toolchain 和 MinGW Make 独立编译成功，构建产物位于各自的 `build/plan_baseline`。

| 工程 | 编译配置 | 结果 |
| --- | --- | --- |
| 第一套 | `UART1_USE=0 USB_TELEMETRY_ENABLE=1 CHASSIS_POWER_CONTROL_STAGE=3` | 成功生成 ELF、HEX、BIN |
| 第二套 | 原工程默认配置 | 成功生成 ELF、HEX、BIN |

基线记录：第一套链接显示 Flash 使用 139972 B、RAM 使用 94136 B；第二套 `size` 显示 text 72888 B、data 1104 B、bss 72400 B。以上为不同构建的原始统计口径，不作为融合后资源预算的直接相加结果。

第二套出现 `gNormDiff` 可能未初始化、`MouseKeySet` 未使用等警告；第一套存在 newlib 系统调用桩相关链接警告。迁入代码时处理相关源码警告，不能通过降低第一套检查标准掩盖问题。

规划检查未烧录、未做实车验证，也未修改两套源码。基线编译只证明源工程在当前环境能构建。

### 2.2 必须解决的差异

| 差异 | 对融合的影响 |
| --- | --- |
| 第一套只有 F407 设备头文件和启动配置 | 仅修改芯片宏不足以编译 F427 |
| 第二套采用 X 型全向轮，轮序和解算符号不同 | 不能保留第一套运动学后只换引脚 |
| 第二套 USART1 为 DBUS | 第一套 `UART1_USE` 不能继续控制该串口的裁判/日志用途 |
| 第二套 README 与源码不一致 | 引脚和波特率以运行源码为基准，修正说明及 `.ioc` |
| 第二套 `.ioc` UART8 为 921600，源码为 115200 | 重新生成工程前必须统一为源码行为 |
| 两套 PWM 单位分别为秒/比例和毫秒/百分数 | 温控、蜂鸣器和舵机参数必须显式转换 |
| 第一套 BMI088 INS 与第二套 MPU6500 INS 的输出约定不同 | 保留第二套与实车匹配的轴向、角速度单位及 Pitch/Roll 映射 |
| 第一套电机任务 1 ms，第二套 2 ms | 以第二套周期为基准，核验第一套功控、超时和整定逻辑 |
| 两套超级电容协议不同 | 使用第一套 `0x061/0x051/0x052`，不迁入第二套旧协议 |
| 第一套仅默认启用底盘 | 恢复第二套完整整车调用链，并隔离底盘功控与其他电机 |
| 第一套存在源码参数覆盖及 Flash 保存 | 必须避免旧参数覆盖第二套实车 PID 和运动模式 |

### 3.3 整车默认行为

- 单板控制整车，X 型全向轮；轮序、方向、遥控映射和几何参数按第二套。
- 云台零位、限位、反馈反向和 PID 按第二套。包括 Yaw 对齐编码器值 350、Pitch 范围 -30～30、拨盘每发角度 45、每圈 8 发。
- 定速小陀螺沿用第二套 `wz=4000` 的命令尺度，不额外解释为新的物理单位。
- 默认控制任务周期：电机 2 ms、整车 5 ms、INS 1 ms、守护 10 ms、USB 遥测 20 ms。
- 实际控制时间使用测量的 `dt`；不能因周期改变而保留隐藏的固定 1 ms 假设。
- 第二套图传键鼠、云台跟随、角度跨圈处理和热量控制全部接入。

## 4. 第一套宏配置的迁移规则

### 4.1 通用原则

1. 保留功控、电容、能量管理、调试与可选功能的宏名和语义；仅对硬件绑定失效的宏做明确迁移。
2. 同名配置只保留一个默认值定义来源，其他文件引用该来源。例如 `POWER_METER_ENABLE` 不再在多个配置头中重复给默认值。
3. 支持构建覆盖的用户配置使用 `#ifndef` 默认值；协议常量、寄存器定义、单位常量不随意变成用户开关。
4. Make 和 CMake 的配置入口保持一致；不同配置使用独立构建目录，防止复用旧对象文件。
5. 保留宏必须检查它的实际使用位置，不能只保留定义而删除生效路径。
6. 单位变化仅在适配边界转换，不默默改变同名宏的单位。
7. 以第一套当前工作区数值为功控初始基线；改变的值必须记录原因。

### 4.3 串口配置接口

板级配置集中表达设备用途，应用层不再散落硬编码串口句柄。新增或统一的配置入口如下：

| 配置入口 | 默认值或含义 |
| --- | --- |
| `REFEREE_ENABLE` | 1，裁判功能独立启用 |
| `BOARD_REMOTE_UART` | `&huart1` |
| `BOARD_VISION_UART` | `&huart3` |
| `BOARD_VTX_UART` | `&huart8` |
| `BOARD_REFEREE_UART` | `&huart6` |
| `BOARD_SUPERCAP_CAN` | `&hcan1` |
| `BOARD_POWER_METER_CAN` | `&hcan1` |
| `LOG_OUTPUT` | 0=关闭、1=RTT、2=串口、3=两者；默认 1 |
| `BOARD_LOG_UART` | 可选日志使用 `&huart2`，不改变其他设备串口 |

串口日志保留队列化、非阻塞输出，USART2 TX 使用中断发送，避免与图传 DMA 争用。默认没有串口日志接线要求。

旧构建命令若显式传入 `UART1_USE`，给出编译错误及新配置入口说明，不静默映射到 DBUS。所有旧条件编译引用、测试和文档一起迁移。

### 4.4 参数覆盖顺序

必须区分“编译时功能选择”和“运行时可调参数”。

**编译时配置：** 对允许覆盖的配置，Make/CMake 传入的定义优先于头文件默认值；配置值必须经过范围和互斥检查。

**启动时参数：**

1. 当前 A 板存储版本有效、参数组模式匹配且范围校验通过的 Flash 参数。
2. `tuning_overrides.h` 中已启用、模式匹配且校验通过的源码覆盖参数。
3. 普通源码初始化值。

**运行时参数：** 网页请求经板端确认后生效。未保存的修改不因断电自动保留；保存及源码同步维持第一套原有流程。

首次融合禁用旧 PID 源码覆盖，并使用新的存储版本标识拒绝旧配置。不得仅修改底盘 `.Kp` 后让旧覆盖文件重新写回 0.75。

交付宏迁移对照表需列出：宏名、旧值、新值、原位置、最终位置、单位、修改原因、生效条件及验证用例。现有 `docs/configuration-guide.md` 和 `docs/configuration-index.md` 同步更新。

### 7.3 实车验收顺序

1. **基础启动：** MCU 识别、复位、时钟、RTT、GPIO、电源输出初态和 USB 枚举正常。
2. **IMU：** 校准、温度、姿态轴向、静止漂移及云台反馈方向符合第二套。
3. **通信：** 遥控、图传、视觉、裁判、电容、功率计和九电机均能接收反馈；记录帧率和超时状态。
4. **架空逐轮：** 核对轮位、ID、方向、参考值、反馈值与实际电流，再验证组合运动。
5. **整车行为回归：** 平移、跟随、定速旋转、云台与发射相关控制按照第二套映射工作。
6. **功控分级：** 从低功率限制开始，验证增载、启动、电容供电、缓冲消耗、恢复及异常反馈。
7. **调试功能：** USB 连续采样、在线修改、Flash 保存重启、自动整定及退出恢复。
8. **持续运行：** 记录控制任务耗时、栈余量、CAN/UART 丢帧及 USB 状态，不出现持续超时、栈溢出或重复输出。

每一项记录固件版本、有效宏配置、接线与测试结果。只有完成实物测试的条目才标记“实车通过”；无硬件时交付软件验证结果和未执行清单，不将编译通过描述为整车验收完成。

## 8. 风险与具体处理

| 风险 | 处理 |
| --- | --- |
| 整份复制第二套覆盖第一套功控扩展 | 按模块清单合并，保留第一套功控/遥测主链，检查其注册和任务调用 |

| 多电机功能加入后旧限流误伤其他电机 | 通过明确四轮注册和分组输出测试隔离功控范围 |
| 任务周期改变破坏超时或积分 | 保持第二套周期，核对实际 `dt`、时间窗和快照新鲜度，补充抖动测试 |
| 裁判布局差异导致热量字段错位 | 按命令与载荷长度显式映射，增加功率/热量联合测试 |
| 保存或整定时其他执行机构仍在运行 | 扩展到整车级互斥状态，不沿用仅底盘停止的判定 |
| 全量适配中未使用代码被遗漏 | 独立配置编译并链接对应路径，维护模块验证表 |
| 旧文档和注释掩盖实际行为 | 源码与实测为依据，文档同步更新，标出尚未完成的物理验证 |
