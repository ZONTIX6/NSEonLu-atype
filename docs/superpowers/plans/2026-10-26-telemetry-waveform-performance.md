# 实时遥测波形流畅度优化

**目标：** 在约 30000 条历史样本下，让可见波形跟随浏览器动画帧平滑刷新，降低绘图耗时，保留真实峰谷、断点、悬停读数和 CSV。

**范围：** `tools/usb-telemetry` 的 Canvas 波形及调度；保持页面布局和固件协议。

- [x] 先用 Node 绘图回归测试复现全历史扫描和密集路径问题。对可见时间窗口二分定位，并按每个像素列保留首尾与峰谷；遇到无效值、分段及超过 500 ms 间隔保留断线。
- [x] 将波形刷新与原有数值面板刷新分开；动画帧最多约 60 Hz，使用 IntersectionObserver 跳过视口外图表，弹窗打开时只刷新大图，暂停时仅在交互或尺寸变化后重画。
- [x] 合并鼠标悬停更新到动画帧，避免高频鼠标事件重复操作 DOM。
- [x] 运行网页 Node 回归及浏览器悬停、缩放、选择、历史回看、IMU/速度测试；同一 Edge、1440×1050、约 30000 条演示样本比较前后耗时和刷新次数。
- [x] 代码审查后只提交本次任务文件，报告提交编号和实物性能验证限制。

**优化前基准：** 单张功率图绘制中位数约 1.10 ms，P95 约 1.30 ms；1.50 s 内全部 7 张图各刷新 29 次（约 19 Hz），绘制合计约 402 ms。测量是本机浏览器模拟数据，不代表板端硬件验收。

## 验证结果

- `node --test tools/usb-telemetry/tests/*.test.cjs tools/waveform-viewer/tests/core.test.cjs`：81/81 通过。
- 绘图测试先在旧代码上复现：501 个可见样本需要读取 61503 次时间戳，126 px 绘图区绘制 10001 点；修复后二分窗口、像素峰谷、断点及重复时间戳测试通过。
- 浏览器 `browser-check`、`chart-check`、`zoom-check`、`selection-check`、`history-check`、`imu-check`、`velocity-check`、`spin-power-check`、`spin-limits-check`、`tuning-check`、`persistence-check`、`autotune-v2-check`、`performance-check` 共 13 组通过。检查截图包含桌面和 320～375 px 窄屏。
- 审查发现原节流方式在 75 Hz 屏幕只能绘制 37.5 fps，已用失败测试复现并修复。合成动画帧驱动真实应用循环，60/75/90/120/144/240 Hz 屏幕分别约 60/60/60.5/60/60/60 fps。
- 最终同场景基准：1.50 s 内可见功率图绘制 90 次（约 60 Hz），屏幕外图表不重绘，绘图合计约 179 ms，比原约 402 ms 少约 55%。单图微基准中位数约 1.30 ms、P95 约 2.30 ms；主要收益来自避免无用重绘和提高可见图刷新频率，不能据此声称每次绘制都更快。
- 额外运行旧 A1 `autotune-check` 时等待模拟板端响应超时；将 `app.js`、`charts.js` 都替换为 Git 基线版本后同样超时，此问题与本次波形优化无关。
- 只使用本地模拟数据和模拟串口，没有连接或烧录 A 板；实物 USB 数据流性能仍需实际设备确认。无新增运行依赖。
