## 阶段 A：行为与依赖基线

- 新增阶段 0/3 输入流夹具 `tests/dji_chassis_power_rtt/baseline-stage*.csv`，固定低速预备、启动、驱动、反转/制动、持续超功率、恢复、失联、整定退出的四轮整数命令、控制版本、预算和瞬态状态。输入流按 2 ms 连续推进，共 196 周期，断言真实进入 STARTUP、负向学习与 RECOVERY，且四轮需求受到限流。原有 RTT 行与超电命令的逐字节断言继续保留。
- 复用已有九电机乱序、非底盘隔离、整定退出、快照交错和最终整数输出测试；未删除已有场景。
- 新增 `tests/architecture/test_layers.py`，按 Make 实际 include 搜索顺序解析头文件，检查模块反向依赖、纯算法硬件依赖、公共功控头与板级访问；检查器自身有相对路径、尖括号、RTOS、CAN/UART、直接寄存器、歧义和注释过滤测试。`baseline.json` 明确记录 57 处既有违规，新增违规或未移除的过期记录均使检查失败；最终验收须使用 `--strict`。
- 基线验证：四组指定主机测试、阶段 0/3 DJI 测试、架构检查通过。完整 `validate-atype.ps1 -FirmwareMatrix -CMake` 全部通过（主机、portable、Python、Node、16 个 Make 配置、3 个 CMake profile）。日志位于 `build/validation/`，日志目录为可重建产物。

## 阶段 C：功控模块与 DJI 适配

- 电机驱动通过注册的组处理接口接入适配器。四轮显式绑定与 °/s→rpm 转换留在适配器；最终门控、int16 量化、组帧和 CAN 提交仍为驱动唯一输出路径。仅最终提交记录发布快环快照，安全零输出与发送失败均如实记录。
- 完整配置请求先校验再整组复制，慢/快环各自拥有配置和状态；配置版本随控制快照切换。非法配置、版本倒退、混用旧控制版本均有测试。
- 新增独立模块测试，覆盖 32 个阶段/直供或超容/功率计/缓冲开关组合。原阶段 0/3 输入流夹具未改动；阶段 0..3、无功率计、九电机隔离、整定退出、RTT、Flash 与 USB 回归保留。
- 两项独立审查指出的配置校验和最终打包竞态已以失败测试复现并修正；策略只读取上一完整快环诊断。捕获可选配置的缺失时钟声明已修正。
- 指定 10 组主机测试、四阶段及无功率计测试通过；完整矩阵再次通过，当前日志共 77 条成功（包含已新增 SPI 主机测试），16 个 Make 配置和 3 个 CMake profile 均通过。

- 删除迁移完成的 `chassis_power_link.*` 与过时旧功控文档，原命令/裁判集成测试已转到新策略接口。无长期兼容功控 API。

## 阶段 D：SPI、MPU 与加热器

- SPI 增加有结果的完整事务、SPI1/SPI5 所有权、GPIO/无片选模式和头文件保护；忙立即返回，使用原始 DWT 周期计数限制等待，未初始化时钟拒绝事务。成功、错误、超时和旧异步结束均释放总线与片选，回调只通知活动所有者一次。
- MPU 通过应用配置注册 SPI；14 字节样本与寄存器地址在同一事务读取。新增中立样本，保留 ±8g/1000dps 单位及有符号温度。初始化/采样失败向上传递。
- 加热器接受注入的 PWM 配置，公开 duty 为 0..1；PID 百分比只在温控边界转换。板级 `board_devices` 在 BSP 后装配 SPI5/PF6、TIM3 CH2/PB5，不重复注册；失败加热置零。
- PWM 实际 BSP 测试发现并修正 ARR 周期计数差一及占空比使用 ARR 而非计数总数的问题：100 μs/1 MHz 为 ARR=99，50% 为 CCR=50；修正 APB2 时钟分频字段，HAL 启动失败返回 NULL 并清零。
- 验证：SPI、PWM、MPU、A 板主机测试与主固件构建通过。架构既有违规从 57 减至 47；减少的 10 项均为迁出的 MPU/加热硬件访问。硬件时序未实测。

## 阶段 E：INS 服务与应用桥接

- 姿态采集、6000 次校准、15 s 超时偏置回退、EKF 和温控迁入 `ins_service`，通过类型正确的样本/加热回调注入；服务不包含设备硬件头或视觉头。
- 保留 `INS_Init/INS_Task/INSIsHealthy`，返回独立固定地址的姿态对象；新增完整快照。失败样本和超过 10 ms 的样本不进入 EKF、不刷新时间、加热为零；校准中途 SPI 失败不被超时回退掩盖，重复初始化不重复注册或启动 EKF。
- 板级装配在原启动位置注册设备和服务。视觉姿态更新移到应用 `ins_bridge`；单板/云台板每个原 1 ms 任务周期仍发送视觉帧，失效姿态不更新；底盘板不发送视觉。
- 移除旧 `mpu6500.c/.h` 姿态实现和无调用方的低层公开包装；Make 显式使用服务源，CMake 自动收集新服务并继续排除原历史 INS/BMI 实现。公共头的 X/Y/Z 宏改为带前缀枚举，避免头文件去硬件依赖后污染 CMSIS 声明。
- 验证：INS 服务、三种板角色桥接、A 板回归通过；Make 与 CMake 主配置构建通过，INS/EKF 符号各一份；架构检查无新增违规。硬件 1 ms 耗时未实测。

## 阶段 F：图传与 OLED

- 图传模块只使用 USART/Daemon 与协议状态，移除内部 DMA 重配；BSP 验证 normal/direct/byte 接收模式，不兼容配置拒绝初始化。现有 `.ioc` 与 `Src/usart.c` 的 USART3_RX 本来已是正确模式，保留配置。增加空参数、重复初始化、注册返回前 IRQ、失联重启与恢复测试。
- OLED 通过注入的 SPI/GPIO 或 IIC BSP 后端工作，不再包含硬编码句柄或 HAL 外设访问；SPI 明确无 CS，I²C 7 位地址只由 BSP 左移。旧入口要求先注册，不隐式装配设备；失败停止本帧并报告诊断。
- PA6/ADC1 IN6 模拟按键迁到板级适配器，显示只接收有效键。ADC 启动/轮询/状态/停止失败均不触发中键。
- OLED 迁移前实际输出记录为固定夹具，迁移后 SPI 2128 字节、I²C 2124 字节全部一致（初始化、清屏、绘图）。图传/OLED/按键主机测试、两种可选后端固件构建通过。架构违规由 47 减至 28。
