# DM-IMU-L1 接入主板 CAN2

DM-IMU-L1 替代原来的第二块 A 板，刚性固定在底盘，直接通过 CAN2 向主板提供姿态、加速度和角速度。主板继续进行轮速与 IMU 的卡尔曼**速度观测**，结果供遥测和对照；电机控制、PID、功控、随动、自旋及原安全门控不消费这份融合结果。本地云台 IMU 继续承担原有职责。

## 1. 接线与模块设置

断电后将模块 `CAN_H` 接主板 CAN2 的 `CAN_H`，`CAN_L` 接 `CAN_L`，参考地连接。使用板卡 CAN 收发器后的总线接口，不接 MCU 的 CAN RX/TX 逻辑引脚。针序按实物丝印和对应版本手册核对；总线两端配置终端电阻，已有两端终端时不因加节点再加第三只。

本地 DM 手册标注模块供电 5～28 V，但随附固件说明对 1.0.3.6 版本温控另有限制：仅 5～6 V 开启温控。先核对手中模块硬件/固件版本、供电与温控设置；CAN 接口上的电源针不能未经核对直接接入模块。主板代码不会替模块设置供电或温控。

使用厂商上位机配置并保存，重新上电后确认生效：

| 项目 | 本工程要求 |
| --- | --- |
| CAN 波特率 | 1 Mbps，与主板 CAN2 一致 |
| 上报方式 | 主动上报，100 Hz |
| 上报内容 | 加速度、角速度、四元数；Euler 可以保留 |
| `MST_ID` | 与主板 `DM_IMU_CAN_RX_ID` 一致，项目示例为 `0x11` |
| `CAN_ID` | 模块命令地址，示例 `0x01`；与 `MST_ID` 是不同参数 |

`0x01/0x11` 是厂商示例及本工程配置值，不能视为已核实的模块出厂值。主板采用**被动接收**，不发送自动配置、查询或校准命令；仅接线而未启用主动上报时不会产生有效输入。核对同一 CAN2 上没有其他设备使用模块上报 ID。

## 2. 主板配置与构建

默认入口是 [board_flash_config.h](../config/00_flash/board_flash_config.h) 的板 1：

- `CHASSIS_IMU_CAN_RX_ENABLE=1`、`CHASSIS_VELOCITY_FUSION_ENABLE=1`、`CHASSIS_REMOTE_IMU_FUSION_ENABLE=1`：接收并运行只读融合观测。
- `CHASSIS_VELOCITY_FUSION_CALIBRATED=0`：关闭本地云台标定融合路径，不表示 DM 融合关闭。

[dm_imu_config.h](../config/92_imu/dm_imu_config.h) 默认 `DM_IMU_CAN_BUS=2`、`DM_IMU_CAN_RX_ID=0x11`、`DM_IMU_GRAVITY_MPS2=9.80665f`。修改接收 ID 后必须同步模块的 `MST_ID`。安装旋转、芯片偏移及滤波噪声仍在 [chassis_remote_imu_config.h](../config/30_velocity_observation/chassis_remote_imu_config.h)，内部坐标前/左/上，偏移单位 m；默认单位旋转和零偏移仅是假定安装，`CONFIG_VERIFIED=0` 保留未标定身份。

```powershell
# 核对 DM 接收、融合开关、输出目录和 VOFA 协议
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-board.ps1 -Action Show -Board 1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-board.ps1 -Action Build -Board 1
# 构建成功且下载器连接主板后执行
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-board.ps1 -Action Flash -Board 1
```

DM 方案只烧录主板，不构建第二块 A 板。模块参数由厂商上位机设置，保存配置截图。直接 Make/CMake 不读取板卡预设，使用时显式传上述接收/融合开关，并选择与 VOFA+ 匹配的遥测模式。关闭 `CHASSIS_REMOTE_IMU_FUSION_ENABLE` 可保留同样 DM 输入和遥测，作为轮速基线对照。

旧第二板预设、CAN 发送与接收协议已删除，外部 CAN IMU 接收就是 DM 路径，不再提供来源切换。构建脚本只支持主板 `1`；本地 `IMU_CAPTURE_ONLY` UART 诊断及可选云台标定融合仍保留。旧实现只作[历史验证记录](superpowers/verification/2026-11-12-remote-imu-fusion.md)。

## 3. 数据转换与时间边界

接收器仅接受长度正确的完整组，类型顺序为 `1（加速度）→2（角速度）→[3（Euler，可选）]→4（四元数）`，从首片起最多 10 ms。缺片、错序、重复片、非法四元数或过期组不刷新已发布样本。这是当前适配器约定；手册未承诺主动帧的组内顺序，首次接入需抓包核对。协议没有跨帧源序号，严格顺序和期限不能证明各字段在模块内部同步采样。

相邻已发布完整组的**首片接收时刻间隔至少 18 ms**；这是首片时间门槛，不是完成时刻间隔。名义 100 Hz 输入约发布 50 Hz，18 ms 门槛为约 ±1 ms 接收抖动留出余量，不保证固定输出频率。三点中心补偿仍要求每侧间隔 15～30 ms，掉线或异常间隔会清历史并重新预热，不能通过降低模块上报频率随意改变这一条件。

模块加速度含重力，按厂商 CAN 编码范围 ±235.2 m/s² 解包；角速度按 ±34.88 rad/s 解包。16 位字段使用无符号线性映射，不按有符号补码或 g/°/s 再次换算。四元数按 Hamilton `[w,x,y,z]` 解包，修正厂商示例 w 分量高位掩码的 `0xF8` 为 `0xFC`。按传感器→导航系解释四元数，将加速度旋转到导航系后减去 `[0,0,g]`，再交给原固定安装与中心偏移补偿。**四元数方向是当前适配假设，必须做水平和倾斜静止实测核对。** 不对 Euler 角重复解算姿态。

DM 协议没有模块采样时间戳或样本序号。主板以首片接收时刻估计样本时间，由接收事件生成序号，源年龄字段设为 0；不会在读取快照时生成新测量。该时间不包含模块内部滤波、采样与 CAN 排队延迟，不能声称硬件同步或真实端到端年龄已知。停流后按已知年龄上限 60 ms 判无效；四轮有效时回退轮速，四轮失效时整体估计无效。

## 4. VOFA 与首次上板核对

VOFA+ 使用主板 UART7 一个接收通道；按构建中 `VOFA_TELEMETRY_MODE` 选择协议：`1` 为 FireWater，`2` 为完整观测 JustFloat。两者使用相同 schema 3 的 72 列，保存完整 `I0`～`I71`，不要沿用模式 `0` 的 19 路列名。

| 检查项 | DM 模式含义 |
| --- | --- |
| `I0=3`、`I63=0`、`I64=2` | schema 3、主板记录、外部 CAN IMU；`I64=2` 不是 CAN 总线编号 |
| `I5` bit 19（524288） | DM 来源标识；未启用外部接收时为 0，本位不证明已收到数据 |
| bit 4 | 当前 IMU 输入有效 |
| bit 16/17/18 | 远端融合开启 / 时间为接收端估计 / 配置声明已实测审核；默认 bit 18=0 |
| `I6=9` 且 bit 3=1 | 本行有效融合；仅有数值或来源位不等于进入融合 |
| `I34/I35` | 主板接收端生成的样本序号高/低 16 位 |
| `I66=0`、`I67/I68` | 源年龄未知时使用 0；时间是主板接收端估计，不是模块源时钟 |
| `I33`、`I65`、`I69` | 首片以来年龄下界、完整组以来年龄、组内首末片跨度，均为 ms |

首次测试先使动力零输出、模块固定，水平静止检查输入有效；再分别绕 X/Y 缓慢倾斜并静止，确认 `I40`～`I42` 去重力加速度接近零，角速度方向与实际转动一致。若倾斜时出现持续接近重力的残差，先查四元数方向、轴向和单位，不用噪声参数掩盖。之后核对实际安装旋转和芯片相对底盘中心偏移。

在保持 CAN2 主干和终端的条件下做模块断流/恢复测试，确认超龄后 bit 4/3 清零、四轮有效则回轮速，恢复后预热。再按 [实车测试与验收手册](kalman-chassis-test-and-acceptance.md) 逐项进行轮序、运动、独立速度参考、延迟和资源检查。软件测试与构建通过不等于模块方向、安装参数或融合精度已在实车通过。
