# 底盘直接力控：标定方法与记录表

整理日期：2026-10-26。对应 [力控方案与启用步骤](chassis-direct-force.md)。当前仅整理测量办法，没有实测结果；三个必测组继续为 0，标定有效标志保持 0。文中数字示例不得作为本车参数回填。

## 测量范围与准备

| 参数 | 结果数量 | 单位 | 作用 |
| --- | --- | --- | --- |
| `wheel[w].k_out_nm_a` | 四轮各一个 | N·m/A | 将输出轴转矩与电流关联，包含减速器影响 |
| `wheel[w].force_limit_n` | 四轮各一个 | N | 在指定地面、载荷下验证过的保守轮缘驱动力 |
| `speed_prediction_rpm` | 四轮工况的共同包络，一个 | 转子 rpm | 覆盖控制期间转速可能增长的裕量，用于功率约束 |

固定轮序：`wheel[0]` 左前 LF/CAN1 ID 1，`[1]` 右前 RF/ID 4，`[2]` 左后 LB/ID 2，`[3]` 右后 RB/ID 3。

原工程没有足够数据推出这三组结果。功率模型系数不是转矩常数，架空轮速不能证明接地驱动力；电流、轮力和预测裕量也不能互相替代。

测量前需要准备固定夹具、长度量具、已知质量的重物或测力装置，以及时间同步的数据记录。已提供默认关闭的独立单轮电流状态机、板端原始事件记录和仪表盘“力控标定”标签。其他三轮电流始终为 0；正常力控的三组实测参数继续为 0，不能伪填参数解锁。

## 标定工具使用

1. 在独立构建目录编译台架固件，保持普通标定有效标志为 0：

   ```powershell
   make -j4 PROFILE=atype-bench BUILD_DIR=build/fc-tool-bench CHASSIS_CONTROL_MODE=1 CHASSIS_FORCE_SPIN_MODE=0 CHASSIS_FORCE_CALIBRATION_ENABLE=1 CHASSIS_FORCE_CALIBRATION_VALID=0 POWER_METER_ENABLE=1 USB_TELEMETRY_ENABLE=1
   ```

   默认直供。已验证的电容构建在此命令追加 `CHASSIS_POWER_SOURCE_MODE=1 CHASSIS_BUFFER_POWER_ENABLE=1` 并改用 `BUILD_DIR=build/fc-tool-cap`。要求 ONE_BOARD、OMNI_X、功率阶段 3、台架模式、USB 和功率计同时启用。此文不自动烧录。

2. 运行 `node tools/usb-telemetry/serve.cjs`，用 Edge/Chrome 打开 [仪表盘标定标签](http://127.0.0.1:4173/#force-calibration)，只使用顶部公共连接栏。连接只查询能力与状态。
3. 核对夹具、四轮电调 ID 和方向。遥控器按现有台架流程保持中位，确认安全许可、辅助电机连续静止、四轮新鲜反馈及有效负载功率。辅助电机、裁判/电容确认或功率计条件不足时先排除故障，不关闭保护。
4. 每次选择一个 LF/RF/LB/RB，初始电流命令 300、上升/保持/下降 50/100/50 ms。点击“手动准备”，等待静止确认后核对本次轮子及夹具，再点击一次开始。最小电流、短脉冲先确认方向与归零。
5. 随时使用公共“立即停止”。切出标定标签会请求停止并等待后续状态确认成功提交零电流；超时仍显示未确认并锁定其他控制。重新连接、刷新、导入和返回标签均不恢复加载。
6. 板端保留 50 ms 预记录与 100 ms 尾段，冻结且成功提交零电流后手动读取。1280 × 48 B 缓存位于 CCM，实际记录时长取决于 RX 与控制事件频率；容量不足会撤力并标记不完整。网页实时状态查询不是高速采样。
7. 下载原始 CSV/JSON；填写实测电压、源码提交号、夹具条件、T 和额外裕量。未知值留空，报告保存为 null。不完整、缺口或 synthetic 数据仅保存证据，不能产生完成结论。转矩表使用包含容器/挂件的总质量与 m 单位力臂；不凭轮速推算转矩常数。导出不写参数或 Flash。

板级初始限值为电流幅值 1500 CAN 单位、通电总时长 500 ms、转子转速低于 1000 rpm、温度低于 50 ℃、四轮低于等于 20 rpm 连续静止 100 ms。心跳每 50 ms、150 ms 失效。仅覆盖低幅短时测试；器材稳定时间不够时先改进测量装置，不能延长加载绕过边界。限值不是物理验收结果。

`I_cmd_A = command × 20 / 16384` 是指令等效值，反馈原始电流标度仍需上板核对。成功提交只证明进入 CAN 发送邮箱，不代表电调已接收或执行。软件验证与首次上板项目见 [验证记录](superpowers/verification/2026-10-26-chassis-force-calibration-tools.md)。

## 1. 输出轴转矩常数：`k_out_nm_a`

### 有测力装置时

1. 固定电机壳体，在减速器输出轴安装长度已知的力臂。`L` 为轴心到力作用线的垂直距离，单位 m。
2. 力臂末端接测力装置，力与力臂垂直，使用夹具承力。扣除力臂自重及装置偏置。
3. 多个受限电流档短时加载，正反方向分别测，多次重复；记录实际发送的 CAN 指令与对应的力，避免长期堵转。
4. 用多个点拟合转矩对等效电流的斜率，检查偏置、静摩擦、方向差异与重复性，不能只用一个静止平衡点。

```text
I_cmd_A = 实际发送的 CAN 电流指令 × 20 / 16384
tau_out = F × L
tau_out ≈ k_out × I_cmd_A + b
```

这里按当前控制器模型使用指令对应的等效转矩电流，测试时须核实电调跟随和反馈量纲。电池输入电流不能替代转矩电流，`feedback_current` 也不能未经核对直接当作 A。输出端测得的 `k_out` 不再乘减速比。

### 没有测力计：已知重物配水平力臂

用秤称量重物，或使用质量已知的砝码；可用装水的容器，但应称量水、容器及挂件的总质量，不用瓶身标注容量代替实际质量。

1. 固定电机，输出轴接力臂，已知总质量 `m` 的重物悬挂在距轴心 `L` 处。力臂接近水平时，重力转矩约为 `m × g × L`。
2. 平衡或计算力臂自重的转矩。设置小角度行程和接重物的限位，测量时限位不能分担重物载荷。
3. 受限加载，记录接近水平时刚开始缓慢抬升、以及降低电流后刚开始缓慢下降的电流阈值。重复多次并更换几个质量，再将重物移到轴的另一侧验证相反转矩方向；保留两侧阈值反映静摩擦影响，不要把任意“恰好不动”的电流直接认作精确平衡电流。
4. 静摩擦和两方向差异较小时，可用上、下阈值的中间值估计平衡电流，按多个质量拟合，结果用于受限范围的初步标定。若阈值差很大、机构不易反拖或测量不重复，这种简化不可靠，需要改善夹具或使用测力装置。

```text
g ≈ 9.81 m/s²
tau_weight ≈ m × 9.81 × L                 # 力臂水平，已处理自重
I_eq ≈ (I_lift_threshold + I_lower_threshold) / 2  # 同一方向的一对阈值，均先换算为 A
k_out ≈ tau_weight 对 I_eq 的拟合斜率
```

例如 `m=0.5 kg`、`L=0.10 m`，外加重物转矩约 `0.4905 N·m`；这只是已知负载，不代表本车转矩常数。力臂明显倾斜时要用实际垂直力臂，不能继续直接使用杆长。

已知质量与力臂建立转矩是常用静态标定原理；家庭夹具的误差还包括长度、角度、摩擦及质量误差，不能套用专业标准机的精度。[PTB：Dynamic Torque Calibration](https://oar.ptb.de/files/download/681c516e53218de84f08e611)

也可使用已有的行李秤/弹簧秤，或让力臂压在水平放置的电子秤上测反力；先用已知重物核对量程、分辨率和重复性，并处理零点和力臂自重。显示 kgf 的力读数乘 9.80665 转为 N；电子秤以 kg 显示的等效质量读数，在正常重力称量方向下可近似乘 9.81 转为 N。

## 2. 可靠接地驱动力：`force_limit_n`

这一项随轮胎、地面、法向载荷及轮胎接触位置改变。优先用单轮加载台架，让车轮承受实际使用时该轮的载荷，沿车轮主动滚动方向测水平牵引力；全向轮滚子自由滚动的方向不能作为驱动力测量方向。

### 有测力装置时

逐步增加受限电流，记录无明显滑移时可重复传递的力。正反方向、代表性地面和接触位置都要测，考虑转弯、加速或载荷变化时轮子变轻的情况。取较差工况结果并折减，作为该轮的 `force_limit_n`。若在测试上限内一直没有打滑，只能证明已测试的力可靠，不代表找到了极限。

### 没有测力计：重物经定滑轮提供水平负载

1. 单轮测试架保持实际法向载荷，并允许沿主动驱动方向移动；用低摩擦定滑轮把水平绳索转向，下端悬挂已称量的重物。
2. 绳索在测试架处保持水平，避免提起或压紧车轮而改变法向载荷。其他约束不能提供同方向的助力，也不能靠推动装置帮助提升重物。
3. 用受限电流使轮子无明显打滑地缓慢牵引、提升重物，重复验证。重物应确实被提升，不能仅靠滑轮卡滞或静摩擦悬住。
4. 理想低摩擦、近似匀速条件下，负载约为 `F=m×9.81 N`。实际滑轮、绳索及导向阻力需要考虑，此方法更适合验证一个低的可靠驱动力下界，不能直接宣称测出了精确打滑极限。相反驱动方向也要布置同样试验，并取较差结果。
5. 对最低可重复完成的验证负载再留裕量。例如确认能可靠牵引 `1 kg`，对应重力约 `9.81 N`；若选择保留七成，则约 `6.87 N`。折减比例只是示例，应根据测量波动和使用工况决定。

使用悬挂重物建立已知力的基础是 `F=mg`，更精确的测量还需考虑当地重力等因素。[NIST：Calibration of Force Transducers](https://www.nist.gov/programs-projects/calibration-force-transducers)

整车牵引重物的结果可以验证整车工况，但不能直接除以四填成单轮值；轮向投影、各轮载荷和被动阻力均有影响。用手按住、整车爬坡或架空转轮也不能直接替代逐轮数据。

## 3. 转速增长裕量：`speed_prediction_rpm`

这一项不需要测力计，需要足够快的转速和时序记录。当前算法对所有候选电流使用同一包络：

```text
rpm_bound[w] = abs(控制器使用的转子rpm[w]) + speed_prediction_rpm
```

它不是转速目标、最高轮速，也不是每秒增加的 rpm。当前 `speed_aps` 是滤波后的转子角速度，换算 rpm 时除以 6；CAN 解码前的原始转速可以与其一起记录，用于估计滤波造成的滞后。不能只记录减速器输出轴转速。

1. 按电机反馈节奏记录原始转子 rpm、滤波后 rpm、接收时间戳、控制周期、最终电流及发送时间。使用高速缓存或合适的调试跟踪，避免在实时路径逐行打印。
2. 确认有效预测窗口 `T`：覆盖当前速度反馈已有的年龄、计算和 CAN 提交延迟、下一次有效控制更新前的时间，以及实际电调响应；结合原始值和滤波值覆盖滤波滞后。窗口应有实测时序及允许最坏延迟的依据，不能直接认定 `osDelay(2)` 就是全部窗口。
3. 在受限测试中覆盖起步、加速、反转过零、突然卸载和架空加速，包含计划使用的电流、速度、电压及温度范围。
4. 对每个控制时刻，找未来 `T` 内的最大绝对转速，减去该时刻控制器使用的绝对转速；四轮、全部工况取最大正增长，再增加测量与未覆盖波动的裕量。

```text
delta_n(w,t) = max(0, max(abs(n_raw(w,u)), u 属于 [t,t+T])
                     - abs(n_used(w,t)))
speed_prediction_rpm >= 全部记录中的最大 delta_n + 额外裕量
```

例如，已经确认窗口为 10 ms，全部记录中的最大增长为 200 rpm，另留 100 rpm，则示例结果是 300 rpm。没有确认窗口时不能直接套用这三个数字。

普通 USB `force-v1` 默认 20 ms 一行，不足以证明毫秒级增长包络。现有共用 transient 配置的 `prediction_s=0.008` 是旧路径兼容参数，不能视为本力控包络已经验证为 8 ms。小电流测试得出的结果只适用于该范围，后续放宽电流、转速、供电或改动滤波和时序时应复测。

## 回填与验收

1. 仅在 `application/board/board_chassis_force.c` 回填四轮常数、四轮力上限及共同转速裕量；保留测量范围和记录路径。未完成项继续为 0。
2. 核对轮序、单位、方向、质心及几何；保持 checksum 在全部赋值之后自动计算。
3. 按实测范围复核或收紧电流、启动、速度、温度和堵转设置。调试初值本身不是测量结果。
4. 所有必测项及保护复核完成后，才设置 `CHASSIS_FORCE_CALIBRATION_VALID=1`，按 [方案中的启用顺序](chassis-direct-force.md#后续启用顺序) 先固定转矩与滑行退出，再功率自适应，最后可选制动。
5. 补做任务最坏耗时、栈余量、失联/急停/故障恢复、功率节点与跟踪误差、实车运动及制动验证。参数校验通过不等于这些验收已通过。
